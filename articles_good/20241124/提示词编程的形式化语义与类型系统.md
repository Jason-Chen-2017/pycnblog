## 第二部分 基础理论

### 2.1 形式化语义的基本概念

形式化语义（Formal Semantics）是计算机科学中用来精确描述程序行为的一种方法。其核心目标是通过数学模型和逻辑推理，为程序提供一种明确的语义定义，从而确保程序的正确性和可理解性。形式化语义通常涉及以下几个基本概念：

**语义模型（Semantic Models）**：语义模型是形式化语义的核心组成部分。它通过抽象和数学化的方法，描述程序的行为和状态变化。常见的语义模型包括操作符语义模型、函数语义模型和状态转换模型等。例如，操作符语义模型可以定义加法操作的行为为两个操作数相加的结果。

**语义规则（Semantic Rules）**：语义规则是描述程序执行过程中状态变化的逻辑规则。它们通常用数学公式或自然语言描述，用于指导程序如何从初始状态过渡到最终状态。例如，赋值语句的语义规则可以描述为：变量A的值被设置为表达式B的值。

**状态（State）**：在形式化语义中，状态表示程序在某一时刻的内存状态。状态通常由变量值、程序计数器和其他相关数据组成。程序执行过程中的每一步都会改变状态，从而影响程序的最终结果。

**动作（Action）**：动作是程序执行过程中发生的具体操作。例如，赋值动作是将某个表达式的值赋给一个变量，跳转动作是改变程序计数器的值，从而跳到新的代码段执行。

通过这些基本概念，形式化语义能够为程序提供一种精确且明确的描述，使得程序的行为可以预测和验证。形式化语义在编程语言设计和程序分析中具有重要意义，它不仅能够帮助开发者理解和调试程序，还能够为编译器和形式验证工具提供理论基础。

### 2.2 形式化语义的组成部分

形式化语义的组成部分主要包括语义模型、语义规则和形式化语义框架。这些组成部分相互配合，共同为程序提供精确的语义描述。

**语义模型（Semantic Models）**：

语义模型是形式化语义的核心，它通过抽象和数学化的方法，描述程序的行为和状态变化。常见的语义模型包括：

1. **操作符语义模型**：描述程序中的操作符如何操作数据。例如，加法操作符的语义模型可以定义为：对于任意两个整数a和b，加法操作符的结果是a + b。

2. **函数语义模型**：描述函数如何接收输入并返回输出。例如，一个求和函数的语义模型可以定义为：对于任意两个整数a和b，求和函数f返回a + b。

3. **状态转换模型**：描述程序在执行过程中状态如何变化。例如，一个循环语句的状态转换模型可以定义为：每次循环执行后，程序的状态将根据循环条件进行更新。

**语义规则（Semantic Rules）**：

语义规则是描述程序执行过程中状态变化的逻辑规则。它们通常用数学公式或自然语言描述，用于指导程序如何从初始状态过渡到最终状态。语义规则包括：

1. **赋值规则**：定义如何将表达式的值赋给变量。例如，赋值语句“a = b”的语义规则可以定义为：将变量b的值赋给变量a。

2. **控制流规则**：定义如何处理控制流语句，如条件分支和循环。例如，if-else语句的语义规则可以定义为：根据条件表达式的结果，选择执行相应的代码块。

3. **函数调用规则**：定义如何执行函数调用并返回结果。例如，函数调用“f(a, b)”的语义规则可以定义为：执行函数f，并将参数a和b传递给函数。

**形式化语义框架（Formal Semantic Framework）**：

形式化语义框架是用于定义和实现形式化语义的工具集。它包括语义模型、语义规则和形式化语义验证工具。常见的形式化语义框架包括：

1. **Operational Semantics**：通过操作符语义和状态转换规则，描述程序执行的过程。Operational Semantics可以分为Small-Step Semantics和Big-Step Semantics。Small-Step Semantics描述程序从一步到另一步的状态变化，而Big-Step Semantics描述程序从初始状态到最终结果的状态变化。

2. **Denotational Semantics**：通过数学函数，将程序行为映射到数学概念上。Denotational Semantics通常使用函数表示程序的行为，从而提供一种直观且形式化的描述方式。

3. **Axiomatic Semantics**：通过逻辑公式和公理，定义程序行为的正确性。Axiomatic Semantics通常用于验证程序的性质，如程序的安全性、完整性和一致性。

通过这些组成部分，形式化语义能够为程序提供一种精确且形式化的描述，使得程序的行为可以预测和验证。形式化语义在编程语言设计和程序分析中具有重要意义，它不仅能够帮助开发者理解和调试程序，还能够为编译器和形式验证工具提供理论基础。

### 3.1 类型系统的基本概念

类型系统（Type System）是编程语言设计中的一个核心组成部分，它通过为程序中的变量、函数和表达式分配类型，确保程序的正确性和可维护性。类型系统的基本概念包括类型、类型检查和类型推断等。

**类型（Types）**：

类型是程序中数据的不同分类，用于描述数据的不同属性和操作。常见的类型包括整数（Int）、浮点数（Float）、布尔值（Bool）、字符串（String）等。每种类型都有其特定的操作集合和语义。

**类型检查（Type Checking）**：

类型检查是在编译时或运行时，对程序中的变量和表达式进行类型验证的过程。类型检查的主要目的是确保程序的执行不会因为类型错误而失败。类型检查分为静态类型检查和动态类型检查。

- **静态类型检查**：在编译时对程序进行类型检查，确保所有变量的类型在编译期间是已知的。静态类型语言（如C++、Java）通过静态类型检查来确保程序的正确性。
- **动态类型检查**：在运行时对程序进行类型检查，确保变量和表达式的类型在执行时匹配。动态类型语言（如Python、JavaScript）通过动态类型检查来提供更高的灵活性。

**类型推断（Type Inference）**：

类型推断是一种自动确定变量和表达式类型的方法，不需要显式声明类型。类型推断可以简化代码编写，提高程序的可读性和可维护性。常见的类型推断方法包括基于上下文的类型推断和基于规则的类型推断。

- **基于上下文的类型推断**：通过分析上下文信息来确定变量的类型。例如，如果变量在一个函数内部被赋值为一个整数，那么这个变量的类型被推断为整数。
- **基于规则的类型推断**：通过一系列的规则来确定变量的类型。例如，如果两个变量参与加法操作，并且其中一个变量的类型已知为整数，那么另一个变量的类型也被推断为整数。

```python
def convert_to_str(x):
```

```python
import spacy

nlp = spacy.load("en_core_web_sm")

def parse_prompt(prompt):
    doc = nlp(prompt)
    report_type = None
    periods = []

    for token in doc:
        if token.text.lower() in ["资产负债表", "利润表", "现金流量表"]:
            report_type = token.text.lower()
        elif token.text.lower() in ["本月", "本季度", "全年"]:
            periods.append(token.text.lower())

    return report_type, periods
```

在这个模块中，我们使用了spaCy库进行自然语言处理。`parse_prompt` 函数接收用户的自然语言提示，并提取关键信息（报表类型和报表周期）。
