**一、程序设计模式的基本概念**

程序设计模式（Design Pattern）是软件工程中的一个重要概念，它描述了在软件设计过程中常用的、可重用的解决方案。这些解决方案被广泛应用于解决特定类型的问题，从而提高代码的可读性、可维护性和复用性。

程序设计模式通常可以分为三大类：创建型、结构型和行为型模式。

**二、创建型模式**

创建型模式关注对象的创建过程，其主要目的是实现对象的创建与使用分离，从而提高系统的灵活性和扩展性。创建型模式包括以下几种：

1. **单例模式（Singleton）**：确保一个类只有一个实例，并提供一个全局访问点。单例模式在需要控制实例数量的场景中非常有用，如数据库连接池。

2. **工厂方法模式（Factory Method）**：定义一个创建对象的家庭，将具体对象的创建委托给子类。这种模式使得扩展系统时只需添加新的具体工厂类，而无需修改现有系统。

3. **抽象工厂模式（Abstract Factory）**：定义一个工厂家族，为每个产品族创建一个抽象工厂，每个抽象工厂创建具体产品族中的产品。这种模式使得系统不依赖于产品类，从而提高了系统的灵活性和可扩展性。

4. **建造者模式（Builder）**：将一个复杂对象的构建与其表示分离，使得同样的构建过程可以创建不同的表示。这种模式在构建复杂对象时非常有用，如构建大型配置文件。

5. **原型模式（Prototype）**：通过复制现有的实例来创建新的实例，从而避免直接构造复杂的对象。这种模式在需要频繁创建大量相似对象时非常有用，如对象池。

**三、结构型模式**

结构型模式关注类与类之间的关系和组合，其主要目的是通过组合接口和实现类来实现系统的解耦和灵活性。结构型模式包括以下几种：

1. **适配器模式（Adapter）**：将一个类的接口转换为另一个客户希望的接口，使得原本由于接口不兼容而无法在一起工作的类可以协同工作。这种模式在需要将现有接口与新接口集成时非常有用。

2. **桥接模式（Bridge）**：将抽象部分与实现部分分离，使它们可以独立地变化。这种模式在需要将抽象部分与实现部分分离，以实现解耦和增强系统灵活性的场景中非常有用。

3. **组合模式（Composite）**：将对象组合成树形结构以表示“部分-整体”的层次结构，使得客户可以统一使用单个对象和组合对象。这种模式在需要表示部分与整体层次结构的场景中非常有用。

4. **装饰器模式（Decorator）**：动态地给一个对象添加一些额外的职责，通过使用一种称为装饰器的类来实现。这种模式在需要给对象添加功能，同时又不想使用继承的场景中非常有用。

5. **代理模式（Proxy）**：为其他对象提供一个代理以控制对这个对象的访问。这种模式在需要控制对某个对象的访问时非常有用。

**四、行为型模式**

行为型模式关注对象之间的通信和协作，其主要目的是实现对象之间的通信和协作，从而提高系统的模块化和灵活性。行为型模式包括以下几种：

1. **职责链模式（Chain of Responsibility）**：将多个对象连成一条链，每个对象只处理它能够处理的那部分请求，从而避免请求发送者和接收者之间的耦合关系。这种模式在需要将请求传递给一系列对象中的某一个时非常有用。

2. **命令模式（Command）**：将请求封装为一个对象，从而可以使用不同的请求、队列或日志来参数化其他对象。这种模式在需要将请求记录下来、支持可撤销的操作或需要将请求发送到队列中的场景中非常有用。

3. **解释器模式（Interpreter）**：为语言创建解释器，该解释器使用模式来解释语句。这种模式在需要实现自定义语言或需要实现语法分析的场景中非常有用。

4. **中介者模式（Mediator）**：定义一个对象来封装一组对象之间的交互，从而降低它们之间的耦合关系。这种模式在需要将一组对象之间的交互解耦时非常有用。

5. **备忘录模式（Memento）**：捕获一个对象的内部状态，并在该对象之外保存这个状态，以便稍后恢复它。这种模式在需要保存和恢复对象的状态时非常有用。

6. **观察者模式（Observer）**：定义一种一对多的依赖关系，使得当一个对象的状态发生变化时，所有依赖于它的对象都会得到通知并自动更新。这种模式在需要实现事件驱动系统或需要实现广播通信的场景中非常有用。

7. **状态模式（State）**：允许一个对象在其内部状态改变时改变其行为。这种模式在需要根据对象的状态改变其行为时非常有用。

8. **策略模式（Strategy）**：定义一系列算法，将每一个算法封装起来，并使它们可以相互替换。这种模式在需要根据不同情况选择不同的算法时非常有用。

9. **模板方法模式（Template Method）**：定义一个操作中的算法的骨架，将一些步骤延迟到子类中。这种模式在需要实现一个算法，但又希望子类可以改变其中的某些步骤时非常有用。

10. **访问者模式（Visitor）**：表示一个作用于某对象结构中的各元素的操作，它可以在不改变各元素的类的前提下定义作用于这些元素的新操作。这种模式在需要实现一个作用于复杂对象结构中的各元素的新操作时非常有用。

**一、创建型模式**

创建型模式主要关注对象的创建过程，以确保对象的创建与使用分离，从而提高系统的灵活性和可扩展性。以下是创建型模式中的几种重要模式：

1. **单例模式（Singleton）**：确保一个类只有一个实例，并提供一个全局访问点。单例模式在需要控制实例数量的场景中非常有用，如数据库连接池。

```python
class Singleton:
    _instance = None

    def __new__(cls, *args, **kwargs):
        if not cls._instance:
            cls._instance = super().__new__(cls, *args, **kwargs)
        return cls._instance

def main():
    s1 = Singleton()
    s2 = Singleton()
    print(s1 is s2)  # 输出：True

    main()
```

行为型模式主要关注对象之间的通信和协作，以实现系统的模块化和灵活性。以下是几种重要的行为型模式：

1. **职责链模式（Chain of Responsibility）**：将多个对象连成一条链，每个对象只处理它能够处理的那部分请求，从而避免请求发送者和接收者之间的耦合关系。

```python
class Handler(ABC):
    def __init__(self, successor=None):
        self._successor = successor

    @abstractmethod
    def handle(self, request):
        pass

    def successor(self):
        return self._successor

class ConcreteHandlerA(Handler):
    def handle(self, request):
        if 0 <= request <= 10:
            print(f"ConcreteHandlerA: Handling request {request}.")
        elif self._successor:
            self._successor.handle(request)

class ConcreteHandlerB(Handler):
    def handle(self, request):
        if 10 < request <= 20:
            print(f"ConcreteHandlerB: Handling request {request}.")
        elif self._successor:
            self._successor.handle(request)

class DefaultHandler(Handler):
    def handle(self, request):
        print(f"DefaultHandler: Handling request {request}.")

def main():
    h1 = ConcreteHandlerA()
    h2 = ConcreteHandlerB()
    h3 = DefaultHandler()

    h1.set_successor(h2)
    h2.set_successor(h3)

    h1.handle(15) # 输出：ConcreteHandlerB: Handling request 15.

    main()
```

```python

    @abstractmethod
    def interpret(self, context):
        pass

class TerminalExpression(AbstractExpression):
    def interpret(self, context):
        if context in self._keywords:
            return self._action

class NonTerminalExpression(AbstractExpression):
    def __init__(self, *sub_expressions):
        self._sub_expressions = sub_expressions

    def interpret(self, context):
        result = ""
        for sub_expression in self._sub_expressions:
            result += sub_expression.interpret(context)
        return result

class Context:
    def __init__(self, text):
        self._text = text

    def remaining_text(self):
        return self._text

class Interpreter:
    def __init__(self, text):
        self._context = Context(text)

    def interpret(self):
        return self._interpret(self._context.remaining_text())

    def _interpret(self, text):
        if not text:
            return ""
        first_word = text.split()[0]
        if first_word in self._keywords:
            return self._action_map[first_word]
        else:
            return NonTerminalExpression(*[TerminalExpression(first_word) for first_word in text.split()]).interpret(self._context)

_action_map = {
    "Hello": "Saying hello.",
    "World": "World",
}

keywords = ["Hello", "World"]

    print(result)  # 输出：Saying hello. World
```
