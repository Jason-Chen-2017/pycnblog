#### 2.1.1 设计模式的基本概念

**设计模式**（Design Pattern）是一套被反复使用、经过时间考验的最佳实践。它是一种针对特定问题的通用解决方案，通常由三个部分组成：模式名称、主要目的和具体实现方式。

- **模式名称**：简洁、具有描述性的名称，用于标识设计模式。
- **主要目的**：设计模式解决的问题或满足的需求。
- **具体实现方式**：设计模式的具体实现细节，包括类和对象的组织和交互。

设计模式通常分为三类：创建型模式、结构型模式和和行为型模式。

1. **创建型模式**：主要关注对象的创建过程，提供创建对象的最佳方式。例如，单例模式确保一个类仅有一个实例，工厂模式提供创建对象的全局接口。
   
2. **结构型模式**：主要关注类和对象的组合，提供类和对象之间的最佳组合方式。例如，适配器模式将一个类的接口转换成客户期望的另一个接口，装饰器模式动态地添加对象的功能。
   
3. **行为型模式**：主要关注对象之间的通信，提供对象之间交互的最佳方式。例如，责任链模式允许对象按顺序处理请求，策略模式定义了算法家族，使得算法的变化不会影响到使用算法的客户对象。

### 2.2 创建型模式

#### 2.2.1 单例模式

**单例模式**确保一个类仅有一个实例，并提供一个全局访问点。该模式在需要确保一个类只有一个实例的场合非常有用，例如数据库连接、文件系统管理等。

**伪代码实现**：

```python
class Singleton:
    instance = None

    def __init__(self):
        if not Singleton.instance:
            Singleton.instance = self
        else:
            return Singleton.instance

    @staticmethod
    def getInstance():
        if not Singleton.instance:
            Singleton.instance = Singleton()
        return Singleton.instance
```

**应用实例**：

假设我们要实现一个数据库连接管理类，确保系统中只有一个数据库连接实例，以避免资源浪费和冲突。我们可以使用单例模式来实现：

```python
class DatabaseConnection:
    instance = None

    def connect(self):
```

在这个例子中，通过`getInstance`方法，我们可以确保系统中的`DatabaseConnection`实例始终只有一个。这有助于确保数据库连接的可靠性和资源管理。

#### 2.2.3 抽象工厂模式

### 2.3 结构型模式

结构型模式主要关注类和对象的组合，提供类和对象之间的最佳组合方式，从而提高代码的可维护性和扩展性。以下是几种常见的结构型模式及其伪代码实现和应用实例：

#### 2.3.1 适配器模式

**适配器模式**将一个类的接口转换成客户希望的另一个接口，使得原本接口不兼容的类可以一起工作。这种模式在需要使用现有类，但接口不匹配的场合非常有用。

**伪代码实现**：

```python
class Adaptee:

class Adapter(Adaptee):
    def adapted_method(self):
        self.specific_method()
```

**应用实例**：

假设我们有一个`Adaptee`类，它有一个`specific_method`方法。现在，我们需要将其转换为`Adapter`类中的`adapted_method`方法，以便与客户端代码无缝对接。

```python
class Adaptee:
    def specific_method(self):
        print("特定的方法")

class Adapter:
    def __init__(self, adaptee):
        self.adaptee = adaptee

    def adapted_method(self):
        self.adaptee.specific_method()

# 客户端代码
adaptee = Adaptee()
adapter = Adapter(adaptee)
adapter.adapted_method()  # 输出：特定的方法
```

在这个例子中，`Adapter`类通过持有`Adaptee`类的实例，实现了接口的适配。这样，客户端代码只需要与`Adapter`类交互，而无需了解`Adaptee`类的具体实现。

#### 2.3.3 代理模式

**代理模式**为其他对象提供一个代理以控制对这个对象的访问。这种模式在需要限制对象访问，或者需要为对象添加额外功能的场合非常有用。

### 2.4 行为型模式

行为型模式主要关注对象之间的交互和通信，提供了解决复杂通信问题的最佳方式。以下是几种常见的行为型模式及其伪代码实现和应用实例：

#### 2.4.1 责任链模式

**责任链模式**使多个对象都有机会处理请求，从而避免请求发送者和接收者之间的耦合关系，将这些对象连成一条链，并沿着这条链传递请求。这种模式在需要多个对象按顺序处理请求的场合非常有用。

**伪代码实现**：

```python
class Handler:
    def __init__(self, successor=None):
        self._successor = successor

    def handle(self, request):
        if self._successor:
            self._successor.handle(request)
        else:
            print("无处理者")

class ConcreteHandlerA(Handler):
    def handle(self, request):
        if 0 <= request <= 10:
            print("处理请求:", request)
        else:
            self._successor.handle(request)

class ConcreteHandlerB(Handler):
    def handle(self, request):
        if 10 < request <= 20:
            print("处理请求:", request)
        else:
            self._successor.handle(request)

class DefaultHandler(Handler):
    def handle(self, request):
        if request > 20:
            print("处理请求:", request)
```

**应用实例**：

假设我们要实现一个请求处理系统，不同类型的请求需要不同的处理。我们可以使用责任链模式来实现：

```python
handler_a = ConcreteHandlerA()
handler_b = ConcreteHandlerB()
handler_c = DefaultHandler()

handler_a.handle(5)  # 输出：处理请求：5
handler_b.handle(15)  # 输出：处理请求：15
handler_c.handle(25)  # 输出：处理请求：25
```

在这个例子中，`Handler`类定义了一个`handle`方法，用于处理请求。通过设置不同的`successor`，我们可以创建一个责任链。每个处理者都可以决定是否处理请求，或者将请求传递给链中的下一个处理者。

#### 2.4.2 策略模式

**策略模式**定义了一系列算法，将每一个算法封装起来，并使它们可以相互替换，使算法的变化不会影响到使用算法的客户对象。这种模式在需要使用不同算法或策略的场合非常有用。

**伪代码实现**：

```python
class Strategy:

class ConcreteStrategyA(Strategy):

class ConcreteStrategyB(Strategy):

        print("执行策略B")

class Context:
    def __init__(self, strategy: Strategy):
        self._strategy = strategy

    def set_strategy(self, strategy: Strategy):
        self._strategy = strategy

    def execute_algorithm(self):

```

**应用实例**：


在这个例子中，`Strategy`类定义了一个`algorithm`方法，用于执行算法。通过创建不同的`ConcreteStrategy`类，我们可以实现不同的策略。`Context`类负责管理策略，并通过`set_strategy`方法切换策略。

#### 2.4.3 模板方法模式

**模板方法模式**定义一个操作中的算法的骨架，而将一些步骤延迟到子类中，使得子类可以不改变一个算法的结构，即可重定义该算法的某些步骤。这种模式在需要定义一个操作中的算法骨架，并允许子类对某些步骤进行修改的场合非常有用。

**伪代码实现**：

```python
class TemplateMethod:

        self.step_b()
        self.step_c()

    def step_a(self):

    def step_b(self):
        print("步骤B")

    def step_c(self):
        print("步骤C")

        super().step_c()
        print("自定义步骤C")

class ConcreteClassB(TemplateMethod):
    def step_b(self):

        print("自定义步骤B")
```

**应用实例**：

假设我们要实现一个通用流程，并允许子类自定义某些步骤。我们可以使用模板方法模式来实现：


在这个例子中，`TemplateMethod`类定义了一个模板方法`template_method`，它包含了算法的骨架。通过在子类中重定义某些步骤，我们可以实现自定义的流程。
