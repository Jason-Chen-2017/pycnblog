## 第1章：故障注入测试背景介绍

### 1.1 问题背景

#### 1.1.1 人工智能与机器学习的发展

人工智能（AI）和机器学习（ML）作为当代科技发展的两个重要领域，已经深刻改变了我们的生活方式和工作方式。AI通过模拟人类智能行为，实现了自动化决策、自动化操作等功能，而ML则是AI的核心技术之一，通过数据驱动的方式，让计算机系统具备学习和适应能力。

近年来，随着计算能力的提升、大数据技术的发展以及算法的优化，ML模型，特别是深度学习模型，在图像识别、语音识别、自然语言处理等领域取得了显著的进展。这些模型通过在大量数据上进行训练，可以学会识别复杂模式、做出预测和决策。

#### 1.1.2 机器学习模型的可靠性问题

尽管ML模型在许多应用场景中表现出色，但它们的可靠性问题仍然是一个亟待解决的难题。可靠性问题主要体现在以下几个方面：

1. **过拟合与欠拟合**：过拟合是指模型在训练数据上表现良好，但在新数据上表现较差；欠拟合则是指模型无法捕捉数据中的关键信息，导致整体性能下降。

2. **数据偏见**：ML模型性能的依赖性使其容易受到数据偏见的影响。如果训练数据存在偏见，那么模型也会继承这种偏见，导致其在真实世界中的表现不公平或不准确。

3. **异常值与噪声**：异常值和噪声数据可能会对模型的学习过程产生不利影响，导致模型无法准确预测或做出错误决策。

4. **模型崩溃**：在某些极端情况下，ML模型可能会出现崩溃，即无法正常工作，这可能是由于输入数据的不当处理、算法的缺陷或计算资源的不足等原因造成的。

#### 1.1.3 故障注入测试的基本概念

故障注入测试（Fault Injection Testing）是一种主动测试方法，通过在系统中引入特定的故障，以评估系统在异常情况下的行为和稳定性。该方法的核心思想是模拟系统可能遇到的故障情况，以测试系统的容错能力、故障恢复能力和系统稳定性。

故障注入测试通常包括以下几个步骤：

1. **故障设计**：根据系统需求和预期故障类型，设计具体的故障场景。

2. **故障注入**：在系统运行过程中，主动引入设计好的故障。

3. **故障观察**：观察系统在故障注入后的行为，记录故障对系统的影响。

4. **故障恢复**：根据故障观察结果，评估系统是否能够自动恢复或需要人工干预。

5. **故障报告**：总结故障注入测试的结果，生成测试报告，为系统优化提供依据。

#### 1.1.4 故障注入测试的类型

故障注入测试可以分为多种类型，根据故障注入的方式和目的，可以将其分为以下几类：

1. **随机故障注入**：通过随机方式引入故障，以模拟系统在实际运行中可能遇到的各种异常情况。

2. **指定故障注入**：根据特定的故障模式或场景，有目的地引入故障，以评估系统对特定故障的响应能力。

3. **演化故障注入**：通过逐步增加故障的复杂度或严重性，观察系统在不同故障级别下的行为和性能变化。

4. **组合故障注入**：同时引入多种类型的故障，以评估系统在多故障情况下的综合表现。

#### 1.1.5 故障注入测试与模型可靠性的联系

故障注入测试与模型可靠性之间存在紧密的联系。通过故障注入测试，可以识别和解决ML模型在运行过程中可能遇到的问题，从而提高模型的可靠性。

1. **提高模型稳定性**：通过故障注入测试，可以验证模型在不同故障情况下的稳定性，确保模型在各种环境下都能正常运行。

2. **优化模型性能**：故障注入测试可以帮助开发者发现模型在处理异常数据时的性能瓶颈，从而进行优化，提高模型的泛化能力。

3. **降低模型风险**：通过故障注入测试，可以提前发现和解决潜在的故障风险，降低模型在实际应用中的失效风险。

4. **提高用户信任度**：可靠性的提高可以增强用户对模型和应用的信任度，从而促进更广泛的应用。

### 1.2 故障注入测试的优势与挑战

#### 1.2.1 故障注入测试的优势

故障注入测试具有以下几个显著优势：

1. **主动识别问题**：通过主动引入故障，可以主动识别系统中潜在的故障和问题，而不仅仅是在问题发生时被动反应。

2. **模拟真实场景**：故障注入测试能够模拟系统在实际运行中可能遇到的各类故障情况，从而更全面地评估系统的可靠性。

3. **提高测试覆盖率**：通过设计各种故障场景，可以覆盖到系统中的更多部分，提高测试的全面性和有效性。

4. **支持迭代优化**：故障注入测试的结果可以用于指导系统优化，从而实现持续改进。

#### 1.2.2 故障注入测试的挑战

尽管故障注入测试具有显著的优势，但其在实际应用中也面临一些挑战：

1. **故障设计难度**：设计符合实际应用场景的故障场景需要深入理解系统的工作原理和可能的故障模式，这对开发者的经验和技术水平有较高要求。

2. **测试资源消耗**：故障注入测试通常需要较多的计算资源和时间，特别是在处理复杂系统和大规模数据时，测试成本可能较高。

3. **故障影响评估**：评估故障对系统的影响可能比较困难，需要综合考虑多种因素，如故障的严重程度、系统的应对策略等。

4. **自动化水平**：虽然故障注入测试可以部分自动化，但完全自动化仍面临一些挑战，如故障场景的设计和故障注入的准确性。

#### 1.2.3 解决方案与未来展望

为了应对故障注入测试的挑战，可以采取以下解决方案和未来研究方向：

1. **自动化工具开发**：开发更先进的自动化工具，以减少人工参与，提高故障注入测试的效率和准确性。

2. **故障模式库建设**：建立丰富的故障模式库，提供多种故障场景的设计和实现方案，以支持更全面的测试覆盖。

3. **智能故障注入**：利用机器学习和人工智能技术，实现更智能的故障注入，提高故障注入的针对性和测试效果。

4. **集成到开发流程**：将故障注入测试集成到开发流程中，实现持续集成和持续测试，以持续提高系统的可靠性。

5. **跨领域合作**：促进不同领域之间的合作，如软件开发、硬件设计、系统架构等，以共同应对故障注入测试的挑战。

通过上述解决方案和未来研究方向，我们可以更好地利用故障注入测试技术，提高ML模型及其应用的可靠性，为人工智能技术的广泛应用奠定坚实基础。

### 1.3 机器学习模型中的可靠性问题

#### 1.3.1 机器学习模型的工作原理

机器学习模型的工作原理主要基于数据驱动和模型训练。ML模型通过从大量数据中学习，识别数据中的模式和关系，然后利用这些模式和关系来对新数据进行预测和分类。ML模型通常分为监督学习、无监督学习和强化学习三种类型。

- **监督学习**：监督学习模型通过已有的标记数据来训练模型，然后利用训练好的模型对未标记的数据进行预测。常见的监督学习算法包括线性回归、决策树、支持向量机等。

- **无监督学习**：无监督学习模型不依赖标记数据，而是通过分析数据中的内在结构来发现数据中的模式和关联。常见的无监督学习算法包括聚类、降维、关联规则等。

- **强化学习**：强化学习模型通过与环境的交互来学习最优策略，即通过不断尝试和反馈来优化决策过程。常见的强化学习算法包括Q-learning、SARSA、深度强化学习等。

#### 1.3.2 可靠性问题的种类

在机器学习模型中，可靠性问题主要包括以下几个方面：

1. **过拟合与欠拟合**：
   - **过拟合**：过拟合是指模型在训练数据上表现良好，但在新的、未见过数据上表现较差。这通常发生在模型过于复杂，对训练数据中的噪声和细节过度学习时。
   - **欠拟合**：欠拟合是指模型无法捕捉到数据中的关键信息，导致在训练数据和测试数据上的表现都较差。这通常发生在模型过于简单，无法捕捉数据中的复杂关系时。

2. **数据偏见**：数据偏见是指训练数据中存在的不合理或不公平的偏见，这些偏见可能会被模型继承并在预测结果中表现出来。例如，如果训练数据中存在性别偏见，那么模型可能会在性别相关的任务中表现出性别偏见。

3. **异常值与噪声处理**：异常值和噪声数据可能会对模型的学习过程产生不利影响。异常值可能是数据中的错误或异常点，而噪声数据则是数据中的随机波动。如果模型无法有效地处理异常值和噪声数据，可能会影响模型的泛化能力。

4. **模型崩溃**：模型崩溃是指模型在某些特定条件下无法正常工作，导致预测失败或系统崩溃。模型崩溃可能是由于算法缺陷、计算资源不足、输入数据不合法等原因引起的。

#### 1.3.3 解决方法

针对机器学习模型中的可靠性问题，可以采取以下解决方法：

1. **模型选择与调优**：
   - 选择适合数据集的模型类型，避免过拟合和欠拟合。
   - 通过调整模型参数（如正则化参数、学习率等）来优化模型性能。

2. **数据预处理**：
   - 清洗数据，去除异常值和噪声数据。
   - 进行特征工程，提取对模型预测有帮助的特征，并减少冗余特征。

3. **交叉验证**：
   - 使用交叉验证来评估模型的泛化能力，避免过拟合。
   - 通过多次训练和测试，提高模型的稳定性和可靠性。

4. **数据增强**：
   - 通过数据增强技术，增加训练数据的多样性，提高模型的泛化能力。
   - 例如，使用数据增强方法（如旋转、缩放、裁剪等）来生成更多的训练样本。

5. **集成学习**：
   - 通过集成多个模型来提高预测的稳定性和可靠性。
   - 例如，使用Bagging、Boosting等方法来构建集成模型。

6. **异常值检测**：
   - 使用异常值检测算法，识别和标记数据中的异常值。
   - 对异常值进行特殊处理，如剔除或进行再训练。

7. **实时监控与反馈**：
   - 在模型部署后，对模型进行实时监控，及时发现和解决模型问题。
   - 通过用户反馈来不断优化模型，提高其性能和可靠性。

通过上述方法，可以有效提高机器学习模型的可靠性，确保其在实际应用中的稳定性和准确性。

### 1.4 故障注入测试的基本流程

故障注入测试是一种主动测试方法，其核心思想是通过在系统中引入故障，评估系统在各种异常情况下的行为和稳定性。故障注入测试的基本流程包括以下几个关键步骤：

#### 1.4.1 故障设计

故障设计是故障注入测试的首要步骤，其主要任务是识别系统可能遇到的各种故障模式，并设计相应的故障场景。故障设计需要深入理解系统的功能、架构和运行机制，以便模拟出真实场景中的故障。

1. **故障识别**：通过对系统进行全面的分析，识别可能出现的故障类型。常见的故障类型包括硬件故障、软件故障、数据故障和网络故障等。
2. **故障场景设计**：根据识别出的故障类型，设计具体的故障场景。故障场景应该能够覆盖系统的关键功能点，并尽可能模拟系统在实际运行中可能遇到的故障情况。
3. **故障参数设置**：为故障场景设置具体的参数，如故障发生的时间、频率、严重程度等。这些参数将直接影响故障注入测试的效果。

#### 1.4.2 故障注入

故障注入是将设计好的故障引入系统的过程。故障注入可以通过不同的方式实现，包括手动注入和自动化注入。

1. **手动注入**：手动注入故障通常由测试人员通过操作界面或控制台手动触发。这种方式适用于对故障场景和系统状态有明确要求的测试场景。
2. **自动化注入**：自动化注入故障通过编写脚本或使用自动化测试工具实现。这种方式可以提高测试的效率和覆盖率，特别适用于大规模系统的测试。

#### 1.4.3 故障观察

故障注入后，需要对系统行为进行仔细观察和记录，以评估故障对系统的影响。故障观察包括以下几个方面：

1. **系统状态监控**：通过监控系统日志、性能指标和状态变化，实时记录系统在故障注入后的状态和行为。
2. **故障影响评估**：分析故障对系统关键功能的影响，如是否导致系统崩溃、性能下降、数据丢失等。
3. **故障记录**：详细记录故障发生的时间、位置、类型、影响范围等信息，以便后续分析和处理。

#### 1.4.4 故障恢复

故障注入测试的最终目标是验证系统在故障情况下的恢复能力。故障恢复包括以下几个方面：

1. **自动恢复**：如果系统具备自动恢复功能，如自动重启、故障转移等，需要验证这些功能是否能够正常执行，并确保系统在故障恢复后能够恢复正常运行。
2. **人工干预**：对于需要人工干预的故障，需要评估系统在人工干预下的恢复能力和效率。
3. **故障恢复测试**：在故障恢复后，进行一系列测试，确保系统恢复正常运行，并验证故障恢复的有效性。

#### 1.4.5 故障报告

故障注入测试的最后一步是生成故障报告，总结测试过程和结果，为系统的优化和改进提供依据。故障报告通常包括以下内容：

1. **故障记录**：详细记录故障的类型、发生时间、影响范围、恢复情况等信息。
2. **测试结果**：分析故障注入测试的结果，包括故障对系统的影响、故障恢复情况等。
3. **优化建议**：根据测试结果，提出系统优化的建议，包括故障预防、故障检测、故障恢复等方面的改进措施。
4. **总结与反思**：总结故障注入测试的经验教训，为未来的测试工作提供参考。

通过故障注入测试的基本流程，可以系统地评估系统的可靠性和稳定性，及时发现和解决潜在故障，从而提高系统的整体质量。

### 1.5 故障注入测试的策略

故障注入测试的策略是指在故障注入过程中，如何选择和实施故障注入，以最大化测试效果和覆盖范围。合理的故障注入策略可以显著提高测试的效率和准确性。以下是一些常见的故障注入策略：

#### 1.5.1 随机故障注入

随机故障注入是一种基于概率的故障注入方法，通过随机生成故障参数，模拟系统在实际运行中可能遇到的各种异常情况。随机故障注入的主要优点是覆盖面广，能够检测到系统中的多种潜在故障。

1. **优点**：
   - 覆盖面广：随机故障注入可以覆盖系统中的大部分功能和模块，提高测试的全面性。
   - 易于实现：随机故障注入不需要复杂的故障设计，可以通过简单的随机数生成器实现。

2. **缺点**：
   - 测试结果不确定性：由于故障是随机生成的，测试结果的可靠性可能较低，难以评估故障对系统的影响。
   - 测试资源消耗：随机故障注入需要大量的测试资源和时间，特别是在大规模系统中，测试成本较高。

3. **应用场景**：
   - 初步测试：在系统开发初期，可以通过随机故障注入快速评估系统的稳定性和可靠性。
   - 功能测试：用于测试系统的各个功能模块，确保在不同故障情况下系统能够正常运行。

#### 1.5.2 指定故障注入

指定故障注入是一种基于预定义故障模式的故障注入方法，通过有目的地引入特定的故障，评估系统对特定故障的响应能力。指定故障注入通常需要详细的故障设计，以确保故障注入的针对性和有效性。

1. **优点**：
   - 针对性强：指定故障注入可以根据系统需求和预期故障模式，有针对性地引入故障，提高测试的针对性。
   - 测试结果可控：由于故障是预先设计的，测试结果的可靠性较高，可以更好地评估故障对系统的影响。

2. **缺点**：
   - 故障设计复杂：指定故障注入需要详细的故障设计，故障设计复杂度较高，对测试人员的经验和技术要求较高。
   - 测试范围受限：指定故障注入可能无法覆盖系统中的所有故障情况，测试范围相对有限。

3. **应用场景**：
   - 安全测试：用于评估系统在面临安全威胁时的响应能力，如SQL注入、XSS攻击等。
   - 性能测试：用于评估系统在不同负载和故障情况下的性能表现。

#### 1.5.3 演化故障注入

演化故障注入是一种通过逐步增加故障的复杂度和严重性，观察系统行为和性能变化的故障注入方法。演化故障注入通常用于评估系统在复杂故障情况下的应对能力和恢复能力。

1. **优点**：
   - 故障发现能力：演化故障注入可以逐步引入不同严重程度的故障，帮助发现系统中的潜在问题。
   - 故障恢复评估：通过逐步增加故障的复杂度，可以评估系统在故障恢复方面的能力。

2. **缺点**：
   - 测试时间较长：演化故障注入需要逐步引入故障，测试时间较长，对测试资源的消耗较大。
   - 故障设计复杂：演化故障注入的故障设计相对复杂，需要详细的故障演变策略。

3. **应用场景**：
   - 长期稳定性测试：用于评估系统在长时间运行下的稳定性和可靠性。
   - 故障恢复测试：用于评估系统在面临复杂故障情况下的恢复能力和应对策略。

通过合理选择和组合不同故障注入策略，可以最大化故障注入测试的效果，提高系统的可靠性和稳定性。

故障注入测试的效果评估是确保测试有效性和系统可靠性的关键步骤。通过科学的评估方法，可以准确判断故障注入测试的成效，并根据评估结果对系统进行优化。以下是一些常见的故障注入测试效果评估方法：

#### 1.6.1 故障注入测试覆盖率

故障注入测试覆盖率是评估测试效果的重要指标，它反映了测试中覆盖到的故障场景和系统功能的全面性。覆盖率可以通过以下方式计算：

2. **功能覆盖率**：评估测试用例覆盖到的系统功能点和业务流程，确保关键功能得到充分测试。

#### 1.6.2 故障检测率

故障检测率是指测试过程中成功检测出的故障数量与总故障数量的比值。高故障检测率表明测试能够有效地发现系统中的问题。

1. **故障识别率**：通过比较测试结果和预期结果，识别出实际存在的故障，评估测试对故障的识别能力。
2. **故障定位率**：对于检测出的故障，评估测试能否准确定位故障发生的位置和原因。

#### 1.6.3 故障恢复率

故障恢复率是评估系统在故障注入后，是否能够自动恢复或通过人工干预恢复正常运行的指标。高故障恢复率表明系统具有较好的容错能力和故障恢复机制。

1. **自动恢复率**：评估系统在故障注入后，是否能够通过预定的自动恢复机制（如自动重启、故障转移等）恢复正常运行。
2. **人工干预恢复率**：评估系统在故障注入后，需要人工干预恢复的时间和技术复杂度。

#### 1.6.4 故障影响评估

故障影响评估是分析故障对系统正常运行的影响程度，包括故障的影响范围、影响时间、修复成本等。通过故障影响评估，可以更全面地了解故障注入测试的实际效果。

1. **故障影响范围**：评估故障对系统不同模块、功能的影响范围，确定故障影响的广度。
2. **故障影响时间**：评估故障对系统正常运行的影响时间，包括故障发生的时间长度和修复所需的时间。
3. **修复成本**：评估故障修复所需的资源（如人力、时间、资金等），以及故障对业务运营的影响。

#### 1.6.5 测试报告

测试报告是对故障注入测试全过程和结果的总结，包括故障注入策略、测试用例、测试结果、故障影响评估等内容。一份详尽的测试报告可以帮助团队理解测试效果，并指导系统优化。

1. **故障记录**：详细记录所有检测出的故障，包括故障类型、发生时间、影响范围、修复措施等。
2. **测试总结**：总结测试过程中发现的问题、测试效果和改进建议。
3. **测试报告**：整理测试结果和评估数据，生成测试报告，为系统优化提供依据。

通过科学的评估方法和详尽的测试报告，可以全面评估故障注入测试的效果，确保系统在故障注入测试中达到预期的可靠性目标。

### 1.7 故障注入测试在机器学习模型中的应用

#### 1.7.1 故障注入测试对模型性能的影响

故障注入测试在机器学习模型中的应用，主要目的是评估模型在不同故障情况下的性能表现，从而提高模型的可靠性和稳定性。具体来说，故障注入测试对模型性能的影响可以从以下几个方面进行分析：

1. **过拟合与欠拟合**：
   - **过拟合**：在过拟合情况下，模型对训练数据的拟合过于紧密，导致在新数据上的表现较差。故障注入测试可以帮助发现模型是否过度依赖特定数据，从而采取适当的正则化措施来防止过拟合。
   - **欠拟合**：在欠拟合情况下，模型无法捕捉到数据中的关键信息，导致整体性能下降。通过故障注入测试，可以评估模型在处理复杂数据时的能力，帮助调整模型复杂度，避免欠拟合。

2. **数据偏见**：
   - 数据偏见是模型性能下降的一个常见原因。故障注入测试可以模拟不同类型的偏见，如性别偏见、种族偏见等，通过评估模型在这些情况下的表现，可以帮助发现和纠正数据偏见，提高模型的公平性和准确性。

3. **异常值与噪声**：
   - 异常值和噪声数据可能会对模型的学习过程产生不利影响，导致模型无法准确预测或做出错误决策。故障注入测试可以引入异常值和噪声数据，评估模型对这些数据的处理能力，从而优化数据预处理和异常值检测策略。

4. **模型崩溃**：
   - 模型崩溃是指模型在特定情况下无法正常工作。故障注入测试可以模拟可能导致模型崩溃的极端情况，如计算资源不足、输入数据异常等，从而评估模型的鲁棒性和容错能力。

#### 1.7.2 故障注入测试的数据预处理

在故障注入测试中，数据预处理是一个重要环节，它直接影响测试的有效性和准确性。以下是一些常见的数据预处理方法：

1. **数据清洗**：
   - 数据清洗是去除数据中的错误、缺失值和重复值的过程。通过数据清洗，可以减少噪声和异常值对模型的影响，提高模型的训练效果。
   - 例如，可以使用Python中的`pandas`库来清洗数据，删除缺失值或使用插值方法填充缺失值，剔除重复记录等。

2. **特征工程**：
   - 特征工程是提取数据中具有代表性的特征，并构造新的特征的过程。合理的特征工程可以增强模型的学习能力和泛化能力。
   - 例如，可以使用`scikit-learn`库进行特征提取和特征选择，如使用主成分分析（PCA）来降维，使用特征选择算法（如递归特征消除RFE）来选择关键特征。

3. **数据增强**：
   - 数据增强是通过生成新的数据样本来扩展训练集，提高模型的泛化能力。数据增强方法包括随机旋转、缩放、裁剪等。
   - 例如，可以使用`Keras`库中的`ImageDataGenerator`类来实现数据增强，增加训练数据的多样性。

4. **异常值检测**：
   - 异常值检测是识别和标记数据中的异常值的过程。通过异常值检测，可以减少异常值对模型学习过程的影响。
   - 例如，可以使用`isolation forest`、`local outlier factor`（LOF）等方法进行异常值检测，并将检测出的异常值进行特殊处理或剔除。

通过这些数据预处理方法，可以确保故障注入测试中使用的训练数据质量，从而提高故障注入测试的准确性和可靠性。

### 1.9 基于故障注入测试的可靠性增强方法

#### 1.9.1 故障注入测试与模型优化

故障注入测试不仅可以发现系统中的潜在问题，还可以为模型的优化提供宝贵的数据和洞察。以下是故障注入测试在模型优化中的应用：

1. **识别过拟合与欠拟合**：通过故障注入测试，可以识别模型是否过拟合或欠拟合。在过拟合的情况下，模型可能对训练数据拟合过度，导致在新数据上的表现较差；在欠拟合的情况下，模型可能无法捕捉数据中的关键信息，导致整体性能下降。识别出这些问题后，可以采取相应的优化措施，如调整模型参数、增加训练数据等。

2. **数据重采样与增强**：故障注入测试可以发现数据中的异常值和噪声，这些问题可能影响模型的性能。通过数据重采样和数据增强技术，如随机重采样、SMOTE（合成少数类过采样技术）等，可以减少异常值和噪声的影响，提高模型的泛化能力。

3. **模型调参与正则化**：通过故障注入测试，可以评估不同模型参数设置对系统性能的影响。在模型调参过程中，可以结合测试结果，选择最优的参数设置，以减少过拟合和欠拟合的风险。同时，引入正则化技术，如L1、L2正则化，可以防止模型过拟合，提高模型的稳定性和泛化能力。

4. **集成学习方法**：故障注入测试可以帮助评估单个模型的性能，同时也可以用于集成学习方法的优化。通过比较不同集成学习方法（如Bagging、Boosting等）在故障注入测试中的表现，可以选择最适合实际应用场景的集成学习方法，提高模型的稳定性和性能。

#### 1.9.2 故障注入测试与数据增强

1. **计算资源故障**：模拟计算资源不足的情况，如CPU利用率过高、内存不足等。
2. **网络故障**：模拟网络中断、延迟等情况，评估LLM应用在网络不稳定条件下的响应能力。
3. **数据故障**：模拟数据丢失、数据损坏等情况，评估LLM应用对数据完整性的保护能力。

#### 1.10.3 故障注入测试的实施

故障注入测试的实施过程分为以下几个步骤：

2. **故障观察**：在故障注入后，监控系统状态和行为，记录故障对系统的影响。通过监控系统日志、性能指标、状态变化等信息，分析故障的影响范围和严重程度。例如，在计算资源故障情况下，我们记录CPU和内存利用率的变化，分析系统响应时间的变化；在网络故障情况下，我们记录网络延迟和数据传输速度的变化，分析系统的响应速度和稳定性。

3. **故障恢复**：评估系统在故障注入后的恢复能力，包括自动恢复和人工干预恢复。在计算资源故障和网络故障情况下，我们观察系统是否能够自动恢复或需要人工干预。例如，在计算资源故障情况下，我们观察系统是否能够通过自动重启恢复；在网络故障情况下，我们观察系统是否能够通过重连网络恢复。
