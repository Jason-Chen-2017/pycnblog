#### 3.2 示例2：复杂查询

```sql
SELECT u.name, u.age, AVG(r.rating) FROM users u JOIN reviews r ON u.id = r.user_id GROUP BY u.name, u.age;
```

**分析**：
- 该查询通过连接`users`和`reviews`表，计算每个用户的平均评分，并按用户名和年龄分组。
- 类型系统需要确保连接条件`JOIN`操作中`u.id`和`r.user_id`的类型一致，`AVG`函数操作的数据类型也需正确。

**伪代码**：
```plaintext
Function CalculateAverageRating():
    result = []
    for each user in users:
        rating_sum = 0
        for each review in reviews:
            if review.user_id == user.id:
                rating_sum += review.rating
        if rating_sum > 0:
            average_rating = rating_sum / count(reviews with user_id == user.id)
            result.append((user.name, user.age, average_rating))
    return result
```

#### 3.3 示例3：错误类型查询

```sql
SELECT u.name, u.age, r.rating FROM users u LEFT JOIN reviews r ON u.id = r.user_id;
```

**分析**：
- 该查询试图从`users`表左连接`reviews`表，但未对结果进行任何聚合操作。
- 类型系统在此场景下无法保证查询结果中缺失的`rating`字段类型正确。

**伪代码**：
```plaintext
Function SelectUserReviewsWithoutRating():
    result = []
    for each user in users:
        reviews = []
        for each review in reviews:
            if review.user_id == user.id:
                reviews.append(review.rating)
        if reviews is not empty:
            result.append((user.name, user.age, reviews))
    return result
```

**错误分析**：
- 若用户`u`没有对应的`r`记录，则`result`中会出现`NULL`值，导致类型不安全。
- 修正方法：使用`COALESCE`函数或聚合函数处理缺失的值，确保类型一致。

```sql
SELECT u.name, u.age, COALESCE(AVG(r.rating), 0) AS average_rating FROM users u LEFT JOIN reviews r ON u.id = r.user_id GROUP BY u.name, u.age;
```

通过上述代码示例和分析，我们可以看到类型系统在确保SQL查询正确性方面的重要作用。类型检查不仅帮助防止逻辑错误，还能提高查询的性能和可靠性。

**问题**：
- 如果用户提交的评分不是一个有效的数字（例如，一个字符串或负数），SQL查询将返回错误结果。
- 类型系统可以确保`rating`字段始终为有效的整数类型，避免这类错误。

**解决方案**：
```sql

```

**分析**：
- 使用`CAST`函数将`rating`值显式转换为整数类型，确保类型一致性。
- `BETWEEN 1 AND 5`确保评分在有效范围内。

**效果**：
- 确保用户评分的有效性和一致性，提高系统的稳定性。
