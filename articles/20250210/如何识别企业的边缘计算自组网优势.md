# 第一部分: 边缘计算自组网的背景与核心概念

## 第1章: 边缘计算自组网的背景与问题背景

### 1.1 边缘计算自组网的定义与特点
- 1.1.1 什么是边缘计算自组网
  - 边缘计算自组网是一种基于分布式架构的网络组织方式，通过节点间的自组织机制实现网络的自动部署和管理。
  - 边缘节点具备自治能力，能够根据网络状态动态调整通信策略和网络结构。

- 1.1.2 边缘计算自组网的核心特点
  - 分布式架构：节点之间通过分布式协议实现通信和数据同步。
  - 自组织能力：网络能够自动发现节点、建立连接并维护网络拓扑。
  - 高可用性：节点故障自动修复，网络能够容忍部分节点失效。

- 1.1.3 边缘计算自组网与传统网络架构的区别
  - 传统网络架构依赖中心化管理，而边缘计算自组网采用分布式架构。
  - 传统网络架构节点不具备自治能力，而边缘计算自组网节点能够动态调整网络状态。

### 1.2 问题背景与问题描述
- 1.2.1 企业网络架构的痛点
  - 传统网络架构的中心化管理导致网络延迟高、扩展性差。
  - 网络故障时，节点无法快速自愈，导致服务中断。
  - 网络扩展时，需要人工配置节点之间的通信关系，效率低下。

- 1.2.2 中心化网络架构的局限性
  - 单点故障：中心节点失效会导致整个网络瘫痪。
  - 扩展性差：增加新节点需要重新配置中心节点的路由表。
  - 带宽消耗高：所有数据都需要经过中心节点传输。

- 1.2.3 边缘计算自组网的提出与目标
  - 提出背景：解决中心化网络架构的高延迟、低扩展性问题。
  - 目标：通过分布式架构和自组织机制，实现高效、可靠、易于扩展的网络架构。

### 1.3 边缘计算自组网的优势与边界
- 1.3.1 边缘计算自组网的优势
  - 高可用性：节点故障时，网络能够自动修复，保证服务不中断。
  - 低延迟：数据可以在边缘节点直接处理，减少传输到中心节点的延迟。
  - 高扩展性：新增节点可以自动加入网络，无需人工配置。

- 1.3.2 边缘计算自组网的边界与限制
  - 适用场景：适用于对延迟敏感、需要本地计算的场景。
  - 限制：不适合需要集中化数据处理和严格依赖中心化管理的场景。
  - 技术边界：当前主要适用于小型分布式系统，大规模网络的性能优化仍需进一步研究。

- 1.3.3 边缘计算自组网的适用场景与外延
  - 适用场景：工业物联网、边缘AI推理、分布式文件存储。
  - 外延：与区块链技术结合，实现去中心化网络；与5G结合，提升网络传输效率。
