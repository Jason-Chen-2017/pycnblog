## 第3章：形式化验证的基本概念

### 3.1 形式化验证的定义和类型

#### 3.1.1 定义

形式化验证是一种基于数学和逻辑的方法，用于验证系统是否满足预定的安全属性。它通过建立系统的形式化模型，并使用逻辑推理和数学证明来验证系统是否正确。

#### 3.1.2 类型

形式化验证主要分为以下几种类型：

1. **模型检查**：
   - **定义**：模型检查是一种自动化的验证方法，通过比较系统的形式化模型和预定的安全属性来检测错误。
   - **特点**：高效、自动化，但仅适用于较小的系统。

2. **定理证明**：
   - **定义**：定理证明是一种手动或半自动化的验证方法，通过逻辑推理和数学证明来证明系统满足预定的安全属性。
   - **特点**：适用于复杂系统，但验证过程较为复杂。

3. **模拟**：
   - **定义**：模拟是一种通过执行系统的行为来验证其安全性的方法。
   - **特点**：直观、灵活，但可能无法覆盖所有可能的执行路径。

4. **组合验证**：
   - **定义**：组合验证是一种将多种验证方法结合起来的方法，以提高验证的全面性和效率。
   - **特点**：结合了不同验证方法的优势，但需要协调不同方法之间的差异。

#### 4.4.1 Model Checker

   - 使用文本编辑器编写一个简单的Promela模型，例如一个并发进程模型，保存为`.pml`文件。

```promela
process main() {
    int i = 0;
    [i < 5] -> (output("Main process: %d\n", i); i = i + 1);
}
```

#### 4.6.2 源代码实现

接下来，我们将使用SMV验证上述Promela模型。以下是源代码实现和解读：

1. **编写SMV验证脚本**：
   - 创建一个名为`verification.smv`的文件，用于编写SMV验证脚本。

```smv
load "main.pml"
define safety_property1 = (P main!(main) -> G (output("Safety property: Main process terminated.\n")))
verify safety_property1
```

该脚本首先加载了`main.pml`模型，然后定义了一个名为`safety_property1`的安全属性，表示主进程最终会终止，并使用`verify`命令验证该安全属性。

2. **代码解读**：
   - `load "main.pml"`：加载Promela模型。
   - `define safety_property1 = (P main!(main) -> G (output("Safety property: Main process terminated.\n"))`：定义安全属性，其中`P main!(main)`表示主进程满足P发生条件，`G`表示全局性质，即主进程最终会终止。
   - `verify safety_property1`：验证定义的安全属性。

#### 4.6.3 验证流程

现在，我们将执行验证流程，检查提示词语言的安全性。

1. **执行验证**：
   - 打开命令行终端，导航到`verification.smv`文件所在目录。
   - 运行命令`smv verification.smv`执行验证。

   输出结果如下：

   ```plaintext
   verify safety_property1
   --------------------------
   UNR
   ```

   结果中的`UNR`表示验证未发现任何未决状态（Unsolved），即安全属性`safety_property1`被满足。

2. **分析结果**：
   - 如果验证结果为`UNR`，表示定义的安全属性在所有路径上都得到满足。
   - 如果验证结果为`ERROR`或其他状态，表示存在违反安全属性的情况。
