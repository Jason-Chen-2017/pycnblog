## 程序复杂度基础

### 3.1 程序复杂度的定义

程序复杂度是计算机科学中的一个基本概念，它描述了程序执行所需的时间和空间资源。程序复杂度可以分为时间复杂度和空间复杂度两种类型。时间复杂度描述了程序执行时间随着输入规模的增长而变化的趋势，空间复杂度描述了程序执行所需内存空间随着输入规模的增长而变化的趋势。

### 3.2 程序复杂度的类型

程序复杂度可以分为多种类型，其中最常见的类型包括：

| 复杂度类型 | 描述                                                         |
|------------|--------------------------------------------------------------|
| 时间复杂度 | 描述程序执行时间随着输入规模的增长而变化的趋势。             |
| 空间复杂度 | 描述程序执行所需内存空间随着输入规模的增长而变化的趋势。     |
| 渐近复杂度 | 描述程序执行时间或空间资源随着输入规模趋于无穷大时增长的最快速度。 |

### 3.3 程序复杂度的衡量标准

程序复杂度的衡量标准通常使用渐近符号来表示。渐近符号包括 \(O(\cdot)\)，\(\Omega(\cdot)\) 和 \(\Theta(\cdot)\) 等。其中，\(O(\cdot)\) 表示上界，\(\Omega(\cdot)\) 表示下界，\(\Theta(\cdot)\) 表示上下界。

| 符号       | 描述                                                         |
|------------|--------------------------------------------------------------|
| \(O(\cdot)\) | 表示渐近上界，即函数增长的最快速度。                         |
| \(\Omega(\cdot)\) | 表示渐近下界，即函数增长的最慢速度。                         |
| \(\Theta(\cdot)\) | 表示渐近上下界，即函数的增长速度介于上界和下界之间。         |

### 3.4 程序复杂度的关系

程序复杂度之间的关系可以通过以下公式表示：

\[ f(n) = O(g(n)) \land g(n) = \Omega(h(n)) \Rightarrow f(n) = \Theta(h(n)) \]

这意味着如果函数 \(f(n)\) 的增长速度不超过函数 \(g(n)\)，且函数 \(g(n)\) 的增长速度不低于函数 \(h(n)\)，则函数 \(f(n)\) 的增长速度介于函数 \(g(n)\) 和函数 \(h(n)\) 之间。
