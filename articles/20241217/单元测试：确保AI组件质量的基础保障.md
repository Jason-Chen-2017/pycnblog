### 引言

单元测试在软件工程中扮演着不可或缺的角色，它不仅有助于提高代码的可靠性，还能显著提升开发效率和项目维护成本。然而，在人工智能（AI）领域，单元测试的重要性更为突出。这是因为AI组件通常涉及复杂的算法和模型，其正确性和稳定性对于整个系统的性能和用户体验具有决定性的影响。因此，确保AI组件质量的基础保障，需要依赖一套科学有效的单元测试体系。

AI技术的发展历程可以追溯到20世纪50年代，随着计算能力的提升和大数据技术的普及，AI领域经历了从符号主义到连接主义，再到现代深度学习的演变。这一过程中，AI组件的复杂性逐渐增加，从简单的规则系统发展到复杂的神经网络和机器学习模型。这不仅带来了更多的技术挑战，也对测试提出了更高的要求。

随着AI技术的不断发展，单元测试的重要性也在不断提升。一方面，AI组件的复杂度使得单点错误可能引发严重的问题，因此单元测试成为发现和修复这些错误的关键手段；另一方面，随着AI应用场景的扩展，单元测试可以帮助确保系统在不同环境和条件下的稳定性，提高用户体验。

综上所述，单元测试不仅是AI组件质量保障的基础，也是提高开发效率和降低维护成本的有效手段。理解并应用单元测试原则和策略，对于确保AI系统的高质量运行具有重要意义。

### AI组件设计原则

在AI组件的设计过程中，遵循一些基本原则是非常重要的，这不仅能确保组件的可靠性，还能提高其可维护性和可扩展性。以下是一些关键的设计原则：

#### 模块化设计

模块化设计是软件工程中的一个基本概念，它将复杂的系统分解为若干个相对独立的模块，每个模块实现特定的功能。这种设计方法的好处在于，它可以大大降低系统复杂性，使得各个模块可以独立开发、测试和维护。

模块化设计的第一步是明确每个模块的功能和职责。这可以通过需求分析和功能定义来完成。接下来，需要为每个模块定义清晰的接口，使得模块间的交互尽可能简单和明确。接口定义应包括输入参数、输出结果和交互协议。

在实现模块化设计时，需要遵循一些最佳实践。例如，模块间的依赖关系应尽量减少，以避免出现复杂的依赖链。此外，模块的实现应尽可能独立，减少模块之间的共享资源和状态依赖，从而降低模块间的影响。

#### 可复用性

可复用性是提高开发效率的重要途径。在AI组件设计中，应确保模块具有通用性，可以应用于不同的场景和任务。这意味着模块不仅要功能强大，还应具有广泛的适用性。

为了实现可复用性，需要在设计阶段充分考虑模块的通用性。这可以通过为模块设计灵活的参数配置、使用标准的接口和数据结构来实现。例如，在图像处理组件中，可以设计一个通用的图像操作模块，该模块可以处理不同类型和尺寸的图像，只需通过适当的参数设置即可适应不同的应用场景。

此外，还应鼓励开发人员分享和复用已测试和验证的模块，避免重复开发。这可以通过建立组件库和代码审查机制来实现。

#### 可维护性

AI组件通常需要长期运行和维护，因此设计时必须考虑其可维护性。良好的可维护性可以降低维护成本，提高系统的稳定性和可靠性。

为了提高可维护性，需要确保代码的可读性和可理解性。这可以通过编写清晰、简洁的代码和添加注释来实现。此外，还应遵循代码规范和编程风格，确保代码的一致性和规范性。

模块化设计有助于提高可维护性，因为独立的模块可以单独测试和修改，而不会影响其他部分。这减少了代码修改带来的风险，并简化了问题定位和修复过程。

#### 可扩展性

随着AI技术的不断进步，AI组件可能会面临新的功能和性能需求。因此，设计时必须考虑系统的可扩展性，以便能够轻松地适应未来的变化。

为了实现可扩展性，设计时应预留扩展接口和扩展点。这可以通过为模块设计灵活的参数配置和扩展协议来实现。例如，在机器学习算法组件中，可以设计一个通用的训练接口，允许用户选择不同的优化器和损失函数，从而适应不同的训练需求。

此外，应采用模块化架构，使得新功能可以以模块的形式添加到系统中，而不会影响现有模块的功能和性能。

#### 可测试性

可测试性是确保AI组件质量的关键因素。在设计中，应考虑如何方便地进行单元测试和集成测试。这可以通过为模块设计明确的接口和独立的实现逻辑来实现。模块应具有清晰的输入和输出，使得测试用例能够准确地验证其功能。

为了提高可测试性，还可以设计模拟环境和测试驱动开发（TDD）框架，使得测试用例可以独立运行和自动化执行。这不仅可以提高测试效率，还能确保测试覆盖率达到预期。

综上所述，AI组件设计原则包括模块化设计、可复用性、可维护性、可扩展性和可测试性。遵循这些原则，可以确保AI组件具有良好的结构、可靠性和灵活性，从而为系统的长期稳定运行提供坚实的基础。

### AI组件开发流程

在AI组件的开发过程中，遵循一个科学合理的开发流程是确保项目成功的关键。AI组件开发流程通常包括需求分析、设计、编码、测试和部署等几个阶段。以下是每个阶段的具体步骤和注意事项。

#### 需求分析

需求分析是项目开发的第一步，其目的是明确项目的目标和功能需求。在AI组件开发中，需求分析尤为重要，因为AI组件往往具有复杂的算法和模型。以下是一些关键步骤和注意事项：

1. **明确项目目标**：首先，需要明确项目要解决的问题或目标，例如图像识别、自然语言处理或推荐系统等。明确目标有助于确定组件的功能和性能需求。
   
2. **收集需求信息**：与项目利益相关者（如产品经理、数据科学家和用户）进行深入沟通，收集详细的业务需求和用户需求。这可以通过需求调研、用户访谈和需求文档等方式实现。

3. **需求文档**：将收集到的需求整理成文档，确保所有相关方对需求有共同的理解。需求文档应包括功能需求、性能需求和非功能需求（如可维护性、可扩展性和安全性）。

4. **需求评审**：在需求文档完成之后，组织评审会议，确保所有相关方对需求达成一致。这有助于避免后期需求变更和误解。

#### 设计阶段

设计阶段是将需求转化为具体的技术方案的过程。以下是一些关键步骤：

1. **系统设计**：根据需求文档，进行系统架构设计。这包括确定系统的整体结构、模块划分和数据流。在设计过程中，需要考虑系统的可扩展性、性能和可维护性。

2. **组件设计**：对于每个AI组件，进行详细的设计。这包括定义组件的功能、接口和数据结构。组件设计应遵循模块化原则，确保各模块之间的高内聚和低耦合。

3. **算法设计**：在AI组件中，通常涉及复杂的算法和模型。在设计阶段，需要选择合适的算法和模型，并进行详细的设计。这包括算法的流程、参数设置和优化策略。

4. **设计文档**：将设计结果整理成文档，包括系统设计文档、组件设计文档和算法设计文档。设计文档应详细描述每个组件的功能、接口和实现细节，以便后续开发、测试和部署。

#### 编码阶段

编码阶段是将设计转化为代码的过程。以下是一些关键步骤和注意事项：

1. **编写代码**：根据设计文档，编写各个组件的代码。编写代码时应遵循编程规范和最佳实践，确保代码的可读性和可维护性。

2. **版本控制**：使用版本控制系统（如Git）管理代码，确保代码的一致性和可追溯性。定期提交代码，并进行代码审查，以发现和修复潜在的问题。

3. **单元测试**：在编码阶段，应同步进行单元测试。单元测试可以帮助发现代码中的错误，确保每个组件按照预期工作。编写测试用例，并使用自动化测试工具（如JUnit或pytest）执行测试。

4. **代码规范**：确保代码符合编程规范，包括命名规则、代码格式和注释。这有助于提高代码的可读性和一致性。

#### 测试阶段

测试阶段是确保AI组件质量和稳定性的重要环节。以下是一些关键步骤：

1. **单元测试**：对每个组件进行单元测试，确保其功能、性能和稳定性。单元测试应覆盖所有的功能点和边界条件。

2. **集成测试**：将各个组件集成到系统中，进行集成测试。集成测试旨在验证组件之间的交互和系统的整体性能。

3. **性能测试**：进行性能测试，确保AI组件在目标环境下的性能符合要求。性能测试应包括负载测试、压力测试和并发测试等。

4. **安全测试**：进行安全测试，确保AI组件的代码和数据安全。安全测试应包括注入攻击、权限验证和加密算法验证等。

5. **用户测试**：邀请实际用户进行测试，收集用户反馈，发现潜在的问题和改进点。

#### 部署阶段

部署阶段是将AI组件部署到生产环境的过程。以下是一些关键步骤：

1. **部署准备**：确保所有部署环境（如服务器、数据库和中间件）已配置完毕，并符合系统的要求。

2. **部署流程**：制定详细的部署流程，包括部署脚本、配置文件和监控工具。确保部署过程自动化，减少人为错误。

3. **监控和运维**：部署后，进行系统监控和运维，确保系统的稳定性和性能。监控应包括日志分析、性能监控和故障预警等。

4. **持续集成和持续部署**（CI/CD）：引入CI/CD流程，实现自动化构建、测试和部署。这有助于提高开发效率和系统可靠性。

通过以上阶段，可以确保AI组件从需求到设计的全过程都遵循科学合理的开发流程，从而提高组件的质量和可靠性。每个阶段的关键步骤和注意事项都是确保项目成功的关键因素，需要高度重视和严格执行。

### 单元测试的概念与类型

单元测试是软件测试的一种重要形式，它主要针对最小可测试单元（通常是函数、方法或模块）进行验证，确保其按照预期工作。在AI组件开发中，单元测试扮演着至关重要的角色，它能够帮助开发者发现和修复代码中的错误，确保组件的稳定性和可靠性。

#### 单元测试的定义与目的

单元测试的定义源于Grenford J. Myers的经典著作《软件测试艺术》，他认为单元测试是验证最小可测试单元是否按照预期工作的过程。具体来说，单元测试的目的是：

1. **验证功能正确性**：确保AI组件的每个功能点都按照设计要求工作，没有逻辑错误或功能遗漏。
   
2. **发现编码错误**：通过执行测试用例，可以发现代码中的语法错误、逻辑错误或资源泄露等问题。

3. **提高代码质量**：单元测试能够迫使开发者编写更加清晰、模块化的代码，从而提高代码的可读性和可维护性。

4. **降低维护成本**：通过早期发现和修复错误，可以减少后期修复的成本和风险。

#### 单元测试的类型

单元测试可以根据不同的测试目标和执行方式分为以下几种类型：

1. **功能测试**：功能测试是最常见的单元测试类型，它主要验证组件的功能是否符合预期。这种测试通常基于需求文档和功能规格说明，通过编写测试用例来验证每个功能点的正确性。

2. **边界测试**：边界测试关注组件在边界条件下的行为，例如输入值的最大值、最小值或特殊值。这种测试能够发现代码在处理边界条件时的潜在问题。

3. **性能测试**：性能测试旨在评估组件在特定负载下的性能，包括响应时间、吞吐量和资源消耗等。虽然性能测试通常不属于单元测试范畴，但有时也会在单元测试中包含一些性能测试用例。

4. **异常测试**：异常测试旨在验证组件在遇到异常情况（如空指针、异常输入或错误配置）时的响应。这种测试能够确保组件在异常情况下不会崩溃或导致系统不稳定。

5. **安全测试**：安全测试关注组件的安全性，包括防止注入攻击、权限验证和数据加密等。虽然安全测试通常在系统测试阶段进行，但在单元测试中，开发者也应关注潜在的安全漏洞。

6. **集成测试**：集成测试虽然通常不在单元测试范畴内，但有时在单元测试阶段也会进行一些集成测试。这种测试旨在验证组件与其他组件或系统的交互是否符合预期。

#### 单元测试的优势与挑战

**优势：**

1. **早期发现问题**：单元测试能够在代码开发的早期阶段发现错误，从而降低修复成本和风险。

2. **提高代码质量**：单元测试迫使开发者编写清晰、模块化的代码，从而提高代码的质量和可维护性。

3. **自动化测试**：通过自动化工具（如JUnit、pytest等），可以大幅提高测试效率和覆盖率。

4. **代码复用**：单元测试用例可以在不同的项目或环境之间复用，提高测试的一致性和可靠性。

**挑战：**

1. **测试覆盖率**：确保所有代码路径都被测试到是单元测试的一大挑战，特别是在复杂组件中。

2. **测试用例编写**：编写高质量的测试用例需要耗费大量时间和精力，对于新手开发者来说，这是一个较大的挑战。

3. **维护成本**：随着代码和需求的变更，测试用例也需要不断更新和维护，这会增加维护成本。

4. **资源消耗**：单元测试通常需要一定的资源和时间，特别是在复杂的AI组件测试中。

综上所述，单元测试在AI组件开发中具有重要意义，它不仅能够提高代码质量，还能确保组件的稳定性和可靠性。然而，实现有效的单元测试也面临着一些挑战，需要开发者付出持续的努力和关注。

### 单元测试框架

在AI组件开发过程中，选择合适的单元测试框架是确保测试有效性的关键。单元测试框架提供了一系列工具和功能，用于编写、执行和管理测试用例。以下是一些主流的单元测试框架及其特点：

#### JUnit

JUnit是Java语言中最常用的单元测试框架之一。它提供了丰富的功能，包括测试用例的编写、执行和结果报告。以下是JUnit的主要特点：

1. **断言（Assertions）**：JUnit提供了一系列断言方法，用于验证预期的测试结果。例如，`assertEquals`用于验证两个值是否相等，`assertNull`用于验证对象是否为空。

2. **测试用例（Test Cases）**：JUnit允许开发者定义测试用例类，每个测试用例类包含一个或多个测试方法。测试方法通过`@Test`注解标记。

3. **测试套件（Test Suites）**：JUnit允许将多个测试用例组织成测试套件，便于批量执行。

4. **测试结果报告**：JUnit提供了多种报告格式，包括文本、XML和HTML，便于开发者查看测试结果。

#### pytest

pytest是Python语言中的强大单元测试框架，它具有简单易用、功能强大的特点。以下是pytest的主要特点：

1. **简单易用**：pytest的安装和使用非常简单，无需复杂的配置。开发者可以直接使用`pytest`命令运行测试。

2. **丰富的断言**：pytest提供了一系列内置的断言方法，如`assertEqual`、`assertRaises`等，便于开发者编写测试用例。

### 单元测试用例设计

单元测试用例设计是确保AI组件质量的关键步骤之一，一个有效的测试用例能够全面覆盖组件的功能和边界条件，从而发现潜在的问题和缺陷。以下是单元测试用例设计的方法和步骤：

#### 步骤1：理解需求和设计文档

在开始设计测试用例之前，首先需要深入理解组件的需求和设计文档。这包括了解组件的功能、预期行为、输入参数和输出结果。通过仔细阅读需求文档和设计文档，可以确保测试用例的编写符合实际需求。

#### 步骤2：列出功能需求

根据需求文档，列出组件的所有功能需求。这些功能需求将作为测试用例的基础，确保每个功能点都得到验证。例如，如果组件是一个图像识别系统，功能需求可能包括识别各种类型的图像、处理不同的图像尺寸等。

#### 步骤3：定义输入参数和输出结果

对于每个功能需求，定义输入参数和预期输出结果。输入参数可以是正常的输入值、边界值和异常输入值。输出结果则是组件执行功能后应返回的值或状态。例如，在图像识别功能中，输入参数可以是不同类型的图像，输出结果可以是正确的识别标签或错误消息。

#### 步骤4：识别边界条件和异常情况

边界条件和异常情况是测试用例设计中需要特别关注的点。边界条件是指输入值处于临界状态的情况，例如最小值、最大值或特定模式。异常情况是指组件在遇到错误输入或异常条件时的响应。例如，对于图像识别组件，边界条件可能包括非常小的图像尺寸或非常高的图像尺寸，异常情况可能包括不支持的图像格式或内存不足。

#### 步骤5：编写测试用例

基于上述步骤，开始编写具体的测试用例。每个测试用例应包括以下内容：

1. **测试用例编号**：用于标识测试用例的唯一编号。

2. **测试用例名称**：简要描述测试用例的目标和功能。

3. **输入参数**：列出测试用例的输入参数及其值。

4. **测试步骤**：详细描述执行测试的步骤，包括输入参数的设置和预期结果的验证。

5. **预期结果**：描述测试用例预期返回的输出结果或状态。

6. **实际结果**：记录测试执行后的实际输出结果或状态。

7. **测试结果**：记录测试用例的通过、失败或跳过状态。

以下是一个示例测试用例：

| 测试用例编号 | 测试用例名称 | 输入参数 | 测试步骤 | 预期结果 | 实际结果 | 测试结果 |
| :---: | :---: | :---: | :---: | :---: | :---: | :---: |
| TC001 | 测试图像识别准确性 | 图像文件1 | 1. 加载图像文件1；2. 调用图像识别方法；3. 验证识别结果 | 正确识别图像 | 正确识别图像 | 通过 |

#### 步骤6：测试用例评审和优化

完成测试用例编写后，组织评审会议，邀请相关开发人员、测试人员和产品经理参与。评审会议的目的是确保测试用例全面、准确和有效，及时发现和修复潜在的问题。在评审过程中，可以优化和调整测试用例，提高其覆盖率和测试效果。

#### 步骤7：执行测试用例

在评审通过后，执行测试用例。可以使用自动化测试工具（如JUnit、pytest等）批量执行测试用例，并生成详细的测试报告。执行测试时，应重点关注失败用例，分析失败原因并进行相应的调试和修复。

#### 步骤8：持续迭代和更新

组件需求和功能可能会随着项目进展而发生变化，因此测试用例也需要持续迭代和更新。在项目开发过程中，定期回顾和优化测试用例，确保其与最新需求保持一致。此外，还可以根据测试结果和用户反馈，对测试用例进行调整和改进。

通过以上步骤，可以设计出全面、准确和有效的单元测试用例，确保AI组件在各个功能和边界条件下都能稳定、可靠地运行。

### AI组件测试策略

在AI组件开发过程中，测试策略的制定至关重要。一个科学合理的测试策略不仅能够全面覆盖组件的功能和性能，还能有效降低潜在的风险，确保组件的稳定性和可靠性。以下是AI组件测试的主要策略：

#### 功能性测试

功能性测试是验证AI组件功能是否符合需求的最基本测试。其主要目标是确保组件的所有功能点都能够正常工作，没有功能缺失或逻辑错误。以下是一些关键步骤和注意事项：

1. **需求分析**：首先，需要深入理解组件的需求文档，明确组件的功能点和性能指标。这包括识别组件的主要功能、子功能以及特殊需求。

2. **测试用例设计**：根据需求分析的结果，设计详细的测试用例。测试用例应覆盖所有功能点，包括正常情况、边界条件和异常情况。测试用例的设计可以参考前面的章节。

3. **执行测试**：使用自动化测试工具（如Selenium、JUnit、pytest等）执行测试用例。自动化测试可以提高测试效率，确保测试的一致性和可重复性。

4. **回归测试**：在组件功能更新或修复后，进行回归测试，确保新功能没有引入新的问题，原有功能依然正常工作。

5. **测试结果分析**：记录测试结果，分析功能测试的覆盖率，找出未覆盖到的功能点，并进行补充测试。同时，对失败用例进行详细分析，找出问题根源，并进行修复。

#### 性能测试

性能测试是验证AI组件在特定负载下的性能和稳定性的测试。其主要目标是确保组件能够满足性能要求，如响应时间、吞吐量和资源消耗等。以下是一些关键步骤和注意事项：

1. **性能需求分析**：明确组件的性能需求，包括最大响应时间、最大吞吐量和最小资源消耗等。这些需求通常来自项目需求和性能基准。

2. **测试环境配置**：配置测试环境，包括硬件、软件和网络配置。确保测试环境与生产环境尽可能一致，以便更准确地评估组件的性能。

3. **测试用例设计**：设计性能测试用例，包括正常负载、最大负载和极端负载等。测试用例应覆盖不同负载场景，以全面评估组件的性能。

4. **执行性能测试**：使用性能测试工具（如LoadRunner、JMeter等）执行性能测试。在测试过程中，监控系统的性能指标，如CPU使用率、内存使用率和网络流量等。

5. **性能分析**：分析性能测试结果，评估组件的性能是否满足需求。如果发现性能问题，可以优化代码、调整配置或改进算法。

6. **容量规划**：根据性能测试结果，制定容量规划，确保系统在预期负载下能够稳定运行。

#### 安全测试

安全测试是验证AI组件安全性的一系列测试，包括防止注入攻击、权限验证和加密算法验证等。其主要目标是确保组件的数据和代码安全，防止恶意攻击和未授权访问。以下是一些关键步骤和注意事项：

1. **安全需求分析**：明确组件的安全需求，包括数据保护、访问控制和加密算法等。这些需求通常来自安全标准和法规。

2. **测试用例设计**：设计安全测试用例，包括正常操作、边界条件和异常情况。测试用例应覆盖各种安全威胁和攻击方式。

3. **执行安全测试**：使用安全测试工具（如OWASP ZAP、Burp Suite等）执行安全测试。在测试过程中，监控系统的安全响应和漏洞。

4. **安全分析**：分析安全测试结果，找出潜在的安全漏洞和威胁。对发现的安全问题进行修复和再测试。

5. **安全培训**：对开发人员和运维人员开展安全培训，提高其安全意识和技能。

6. **安全审计**：定期进行安全审计，确保组件符合安全标准和法规要求。

#### 测试策略的执行

1. **测试计划**：制定详细的测试计划，包括测试目标、测试范围、测试资源和时间安排等。测试计划应与项目计划紧密集成。

2. **测试执行**：按照测试计划执行各项测试任务，确保测试覆盖率和质量。测试执行应遵循测试流程和规范。

3. **测试报告**：编写详细的测试报告，包括测试结果、问题分析和改进建议。测试报告应及时提交给相关利益相关者。

4. **持续改进**：根据测试结果和用户反馈，持续优化测试策略和流程，提高测试效率和效果。

通过以上测试策略，可以全面评估AI组件的功能、性能和安全，确保组件的稳定性和可靠性。同时，测试策略的执行也需要注重细节和持续改进，以应对不断变化的技术和需求。

### AI组件单元测试优化策略

为了确保AI组件的稳定性和可靠性，优化单元测试策略至关重要。以下是一些关键的优化策略，包括测试覆盖率的提升、测试时间的减少和测试质量的提升。

#### 提升测试覆盖率

1. **全面覆盖功能点**：确保每个功能点都至少有一个测试用例，覆盖所有可能的输入和输出情况。可以通过编写额外的测试用例来补充遗漏的功能点。

2. **增加边界测试**：边界测试可以揭示组件在处理边界条件时的潜在问题。设计测试用例时，应特别关注最小值、最大值和特殊值等边界条件。

3. **代码覆盖率分析**：使用代码覆盖率工具（如JaCoCo、Code coverage for Python等）分析测试覆盖率，找出未覆盖的代码路径，并补充相应的测试用例。

4. **集成测试与单元测试的结合**：在单元测试中引入集成测试元素，确保组件之间的交互和集成过程也被覆盖到。可以通过模拟外部依赖和服务来实现集成测试。

#### 减少测试时间

1. **并行测试**：利用并行测试框架（如Jenkins、pytest-xdist等）将测试用例并行执行，提高测试效率。

2. **缩小测试数据集**：在保证测试效果的前提下，选择代表性的小数据集进行测试，减少测试数据的大小和测试时间。

3. **缓存测试结果**：对于依赖外部服务或资源的测试，可以缓存测试结果，减少重复测试的时间。

4. **使用Mock对象**：在单元测试中使用Mock对象模拟外部依赖和服务，避免真实的网络请求和外部调用，从而减少测试时间。

#### 提升测试质量

1. **持续集成与持续部署（CI/CD）**：引入CI/CD流程，实现自动化构建、测试和部署。这不仅可以提高开发效率，还能确保每次代码更改都经过全面的测试。

2. **测试自动化**：编写和维护自动化测试脚本，实现自动化测试的持续执行。自动化测试不仅可以减少测试时间，还能确保测试的一致性和准确性。

3. **代码审查与静态分析**：在代码提交前进行代码审查和静态分析，及时发现潜在的问题和缺陷。这有助于提升代码质量和测试质量。

4. **测试用例优化**：定期回顾和优化测试用例，确保其与代码和需求保持一致。可以通过删除冗余测试用例、增加新的测试场景和改进测试用例设计来实现优化。

```python
# data_preprocessing.py
import tensorflow as tf
from tensorflow.keras.preprocessing.image import ImageDataGenerator

def preprocess_data(train_dir, test_dir, image_size=(224, 224)):
    train_datagen = ImageDataGenerator(rescale=1./255, rotation_range=40, width_shift_range=0.2,
                                       height_shift_range=0.2, shear_range=0.2, zoom_range=0.2,
                                       horizontal_flip=True, fill_mode='nearest')

    test_datagen = ImageDataGenerator(rescale=1./255)

    train_generator = train_datagen.flow_from_directory(
            train_dir,
            target_size=image_size,
            batch_size=32,
            class_mode='binary')

    test_generator = test_datagen.flow_from_directory(
            test_dir,
            target_size=image_size,
            batch_size=32,
            class_mode='binary')

    return train_generator, test_generator

# model_training.py
from tensorflow.keras.models import Sequential
from tensorflow.keras.layers import Conv2D, MaxPooling2D, Flatten, Dense
from tensorflow.keras.optimizers import Adam
from tensorflow.keras.metrics import categorical_crossentropy

def build_model(input_shape):
    model = Sequential([
        Conv2D(32, (3, 3), activation='relu', input_shape=input_shape),
        MaxPooling2D((2, 2)),
        Conv2D(64, (3, 3), activation='relu'),
        MaxPooling2D((2, 2)),
        Conv2D(128, (3, 3), activation='relu'),
        MaxPooling2D((2, 2)),
        Flatten(),
        Dense(128, activation='relu'),
        Dense(1, activation='sigmoid')
    ])

    model.compile(optimizer=Adam(),
                  loss=categorical_crossentropy,
                  metrics=['accuracy'])
    return model

def train_model(model, train_generator, test_generator, epochs=10):
    model.fit(
        train_generator,
        epochs=epochs,
        validation_data=test_generator,
        validation_steps=50)
```
