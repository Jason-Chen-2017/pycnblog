#### 一、类型通配符基础

##### 1.1 泛型的基本概念

泛型编程是一种在编程语言中通过参数化类型来增强代码复用性和灵活性的编程范式。在泛型编程中，类型参数可以用于定义类、接口和方法，从而实现对多种类型的支持。

```java
public class Box<T> {

    public void set(T t) {

    }

    public T get() {

    }

```

在上面的例子中，`Box` 类使用类型参数 `T` 来表示它可以容纳任意类型的对象。

##### 1.2 类型通配符的定义

类型通配符是一种特殊类型参数，用于表示任意类型的对象。在Java中，类型通配符通常使用 `?` 表示。类型通配符可以用来表示泛型类型中的未知类型，从而实现对多种类型对象的操作。

```java
public class GenericMethod<T> {

        // 对T类型的元素进行操作
    }
}

public class GenericMethodWithWildcard<T> {
    public void add(? super T element) {
        // 对T的上界类型进行操作
    }
}
```

在上面的例子中，`GenericMethod` 使用类型参数 `T` 来定义一个泛型方法，而 `GenericMethodWithWildcard` 使用类型通配符来定义一个泛型方法。

##### 1.3 类型通配符的类型参数

类型通配符可以指定上界和下界，从而进一步限制通配符所表示的类型。

- **上界通配符**（`? extends T`）：表示通配符所表示的类型必须是 `T` 的子类。
- **下界通配符**（`? super T`）：表示通配符所表示的类型必须是 `T` 的父类。

```java

    public void process(List<? extends Number> numbers) {
        // 对Number或其子类的对象进行操作
    }

public class LowerBoundWildcard<T> {
    public void process(List<? super Number> numbers) {
        // 对Number或其父类的对象进行操作
    }
}
```

### 第4章 类型通配符的最佳实践与优化

##### 4.1 避免类型通配符的滥用

滥用类型通配符可能导致代码的不安全和不清晰。以下是一些避免类型通配符滥用的最佳实践：

1. **明确指定类型参数**：

   在大多数情况下，我们应该明确指定类型参数，而不是使用类型通配符。明确指定类型参数可以提高代码的可读性和安全性。


   而不是：

   ```java
   List<?> integers = new ArrayList<>();
   List<? extends Number> numbers = new ArrayList<>();
   ```

2. **避免无界通配符**：

   无界通配符（`?`）虽然可以表示任意类型的对象，但可能会导致类型擦除和类型检查的损失。在性能敏感的场景中，我们应该避免使用无界通配符。

3. **使用限定通配符**：

   当我们需要确保返回类型是特定类型的父类时，可以使用限定通配符（`? super T`）。这有助于保持类型安全。

   ```java

       result.addAll(integers);
       return result;
   }
   ```

##### 4.2 类型通配符的性能优化

类型通配符可能会影响代码的性能，特别是在类型擦除和类型检查方面。以下是一些性能优化的建议：

1. **避免类型擦除**：

   类型擦除是泛型编程中的一个常见问题，它可能导致性能损失。在性能敏感的场景中，我们应该尽量避免类型擦除。

2. **使用具体类型**：

   当我们知道具体的类型时，最好使用具体类型而不是类型通配符。这样可以避免类型擦除和额外的类型检查。

3. **延迟类型检查**：
