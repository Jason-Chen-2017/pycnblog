## 第1章：设计模式概述

### 1.1 设计模式的概念与重要性

设计模式是一套被反复使用、经过分类的、代码的设计模版，它描述了在特定场景下的解决方案。设计模式不仅能够帮助开发者编写更清晰、更优雅的代码，还能够提高代码的复用性、可维护性和可扩展性。在现代软件开发中，设计模式被广泛认为是提高软件质量和开发效率的重要工具。

### 1.2 设计模式的历史与发展

设计模式的概念起源于1970年代的软件工程领域。自Gang of Four（即“四人帮”）在1994年出版的《设计模式：可复用面向对象软件的基础》一书中提出23种经典设计模式以来，设计模式的理论和实践得到了迅速的发展和普及。

### 1.3 设计模式的分类

设计模式主要分为三类：创建型模式、结构型模式和Behavioral模式。

- **创建型模式**：处理对象的创建过程，包括单例模式、工厂方法模式、抽象工厂模式等。
- **结构型模式**：处理类和对象之间的组合，包括适配器模式、桥接模式、代理模式等。
- **行为型模式**：处理对象之间的通信，包括责任链模式、命令模式、解释器模式等。

## 第2章：创建型设计模式

### 2.1 单例模式

#### 2.1.1 单例模式的原理

单例模式确保一个类只有一个实例，并提供一个访问它的全局访问点。

#### 2.1.2 单例模式的实现

```python
class Singleton:
    _instance = None
    
    def __new__(cls, *args, **kwargs):
        if not cls._instance:
            cls._instance = super().__new__(cls, *args, **kwargs)
        return cls._instance

singleton1 = Singleton()
singleton2 = Singleton()
print(singleton1 is singleton2)  # 输出：True
```

#### 2.1.3 单例模式的实际应用

单例模式在许多场景下非常有用，例如数据库连接、线程池和日志系统等。

### 2.2 工厂方法模式

#### 2.2.1 工厂方法模式的原理

工厂方法模式定义一个接口用于创建对象，但让子类决定实例化哪个类。工厂方法使一个类的实例化延迟到其子类。

#### 2.2.2 工厂方法模式的实现

```python
class Creator:
    def create_product(self):
        raise NotImplementedError

class ConcreteCreatorA(Creator):
    def create_product(self):
        return ConcreteProductA()

class ConcreteCreatorB(Creator):
    def create_product(self):
        return ConcreteProductB()

class Product:
    pass

class ConcreteProductA(Product):
    pass

class ConcreteProductB(Product):
    pass

creator_a = ConcreteCreatorA()
product_a = creator_a.create_product()
print(isinstance(product_a, ConcreteProductA))  # 输出：True
```

#### 2.2.3 工厂方法模式的实际应用

工厂方法模式在软件库、框架和系统中常用，例如Java Swing组件和Spring框架中的Bean工厂。

## 第3章：结构型设计模式

### 3.1 适配器模式

#### 3.1.1 适配器模式的原理

适配器模式将一个类的接口转换成客户希望的另一个接口，使得原本由于接口不兼容而无法在一起工作的类可以协同工作。

#### 3.1.2 适配器模式的实现

```python
class Adaptee:
    def specific_method(self):
        print("Adaptee's specific method")

class Target:
    def target_method(self, arg):
        print("Target's target method:", arg)

class Adapter(Adaptee, Target):
    def target_method(self, arg):
        print("Adapter's target method:", arg)
        super().specific_method()

adaptee = Adaptee()
target = Adapter()

adaptee.specific_method()  # 输出：Adaptee's specific method
target.target_method("argument")  # 输出：Adapter's target method: argument
```

#### 3.1.3 适配器模式的实际应用

适配器模式在接口不兼容的场景下非常有用，例如使用旧组件与新系统集成。

## 第4章：行为型设计模式

### 4.1 职责链模式

#### 4.1.1 职责链模式的原理

职责链模式使多个对象都有机会处理请求，从而避免请求发送者和接收者之间的耦合关系。这些对象按顺序排列，直到有一个对象处理请求。

#### 4.1.2 职责链模式的实现

```python
class Handler:
    def __init__(self, successor=None):
        self._successor = successor

    def handle(self, request):
        if not self._successor or self._successor.handle(request):
            return self._handle(request)
        return False

    def _handle(self, request):
        raise NotImplementedError

class ConcreteHandler1(Handler):
    def _handle(self, request):
        if 0 < request <= 10:
            return "Handler1 handles request: " + str(request)
        return False

class ConcreteHandler2(Handler):
    def _handle(self, request):
        if 10 < request <= 20:
            return "Handler2 handles request: " + str(request)
        return False

handler1 = ConcreteHandler1()
handler2 = ConcreteHandler2()
handler1._successor = handler2

request = 5
print(handler1.handle(request))  # 输出：Handler1 handles request: 5
request = 15
print(handler1.handle(request))  # 输出：Handler2 handles request: 15
```

#### 4.1.3 职责链模式的实际应用

职责链模式在过滤器和权限控制系统等场景中非常有用。

## 第7章：设计模式应用技巧与注意事项

### 7.1 设计模式应用的技巧

- 选择合适的设计模式，避免过度设计。
- 保持模式的简单性，避免过度复杂化。
- 合理使用设计模式，避免滥用。

### 7.2 设计模式应用的注意事项

- 设计模式不能解决所有问题，要根据实际情况选择合适的方法。
- 设计模式需要与其他软件工程原则相结合，如模块化、可复用性等。
