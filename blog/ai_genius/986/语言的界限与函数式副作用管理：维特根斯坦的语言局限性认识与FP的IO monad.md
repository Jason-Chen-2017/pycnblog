- I/O 操作：读写文件、网络请求等。
- 修改全局变量：修改全局状态或数据结构。
- 异常处理：捕获和抛出异常。
- 时间延迟：执行异步操作，如定时器、线程调度等。

根据副作用的性质和影响，我们可以将副作用分为以下几类：

- 可恢复副作用：这类副作用不会对程序造成永久性损害，可以通过重试或回滚来恢复。例如，网络请求失败或文件读写错误。
- 不可恢复副作用：这类副作用可能导致程序状态永久性改变，无法通过回滚来恢复。例如，修改全局变量或写入数据库。
- 暂时性副作用：这类副作用仅在一个函数执行期间产生影响，不会影响到其他函数或程序的其他部分。例如，执行时间延迟操作。
- 持久性副作用：这类副作用会持续影响到程序的其他部分，直到程序结束。例如，修改全局变量或写入日志文件。

4.2 副作用管理的策略

- 单子（Monad）：单子是一种将副作用封装在一个类型中的机制。通过使用单子，我们可以将副作用与纯函数分离，从而提高程序的可维护性和可测试性。IO monad是函数式编程中最常用的单子，用于处理I/O操作。

- 错误处理：通过异常处理和错误恢复机制，可以处理可恢复副作用。例如，在发生网络请求失败时，可以尝试重试或返回默认值。

IO monad是函数式编程中用于管理I/O操作的一种机制。它的基本原理是将I/O操作封装在一个类型中，从而使得我们可以通过纯函数来处理I/O操作。在IO monad中，I/O操作被看作是一个包含多个操作序列的类型，我们可以通过链接操作将多个I/O操作串联起来。以下是IO monad的基本原理：

- IO类型：在IO monad中，IO类型是一个单子类型，它将I/O操作封装在一个类型中。IO类型可以看作是一个包含多个I/O操作的序列。每个I/O操作都被封装在一个IO动作（IO action）中，IO动作可以看作是一个函数，它接受输入并返回输出。
- 链接操作：在IO monad中，我们可以使用链接操作将多个I/O操作串联起来。链接操作通常用符号`>>=`表示，它接受一个IO动作和一个函数，并将IO动作的输出作为函数的输入。例如，如果我们有一个读取文件的IO动作`readFile "example.txt"`,我们可以将它与一个解析文本的函数`parseText`链接起来，得到一个新的IO动作`readFile "example.txt" >>= parseText`。这个新的IO动作首先读取文件，然后解析文本。
- 返回操作：在IO monad中，我们可以使用返回操作来生成一个纯函数，该函数可以从IO动作中提取结果。返回操作通常用符号`pure`或`return`表示。例如，如果我们有一个值`x`，我们可以使用`pure x`或`return x`将`x`封装在一个IO动作中。这样，我们就可以在IO monad中使用纯函数来处理这个值。
- 套接字操作：在IO monad中，我们可以使用套接字操作来执行底层网络编程操作。套接字操作通常包括连接、发送和接收数据等。例如，`Socket.connect "localhost" 8080`可以尝试连接到本地主机的8080端口。

5.2 IO monad的应用实例

下面通过一个简单的例子来展示IO monad的应用。假设我们有一个应用程序，它需要从文件中读取数据，然后解析数据并打印出来。我们可以使用IO monad来实现这个应用程序：

```haskell
import System.IO

main :: IO ()
main = do
    contents <- readFile "example.txt"
    let parsedData = parseText contents
    print parsedData

parseText :: String -> [Int]
parseText text = map read (words text)
```

在这个例子中，我们首先使用`readFile "example.txt"`从文件中读取数据，这是一个IO动作。然后，我们使用`parseText`函数解析文本，这是一个纯函数。最后，我们使用`print`函数打印解析后的数据。整个应用程序是一个IO动作序列，我们可以通过链接操作将这些操作串联起来。

5.3 IO monad的优势与局限

IO monad在函数式编程中具有以下优势：

- 避免副作用：通过将I/O操作封装在IO monad中，我们可以将副作用与纯函数分离，从而避免副作用的影响。
- 提高可维护性：IO monad使得代码更加模块化，易于理解和维护。
- 支持异步编程：IO monad支持异步编程，我们可以使用异步I/O操作来提高程序的并发性能。
- 提供类型安全：通过IO monad，我们可以确保I/O操作不会意外地改变程序的状态，从而提供类型安全。

然而，IO monad也存在一些局限：

- 性能开销：IO monad引入了一定的性能开销，因为它需要将I/O操作封装在一个类型中。在某些情况下，直接使用底层的I/O库可能会更高效。
- 学习曲线：对于初学者来说，IO monad可能会比较难以理解，因为它涉及到单子和类型类等高级概念。
- 限制并行性：在某些情况下，IO monad可能无法充分利用并行计算的优势，因为它依赖于串行的IO动作序列。

总之，IO monad是函数式编程中用于管理副作用的强大工具，它通过将副作用与纯函数分离，提高了程序的可预测性和可靠性。然而，我们在使用IO monad时也需要权衡其优势和局限，以找到最适合实际应用的方法。

```haskell

import Network.HTTP.Server
import Network.HTTP.Request
import Network.HTTP.Response

main :: IO ()
main = startServer "localhost" 8080 requestHandler

requestHandler :: Request -> Response ()
requestHandler request = do
    let params = parseQuery (queryString request)
    let responseText = processParams params
    setResponseStatus 200 (responseText)
    setContentType "text/plain"
    return (responseText)

parseQuery :: String -> [(String, String)]
parseQuery query = splitOn "&" query >>= splitOn "="

splitOn :: String -> String -> [String]
splitOn delimiter str = foldr (\c -> \acc -> case c of { _ -> words acc }) [] (takeWhile (/= delimiter) str)

processParams :: [(String, String)] -> String
processParams params =
    let
        sumParams :: [(Int, Int)]
        sumParams = map (\(x, y) -> (read x, read y)) params

        total = sum (map (\(x, y) -> x * y) sumParams)
    in
    "Total: " ++ show total

```
