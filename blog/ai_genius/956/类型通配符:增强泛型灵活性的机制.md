#### 1.2 类型通配符简介

**定义与作用**：
类型通配符（Type Wildcards）是泛型编程中的一个重要概念，它允许我们在声明泛型类型时引入一定的类型不确定性。在Java中，类型通配符通常用`?`表示，它可以是一个简单的`?`，也可以是`? extends B`或者`? super A`。

类型通配符的作用主要体现在以下几个方面：

1. **提高泛型的灵活性**：通过类型通配符，我们可以编写更加通用的泛型代码，减少对具体类型的依赖。
2. **实现类型检查**：类型通配符帮助编译器在编译时进行类型检查，确保代码的运行安全。
3. **简化代码**：在某些情况下，使用类型通配符可以简化泛型代码的编写，提高代码的可读性和可维护性。

**类型通配符的类型**：
在Java中，类型通配符主要有以下三种类型：

1. **无界通配符（?）**：表示没有任何限制的通配符，是最常见的一种类型通配符。它允许任何类型的对象作为通配符类型，但这也可能导致类型检查的不严格。
2. **有界通配符（? extends B）**：表示通配符类型必须是B及其子类的类型。这种通配符可以在泛型方法的参数中使用，以确保输入类型至少具备一定的继承关系。
3. **无界通配符（? super A）**：表示通配符类型必须是A及其超类的类型。这种通配符常用于泛型方法的返回类型，确保返回类型不会超出指定的超类。

**具体使用场景**：
类型通配符在泛型编程中的应用非常广泛，以下是一些常见的使用场景：

1. **泛型方法的参数**：在泛型方法中，可以使用类型通配符作为参数类型，使得方法可以处理多种类型的对象。
2. **泛型集合**：在泛型集合中，可以使用类型通配符表示集合中的元素类型，从而使得集合可以存储多种类型的对象。
3. **泛型类**：在泛型类中，可以使用类型通配符作为成员变量的类型，或者作为构造函数的参数类型。

**类型通配符的限制与条件**：
虽然类型通配符提供了泛型编程的灵活性，但它的使用也受到一定的限制和条件。以下是一些需要注意的方面：

1. **类型边界**：类型通配符可以设置边界条件，以确保通配符类型满足特定的继承关系。
2. **类型通配符的组合**：类型通配符可以组合使用，例如`? extends Number`表示通配符类型必须是Number及其子类。
3. **类型通配符的限制**：在某些情况下，类型通配符的使用可能受到编译器限制，例如在泛型集合中不能使用无界通配符作为元素类型。

通过上述介绍，我们可以看到类型通配符在泛型编程中扮演着重要的角色。它不仅提高了代码的灵活性，还有助于实现类型检查和代码的简化。在后续章节中，我们将进一步探讨类型通配符的详细应用和高级特性。

#### 1.3 泛型编程基础

**泛型编程的定义**：
泛型编程是一种在编程语言中引入参数化类型的编程范式。它允许开发者定义一种模板化的类型，使得代码可以在编译时或运行时根据实际传入的类型参数进行实例化。泛型编程的主要目的是提高代码的灵活性和可复用性，避免代码冗余，同时也能在编译时进行类型检查，提高程序的稳定性和安全性。

**泛型编程的优势**：
1. **类型安全**：泛型编程通过类型参数和类型边界，确保在运行时不会发生类型错误，从而减少了运行时错误的发生。
2. **代码复用**：泛型编程允许开发者编写一次泛型类或方法，即可适用于多种数据类型，减少了代码的重复编写。
3. **性能提升**：泛型编程使得编译器能够生成更高效的代码，因为编译器可以根据类型参数生成具体的类型实现，而不是使用通用的运行时类型检查。

**泛型编程的基本概念**：
1. **类型参数**：类型参数是在泛型类或方法中定义的占位符，用于表示泛化后的类型。类型参数通常用大写字母表示，例如`T`、`K`等。
2. **类型边界**：类型边界是用于限制类型参数的继承关系，确保类型参数满足特定的约束条件。类型边界通常用`extends`或`super`关键字表示。
3. **泛型类**：泛型类是在定义类时使用类型参数的类，它允许在编译时根据传入的类型参数生成具体的类实现。
4. **泛型方法**：泛型方法是在定义方法时使用类型参数的方法，它允许在编译时根据传入的类型参数生成具体的方法实现。
5. **泛型接口**：泛型接口是在定义接口时使用类型参数的接口，它允许在编译时根据传入的类型参数生成具体的接口实现。

**泛型类的定义**：
泛型类的定义通常包含类型参数列表和类体。类型参数列表位于类名之前，例如：

```java
public class Box<T> {
    private T t;

    public void set(T t) {
        this.t = t;
    }

    public T get() {
        return t;
    }
}
```

在这个例子中，`Box`类使用了类型参数`T`，表示这个类可以存储任何类型的对象。

**泛型类的实例化**：
泛型类的实例化需要指定具体的类型参数，例如：

```java
Box<Integer> integerBox = new Box<>();
Box<String> stringBox = new Box<>();
```

在这里，我们分别创建了一个`Box`类的`Integer`类型实例和一个`String`类型实例。

**泛型接口**：
泛型接口的定义与泛型类的定义类似，也包含类型参数列表。例如：

```java
public interface Box<T> {
    void set(T t);
    T get();
}
```

泛型接口用于定义具有通用类型的操作，例如`Box`接口定义了设置和获取对象的操作。

**泛型接口的实现**：
泛型接口的实现需要指定具体的类型参数，例如：

```java
public class IntegerBox implements Box<Integer> {
    private Integer t;

    @Override
    public void set(Integer t) {
        this.t = t;
    }

    @Override
    public Integer get() {
        return t;
    }
}
```

在这里，`IntegerBox`类实现了`Box`接口，并指定了类型参数为`Integer`。

**泛型集合**：
泛型集合（如Java中的`ArrayList`、`HashMap`等）使用类型参数来定义集合中元素的类型。例如：

```java
List<String> stringList = new ArrayList<>();
Map<Integer, String> integerStringMap = new HashMap<>();
```

泛型集合不仅提供了类型安全，还使得集合操作更加直观和易于理解。

**泛型编程的性能优化**：
泛型编程在性能上具有优势，因为它允许编译器生成更高效的代码。然而，也有需要注意的地方，例如：

1. **类型擦除**：泛型编程依赖于类型擦除机制，这意味着在运行时泛型类型参数会被替换为原始类型。这可能会导致一些类型检查仅在编译时进行，而在运行时可能会受到限制。
2. **泛型集合的性能**：泛型集合的性能可能会因为类型擦除和类型边界而受到影响。合理选择类型边界和使用继承关系可以提高泛型集合的性能。

通过上述对泛型编程基础概念的介绍，我们可以看到泛型编程为现代编程带来了许多优势。在后续章节中，我们将深入探讨类型通配符与泛型编程的结合，展示其在实际开发中的应用。

#### 2.1 类型通配符的基本使用方法

**通配符`?`**：
最基本的类型通配符是`?`，它表示一个未知的类型。当我们在泛型编程中使用`?`时，意味着我们接受任何类型的对象。例如：

```java
public void printList(List<?> list) {
    for (Object item : list) {
        System.out.println(item);
    }
}
```

在这个例子中，`printList`方法接受任何类型的`List`，并打印出其中的每个元素。需要注意的是，由于类型是未知的，我们不能对元素进行类型特定的操作，例如`Integer`的`toString()`方法。

**通配符`? extends B`**：
`? extends B`表示通配符类型必须是B及其子类的类型。这种通配符常用于泛型方法的参数类型，例如：

```java
public void printNumbers(List<? extends Number> list) {
    for (Number number : list) {
        System.out.println(number.doubleValue());
    }
}
```

在这个例子中，`printNumbers`方法接受任何`Number`及其子类的`List`。由于这里使用了`? extends Number`，我们只能调用`doubleValue()`方法，而不能调用其他非`Number`类型的方法。

**通配符`? super A`**：
`? super A`表示通配符类型必须是A及其超类的类型。这种通配符常用于泛型方法的返回类型或集合类型，例如：

```java
public List<? super Number> reverse(List<? super Number> list) {
    List<Number> reversedList = new ArrayList<>(list);
    Collections.reverse(reversedList);
    return reversedList;
}
```

在这个例子中，`reverse`方法接受任何`Number`及其超类的`List`，并返回一个新的`List`。由于使用了`? super Number`，返回类型可以是任何`Number`的父类，如`Object`。

**具体使用示例**：
以下是一些使用类型通配符的示例，展示了不同通配符的使用方法：

```java
// 使用无界通配符
List<?> wildcardList = new ArrayList<>();
wildcardList.add("Hello");
wildcardList.add(123);
printList(wildcardList); // 输出：Hello 123

// 使用有界通配符（上界）
List<? extends Number> boundedList = new ArrayList<>();
boundedList.add(456);
boundedList.add(789.0);
printNumbers(boundedList); // 输出：456.0 789.0

// 使用有界通配符（下界）
List<? super Number> boundedReverseList = new ArrayList<>();
boundedReverseList.add(12.34);
boundedReverseList.add(56.78);
List<Number> reversedList = reverse(boundedReverseList);
System.out.println(reversedList); // 输出：[56.78, 12.34]
```

通过这些示例，我们可以看到类型通配符在不同场景下的具体使用方法。类型通配符不仅提高了代码的灵活性，还使得泛型编程更加安全和可维护。

#### 2.2 类型通配符的限制与条件

**上界与下界的概念**：
在泛型编程中，上界（Upper Bound）和下界（Lower Bound）是用于限制类型通配符的边界条件。上界表示通配符类型必须是某个类型的子类，而下界表示通配符类型必须是某个类型的超类。

**通配符的上界和下界**：
1. **上界**：使用`? extends`表示，例如`? extends Number`表示通配符类型必须是`Number`及其子类。这种上界可以确保我们只能调用通配符类型的子类中的方法。
2. **下界**：使用`? super`表示，例如`? super Object`表示通配符类型必须是`Object`及其子类。这种下界可以确保我们只能将通配符类型的对象赋值给超类类型的变量。

**类型通配符的组合使用**：
类型通配符可以组合使用，例如`? extends Number`和`? super Object`。这种组合使用可以进一步细化通配符的类型限制，提高代码的灵活性。

**具体使用示例**：
以下是一些使用类型通配符上界和下界的示例：

```java
// 使用上界
List<? extends Number> boundedExtendsList = new ArrayList<>();
boundedExtendsList.add(new Integer(10));
boundedExtendsList.add(new Double(20.0));
for (Number number : boundedExtendsList) {
    System.out.println(number);
}
// 输出：
// 10
// 20.0

// 使用下界
List<? super Number> boundedSuperList = new ArrayList<>();
boundedSuperList.add(new Integer(30));
boundedSuperList.add(new Double(40.0));
List<Object> objectList = boundedSuperList;
System.out.println(objectList);
// 输出：
// [30, 40.0]

// 使用组合上界和下界
List<? extends Number & Comparable> boundedCombinationList = new ArrayList<>();
boundedCombinationList.add(new Integer(50));
boundedCombinationList.add(new Double(60.0));
for (Number number : boundedCombinationList) {
    System.out.println(number);
}
// 输出：
// 50
// 60.0
```

通过这些示例，我们可以看到如何使用类型通配符的上界和下界来限制类型，确保代码的类型安全性和灵活性。合理使用类型通配符的限制条件，可以编写出更加灵活和健壮的泛型代码。

#### 2.3 类型通配符的泛型方法

**泛型方法的定义**：
泛型方法是在方法定义时使用类型参数的方法。与泛型类类似，泛型方法也允许我们在编译时根据传入的类型参数生成具体的方法实现。泛型方法的定义格式为：

```java
public <T> T methodName(T arg) {
    // 方法实现
}
```

在这个定义中，`<T>`表示类型参数，`T`代表任何类型。`methodName`是方法名，`arg`是方法参数。

**使用类型通配符定义泛型方法**：
类型通配符可以在泛型方法中使用，以提供更灵活的类型处理。以下是一些使用类型通配符定义泛型方法的示例：

1. **无界通配符**：
   ```java
   public <T> void printList(List<T> list) {
       for (T item : list) {
           System.out.println(item);
       }
   }
   ```

   在这个例子中，`printList`方法接受任何类型的`List`，并打印出每个元素。

2. **有界通配符（上界）**：
   ```java
   public <T extends Number> void printNumbers(List<T> list) {
       for (T number : list) {
           System.out.println(number.doubleValue());
       }
   }
   ```

   在这个例子中，`printNumbers`方法接受任何`Number`及其子类的`List`，并打印出每个元素的双精度值。

3. **有界通配符（下界）**：
   ```java
   public <T super Number> void addToList(List<T> list, Number number) {
       list.add(number);
   }
   ```

   在这个例子中，`addToList`方法接受任何`Number`及其超类的`List`，并添加一个`Number`类型的元素。

**泛型方法的使用示例**：
以下是一些使用泛型方法的示例，展示了不同类型通配符的使用方法：

```java
List<String> stringList = new ArrayList<>();
List<Integer> integerList = new ArrayList<>();
List<Number> numberList = new ArrayList<>();

printList(stringList); // 输出：[Hello, World]
printList(integerList); // 输出：[1, 2, 3]
printNumbers(numberList); // 输出：[1.0, 2.0, 3.0]

addToList(stringList, "Java"); // 输出：[Hello, World, Java]
addToList(integerList, new Integer(4)); // 输出：[1, 2, 3, 4]
addToList(numberList, new Double(5.0)); // 输出：[1.0, 2.0, 3.0, 5.0]
```

通过这些示例，我们可以看到如何使用类型通配符定义和调用泛型方法，从而实现更灵活和可复用的代码。

#### 3.1 泛型类的定义

**泛型类的概念**：
泛型类是一种在类定义时使用类型参数的类。通过泛型类，我们可以定义一种具有参数化的类型，使得类可以处理多种数据类型，提高代码的灵活性和可复用性。泛型类的基本形式如下：

```java
public class Box<T> {
    private T item;

    public void set(T item) {
        this.item = item;
    }

    public T get() {
        return item;
    }
}
```

在这个定义中，`<T>`表示类型参数，`T`代表任何类型。`Box`类是一个泛型类，它有两个泛型方法：`set`用于设置类的内部元素，`get`用于获取内部元素。

**泛型类的定义**：
泛型类的定义包含类型参数列表和类体。类型参数列表位于类名之前，例如：

```java
public class Box<T> {
    // 类体
}
```

在这个例子中，`Box`类使用了类型参数`T`，表示这个类可以存储任何类型的对象。

**泛型类的类型参数**：
泛型类的类型参数可以用于类成员变量、构造函数和方法中。以下是一些使用泛型类类型参数的示例：

1. **成员变量**：
   ```java
   private T item;
   ```

   在这个例子中，`item`是泛型类型的成员变量，表示盒子里存储的任何类型的对象。

2. **构造函数**：
   ```java
   public Box(T item) {
       this.item = item;
   }
   ```

   在这个例子中，构造函数接受一个泛型类型的参数，用于初始化盒子中的对象。

3. **方法**：
   ```java
   public <U> U transform(U newitem) {
       T olditem = item;
       item = newitem;
       return olditem;
   }
   ```

   在这个例子中，`transform`方法接受一个泛型类型的参数，并返回原始的泛型类型。这个方法展示了如何使用泛型类型参数进行类型转换。

**泛型类的实例化**：
泛型类的实例化需要指定具体的类型参数，例如：

```java
Box<String> stringBox = new Box<>("Hello");
Box<Integer> integerBox = new Box<>(123);
Box<Double> doubleBox = new Box<>(456.789);
```

在这里，我们分别创建了一个`Box`类的`String`、`Integer`和`Double`类型实例。

**泛型类的使用示例**：
以下是一些使用泛型类的示例，展示了如何创建泛型类实例和操作泛型类的成员变量：

```java
// 创建泛型类实例

// 再次访问成员变量
System.out.println(stringBox.get()); // 输出：World
System.out.println(integerBox.get()); // 输出：456
```

通过这些示例，我们可以看到如何定义和实例化泛型类，并操作泛型类的成员变量。泛型类在提高代码灵活性和可复用性方面具有显著优势，是现代面向对象编程中不可或缺的一部分。

#### 3.2 泛型接口

**泛型接口的概念**：

#### 4.1 类型通配符在泛型类中的应用

**类型通配符在泛型类中的引入**：
类型通配符（Type Wildcards）在泛型类中的应用是为了处理类型不确定的情况，提高代码的灵活性和可复用性。类型通配符允许我们在泛型类中使用未指定具体类型的类型参数。在Java中，类型通配符通常用`?`表示。

**类型通配符的使用场景**：
1. **泛型方法的参数**：在泛型类的方法中，可以使用类型通配符作为参数类型，使得方法可以接受多种类型的对象。
2. **泛型集合**：在泛型类的成员变量中，可以使用类型通配符表示集合中的元素类型，使得集合可以存储多种类型的对象。
3. **泛型类的构造函数**：在泛型类的构造函数中，可以使用类型通配符指定输入参数或返回类型。

**具体示例**：
以下是一个使用类型通配符的泛型类示例：

```java

    private List<? extends Number> numbers;

    public GenericClass(List<? extends Number> numbers) {
        this.numbers = numbers;
    }

    public void printNumbers() {
        for (Number number : numbers) {
            System.out.println(number);
        }
    }

    public void addNumber(Number number) {
        numbers.add(number);
    }

    public List<? extends Number> getNumbers() {
        return numbers;
    }
}
```

在这个例子中，`GenericClass`类使用了类型通配符`? extends Number`，表示`numbers`变量可以存储任何`Number`及其子类的对象。

**类型通配符对泛型类的限制**：
尽管类型通配符提供了泛型类的灵活性，但它的使用也受到一定的限制。以下是一些需要注意的方面：

1. **类型边界**：类型通配符必须设置边界条件，以确保通配符类型满足特定的继承关系。例如，`? extends Number`表示通配符类型必须是`Number`及其子类。
2. **方法调用**：在使用类型通配符时，不能调用不确定类型的方法。例如，如果我们有一个方法`printNumbers`，我们不能在这个方法中调用一个不确定类型的方法，如`toString()`，因为编译器无法确定该方法是否存在。
3. **方法重写**：在继承泛型类时，不能重写使用类型通配符的方法，除非新方法与原方法有相同的类型边界。

**类型通配符在泛型类中的实际应用**：

#### 6.1 可变通配符

**定义与作用**：
可变通配符（Reifiable Wildcards）是Java 5引入的一个特性，它允许我们在泛型代码中指定类型通配符的上下界。可变通配符通过在通配符前加上`?`符号来表示，例如`? extends`和`? super`。可变通配符的主要作用是提供更灵活的泛型类型处理，特别是在类型边界需要调整时。

**可变通配符的使用方法**：
1. **上界通配符（`? extends`）**：表示通配符类型必须是某个类型的子类。这种通配符可以用于方法参数或返回类型，确保传入或返回的类型满足特定的继承关系。

```java
public <T> void processList(List<? extends Number> list) {
    // 对list进行处理
}
```

2. **下界通配符（`? super`）**：表示通配符类型必须是某个类型的超类。这种通配符可以用于方法参数或返回类型，确保传入或返回的类型满足特定的继承关系。

```java
public <T> void addToCollection(Collection<? super Number> collection) {
    // 向collection中添加元素
}
```

**具体使用场景**：
以下是一些使用可变通配符的具体场景：

1. **泛型方法**：在泛型方法中使用可变通配符，可以使得方法更加通用。例如，我们可以编写一个方法，用于处理任意`Number`类型的列表。

```java
public void printNumbers(List<? extends Number> numbers) {

        System.out.println(number);
    }
}
```

2. **泛型集合**：在泛型集合中使用可变通配符，可以确保集合中的元素类型满足特定的继承关系。例如，我们可以创建一个只包含`Number`及其子类的集合。

```java
public void addNumbers(Collection<? super Number> collection, Number... numbers) {
    for (Number number : numbers) {
        collection.add(number);
    }
}
```

3. **泛型类**：在泛型类中使用可变通配符，可以使得类的操作更加灵活。例如，我们可以创建一个可以存储任意`Number`及其子类的泛型类。

```java

```

#### 6.2 多类型通配符

**定义与作用**：
多类型通配符（Multi-type Wildcards）是Java泛型编程中的一个高级特性，允许我们在泛型类型参数中指定多个边界条件。多类型通配符通过组合使用`? extends`和`? super`来定义，使得泛型类型参数可以同时满足多个继承关系。这种特性为泛型编程提供了更大的灵活性和复杂性。

**多类型通配符的使用方法**：
多类型通配符的表示方法为`? extends B & ? super A`，其中`B`是上界类型，`A`是下界类型。这意味着类型参数`T`必须同时满足`B`及其子类，以及`A`及其超类的条件。

1. **上界和下界组合**：使用`? extends B & ? super A`表示类型参数`T`必须满足上界`B`和下界`A`。
2. **交叉类型边界**：在组合使用时，上界和下界需要满足交叉条件，即类型参数`T`必须同时是`B`的子类和`A`的父类。

**具体使用场景**：
以下是一些使用多类型通配符的具体场景：

1. **泛型方法**：在泛型方法中，可以使用多类型通配符来确保方法参数能够同时处理多种类型的对象。

```java

    if (result < 0) {
        System.out.println(a + " is less than " + b);
    } else if (result > 0) {
        System.out.println(a + " is greater than " + b);
    } else {
        System.out.println(a + " is equal to " + b);
    }
}
```

2. **泛型集合**：在泛型集合中，可以使用多类型通配符来确保集合中的元素类型同时满足多个边界条件。

```java

    for (T element : elements) {
        collection.add(element);
    }
}
```

3. **泛型类**：在泛型类中，可以使用多类型通配符来确保类的类型参数同时满足多个边界条件。

```java
public class MultiTypeContainer<T extends Number & String> {

        return value;
    }
```

#### 6.3 类型通配符与类型检查

**类型检查的基本概念**：
类型检查（Type Checking）是编程语言中确保代码类型安全的重要机制。类型检查分为编译时类型检查和运行时类型检查。编译时类型检查在代码编译阶段进行，通过检查代码中的类型一致性来确保程序的正确性。运行时类型检查则在程序运行时进行，通过运行时类型信息来判断代码的类型是否匹配。

**类型通配符对类型检查的影响**：
类型通配符（Type Wildcards）在泛型编程中提供了对类型不确定性的处理，但这也对类型检查带来了一定的影响。以下是一些主要影响：

1. **编译时类型检查**：使用类型通配符可以减少编译时类型检查的范围。例如，在泛型方法中使用`? extends Number`时，编译器不需要检查`Number`及其子类的具体实现，这简化了编译过程，但也可能导致类型检查的不严格。

2. **运行时类型检查**：类型通配符在运行时会影响类型检查，因为编译器无法在编译时确定具体的类型信息。这可能导致一些运行时错误，例如在方法调用时，无法保证类型参数的正确性。

**类型通配符在类型检查中的实际应用**：
类型通配符在类型检查中的一些实际应用场景如下：

1. **泛型方法的参数**：在泛型方法中使用类型通配符，可以确保方法能够处理多种类型的对象，但这也需要结合具体的方法实现进行类型检查。例如，在方法中使用`? extends Number`时，方法内部需要确保能够正确处理`Number`及其子类的对象。
