### 2.2 代码复用的基本概念

#### 2.2.1 代码复用的定义与重要性

**代码复用的定义：**
代码复用是指在不同程序或项目中使用相同或类似的代码，以避免重复编写和维护工作，提高开发效率和代码质量。

**代码复用的重要性：**
- **节省开发时间：** 避免重复编写相同的代码段。
- **提高代码一致性：** 通过复用代码，可以确保不同项目中的代码风格和实现方式一致。
- **便于维护：** 当代码需要更新或修复时，只需在一个地方修改，即可影响所有使用该代码的部分。

#### 2.2.2 代码复用的形式与层次

**代码复用的形式：**
- **功能模块复用：** 将具有独立功能的代码块封装为模块，供其他程序调用。
- **类与对象复用：** 在面向对象编程中，通过继承和组合实现代码的复用。

**代码复用的层次：**
- **局部复用：** 在同一程序内部复用代码。
- **全局复用：** 在不同的程序或项目中复用代码。

1. **模板复用：**
   - **优点：** 简化代码编写，提高开发效率。
   - **缺点：** 复用粒度较低，难以应对复杂业务场景。

   - **优点：** 灵活性高，易于维护。

4. **类与对象复用：**
   - **优点：** 支持面向对象编程，提高代码复用性和灵活性。
   - **缺点：** 需要较深的编程基础，实现相对复杂。

### 3.2 提示词编程语言中的设计模式

#### 3.2.1 创建型设计模式

**工厂模式：**
工厂模式是一种在提示词编程语言中常用的创建型设计模式，它通过工厂类来创建对象，实现对象的创建逻辑的复用。

**伪代码示例：**
```python
class Factory:
    def create_object(type):
        if type == "TypeA":
            return TypeA()
        elif type == "TypeB":
            return TypeB()

# 使用工厂模式创建对象
factory = Factory()
objectA = factory.create_object("TypeA")
objectB = factory.create_object("TypeB")
```

**数学模型与公式：**
假设我们有三种类型的对象（A、B、C），每种类型的对象都有不同的创建概率。我们可以使用以下公式计算每种类型对象的期望数量：

$$
E[A] = p[A] \times N
$$

$$
E[B] = p[B] \times N
$$

$$
E[C] = p[C] \times N
$$

其中，$p[A]$、$p[B]$、$p[C]$ 分别为类型 A、B、C 对象的创建概率，$N$ 为总对象数量。

**举例说明：**
假设创建概率如下：
- 类型 A：40%
- 类型 B：30%
- 类型 C：30%

如果我们需要创建 100 个对象，则期望数量如下：

$$
E[A] = 0.4 \times 100 = 40
$$

$$
E[B] = 0.3 \times 100 = 30
$$

$$
E[C] = 0.3 \times 100 = 30
$$

这意味着在创建 100 个对象的过程中，期望有 40 个类型 A 对象，30 个类型 B 对象，30 个类型 C 对象。

**Mermaid流程图示例：**

#### 3.2.2 结构型设计模式

**装饰器模式：**
装饰器模式是一种在提示词编程语言中常用的结构型设计模式，它通过动态地给一个对象添加一些额外的职责，就增加功能来说，装饰器模式比生成子类更为灵活。

**伪代码示例：**
```python
class Decorator:
    def __init__(self, component):
        self._component = component

    def operation(self):
        self._component.operation()
        # 添加额外的职责
        self.additional_operation()

class ConcreteComponent:
    def operation(self):
        print("基础操作")

class ConcreteDecoratorA(Decorator):
    def additional_operation(self):
        print("额外操作 A")

class ConcreteDecoratorB(Decorator):
    def additional_operation(self):
        print("额外操作 B")

# 使用装饰器模式
component = ConcreteComponent()
decoratorA = ConcreteDecoratorA(component)
decoratorB = ConcreteDecoratorB(decoratorA)

decoratorB.operation()
```

**数学模型与公式：**
假设有一个基础操作的成本为 $C$，额外操作的叠加成本为 $D$，我们可以使用以下公式计算总成本：

$$
C_{total} = C + D \times n
$$

其中，$n$ 为额外操作的次数。

**举例说明：**
假设基础操作的成本为 10，额外操作的叠加成本为 5，如果我们需要进行 3 次额外操作，则总成本为：

$$
C_{total} = 10 + 5 \times 3 = 25
$$

这意味着在执行操作的过程中，总成本为 25。

**Mermaid流程图示例：**

#### 3.2.3 行为型设计模式

**责任链模式：**
责任链模式是一种在提示词编程语言中常用的行为型设计模式，它允许将多个对象连成一条链，请求沿着这条链传递，直到链上的某个对象处理它。

**伪代码示例：**
```python
class Handler:
    def __init__(self, successor=None):
        self._successor = successor

    def handle_request(self, request):
        if self.can_handle_request(request):
            self.handle_internal_request(request)
        elif self._successor is not None:
            self._successor.handle_request(request)

class ConcreteHandlerA(Handler):
    def can_handle_request(self, request):
        return request >= 0 and request <= 10

    def handle_internal_request(self, request):
        print(f"处理请求 {request} 在 ConcreteHandlerA 中")

class ConcreteHandlerB(Handler):
    def can_handle_request(self, request):
        return request > 10 and request <= 20

    def handle_internal_request(self, request):
        print(f"处理请求 {request} 在 ConcreteHandlerB 中")

# 使用责任链模式
handlerA = ConcreteHandlerA()
handlerB = ConcreteHandlerB()

handlerA.handle_request(5)
handlerA.handle_request(15)
```

**数学模型与公式：**
假设有两个处理者（A 和 B），每个处理者都有特定的请求范围，我们可以使用以下公式计算请求的分配情况：

$$
R[A] = r[A] \times p[A]
$$

$$
R[B] = r[B] \times p[B]
$$

其中，$r[A]$、$r[B]$ 分别为处理者 A 和 B 的请求范围，$p[A]$、$p[B]$ 分别为处理者 A 和 B 的概率。

**举例说明：**
假设处理者 A 的请求范围为 0-10，概率为 0.6；处理者 B 的请求范围为 10-20，概率为 0.4。如果我们有 100 个请求，则请求的分配情况如下：

$$
R[A] = 0.6 \times 100 = 60
$$

$$
R[B] = 0.4 \times 100 = 40
$$

这意味着在处理请求的过程中，有 60 个请求由处理者 A 处理，有 40 个请求由处理者 B 处理。

**Mermaid流程图示例：**

```mermaid
B --> C[概率 0.6]
B -->|请求范围 10-20| D[处理者 B]

```

```python
def read_file(file_path):
    with open(file_path, "r") as f:
        return f.readlines()

def split_lines(text):
    return [line.strip() for line in text]

def filter_empty_lines(lines):
    return [line for line in lines if line]

def write_file(file_path, content):
    with open(file_path, "w") as f:
        for line in content:
            f.write(line + "\n")
```

通过这些函数，我们可以实现文本处理操作，并在不同场景下复用代码。与传统的代码实现相比，提示词编程语言使代码更加简洁、易读、易维护。
