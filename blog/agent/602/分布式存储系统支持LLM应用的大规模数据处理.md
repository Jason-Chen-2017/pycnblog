### 第一部分：分布式存储系统概述

#### 第1章：分布式存储系统背景与基本概念

##### 1.1.1 分布式存储系统的发展历程

分布式存储系统起源于20世纪90年代，随着互联网和数据中心的发展而逐渐成熟。早期的分布式存储系统主要基于共享文件系统和网络文件系统（NFS、CIFS）实现，但随着数据规模的不断扩大和存储需求的多样化，传统的集中式存储系统已无法满足需求。分布式存储系统通过将数据分散存储在多个节点上，提高了系统的可扩展性、可靠性和性能。

##### 1.1.2 分布式存储系统的基本概念

分布式存储系统通常由多个节点组成，每个节点负责存储一部分数据，并通过网络进行通信和协同工作。分布式存储系统的主要概念包括：

- 节点：分布式存储系统中的基本单元，负责存储和提供数据服务。
- 数据分片：将大规模数据集划分为多个较小的数据块，存储在不同的节点上。
- 复制：为提高数据的可靠性和访问速度，将数据在多个节点上进行复制。
- 数据一致性：确保分布式存储系统中数据的一致性和完整性。
- 容错性：通过冗余设计和故障转移机制，确保系统在节点故障时仍能正常运行。

##### 1.1.3 分布式存储系统的重要性

分布式存储系统在LLM应用中的重要性主要体现在以下几个方面：

- 可扩展性：分布式存储系统可以轻松地扩展存储容量和性能，以满足大规模数据存储和处理的挑战。
- 可靠性：通过数据复制和容错机制，分布式存储系统确保了数据的安全性和可用性。
- 性能优化：分布式存储系统可以针对不同类型的应用场景进行性能优化，提高数据处理效率。
- 降低成本：分布式存储系统利用廉价的硬件资源，降低了存储成本。

#### 第2章：分布式存储系统核心原理

##### 2.1.1 节点架构

分布式存储系统的节点架构可以分为客户端-服务器架构和对等网络架构。客户端-服务器架构中，客户端负责发送请求并接收响应，服务器负责存储和提供数据服务。对等网络架构中，所有节点都具有相同的功能，相互之间直接进行通信和协同工作。

##### 2.1.2 数据分片与复制

数据分片是将大规模数据集划分为多个较小的数据块，存储在不同的节点上。常用的数据分片策略包括基于哈希的分片和范围分片。复制是将数据在多个节点上进行复制，提高数据的可靠性和访问速度。常用的复制策略包括全复制和部分复制。

##### 2.1.3 数据一致性与容错机制

数据一致性是指分布式存储系统中数据的一致性和完整性。分布式存储系统通常采用一致性算法（如Paxos、Raft）来确保数据的一致性。容错机制是指系统在节点故障时仍能正常运行。分布式存储系统通过冗余设计和故障转移机制实现容错。

##### 2.1.4 系统性能优化

分布式存储系统的性能优化可以从以下几个方面进行：

- 数据访问优化：通过优化数据存储结构和索引策略，提高数据访问速度。
- 资源调度优化：通过负载均衡和资源分配策略，提高系统的整体性能。
- 网络优化：通过优化网络拓扑结构和通信协议，提高数据传输效率。

#### 第3章：主流分布式存储系统

##### 3.1.1 Hadoop HDFS

Hadoop HDFS（Hadoop Distributed File System）是基于Hadoop框架的分布式文件系统，主要用于存储大规模数据集。HDFS采用分片和复制机制，提供了高可靠性、高扩展性和高性能的数据存储和管理功能。

##### 3.1.2 Apache Cassandra

Apache Cassandra是一种分布式NoSQL数据库，适用于大规模数据存储和实时数据处理。Cassandra采用数据分片和复制机制，提供了高可用性、高一致性和高性能的数据存储解决方案。

##### 3.1.3 Amazon S3

Amazon S3（Simple Storage Service）是亚马逊公司提供的分布式对象存储服务，适用于大规模数据存储和访问。S3采用数据分片和复制机制，提供了高可靠性、高扩展性和高性能的数据存储服务。

##### 3.1.4 Google File System (GFS)

Google File System（GFS）是谷歌公司开发的分布式文件系统，主要用于存储和管理大规模数据集。GFS采用数据分片和复制机制，提供了高可靠性、高扩展性和高性能的数据存储和管理功能。

### 第2章：分布式存储系统核心原理

分布式存储系统的核心原理包括节点架构、数据分片与复制、数据一致性与容错机制、以及系统性能优化策略。这些原理共同构成了分布式存储系统的理论基础，是实现高可用性、高性能和可扩展性的关键。

#### 2.1.1 节点架构

节点架构是分布式存储系统的基本组成部分。每个节点都承担一定的存储和处理任务，节点之间的通信和协作决定了系统的整体性能和可靠性。

1. **节点类型**：
   - **主节点（Master Node）**：负责协调和管理整个分布式存储系统，如数据分片和复制策略的制定。在主节点故障时，可以通过选举机制选出新的主节点。
   - **数据节点（Data Node）**：负责存储和提供数据服务，如数据读写、复制和备份。数据节点通常没有固定的角色，可以在系统中动态加入或离开。

2. **节点通信**：
   - **内部通信**：节点之间通过内部通信机制进行数据同步和状态更新。常用的通信协议包括HTTP/HTTPS、gRPC、Thrift等。
   - **外部通信**：节点通过外部接口与其他系统进行数据交换和交互。例如，通过RESTful API或消息队列实现与其他应用程序的集成。

3. **节点管理**：
   - **自组织**：分布式存储系统通常采用自组织机制，自动检测和修复节点故障，动态调整节点角色和负载。
   - **监控与维护**：通过监控工具和运维策略，实时监控节点的运行状态，及时发现和解决潜在问题。

#### 2.1.2 数据分片与复制

数据分片与复制是分布式存储系统的核心功能，通过将数据分散存储在多个节点上，提高系统的可靠性和性能。

1. **数据分片**：
   - **分片策略**：
     - **基于哈希的分片**：将数据按照哈希值分配到不同的节点上，确保数据访问的高效性。
     - **范围分片**：将数据按照特定的范围（如时间、ID等）分配到不同的节点上，适用于有序数据的存储和查询。
   - **分片管理**：
     - **动态分片**：在系统运行过程中，根据数据规模和访问模式动态调整分片策略和节点分配。
     - **分片迁移**：当节点加入或离开系统时，通过分片迁移保证数据的均匀分布和系统的稳定性。

2. **数据复制**：
   - **复制策略**：
     - **全复制**：将数据在所有节点上复制，提供最高的数据可靠性。
     - **部分复制**：只将数据复制到部分节点上，降低存储成本和带宽消耗。
     - **纠删码复制**：通过将数据编码成纠删码，只需存储一部分数据即可恢复整个数据集，适用于大规模数据的存储。
   - **复制管理**：
     - **异步复制**：在数据写入源节点后，异步地将数据复制到其他节点上，提高系统吞吐量。
     - **同步复制**：在数据写入源节点后，立即将数据同步复制到其他节点上，确保数据一致性。

#### 2.1.3 数据一致性与容错机制

数据一致性和容错性是分布式存储系统的关键特性，确保数据在分布式环境中的可靠性和可用性。

1. **数据一致性**：
   - **一致性模型**：
     - **强一致性**：在所有节点上同时读取和写入数据，确保数据的一致性。但强一致性可能影响系统性能和可用性。
     - **最终一致性**：在系统达到稳定状态后，所有节点的数据是一致的，但允许短暂的滞后。最终一致性适用于大多数应用场景。
   - **一致性算法**：
     - **Paxos算法**：通过选举主节点和达成共识机制，确保分布式系统中数据的一致性。
     - **Raft算法**：通过领导选举和日志复制机制，实现分布式系统中的强一致性。

2. **容错机制**：
   - **故障检测与恢复**：通过心跳检测和故障转移机制，实时监控节点的运行状态，并在节点故障时自动恢复系统。
   - **数据冗余**：通过数据复制和纠删码技术，确保在节点故障时仍能访问和恢复数据。
   - **故障隔离**：通过隔离故障节点，防止故障蔓延到整个系统。

#### 2.1.4 系统性能优化

系统性能优化是分布式存储系统设计的重要方面，通过优化数据存储结构、访问策略和网络拓扑结构，提高系统的整体性能。

1. **数据存储优化**：
   - **存储压缩**：通过数据压缩技术，减少存储空间占用和I/O负载。
   - **数据去重**：通过检测和消除冗余数据，提高数据存储效率。
   - **缓存策略**：通过缓存热点数据，减少对底层存储的访问，提高数据访问速度。

2. **访问策略优化**：
   - **负载均衡**：通过负载均衡算法，将访问请求均匀分配到不同节点上，避免单点瓶颈。
   - **缓存机制**：通过缓存机制，减少对底层存储的访问，提高数据访问速度。

3. **网络优化**：
   - **网络拓扑优化**：通过优化网络拓扑结构，减少数据传输延迟和带宽消耗。
   - **网络协议优化**：通过优化网络协议，提高数据传输效率和可靠性。

#### 2.1.5 交易一致性机制

在分布式存储系统中，交易一致性是确保数据在分布式环境中的正确性和一致性的关键。

1. **一致性保障机制**：
   - **两阶段提交（2PC）**：通过两个阶段的协议，确保分布式系统中的多个事务原子性地提交或回滚。
   - **三阶段提交（3PC）**：改进两阶段提交算法，减少单点故障的风险。
   - **最终一致性保障**：通过日志记录和状态机复制机制，实现分布式系统中的最终一致性。

2. **一致性挑战与解决方案**：
   - **数据冲突**：在分布式系统中，多个事务可能同时访问和修改同一份数据，导致数据冲突。

分布式存储系统的可扩展性和弹性是其应对大规模数据和高并发访问的关键。

1. **水平扩展**：通过增加节点数量，线性提高系统的存储容量和处理能力。
2. **弹性扩展**：在系统负载变化时，自动调整节点数量和资源分配，保持系统稳定运行。

### 第3章：主流分布式存储系统

分布式存储系统在处理大规模数据方面具有显著优势，因此许多主流分布式存储系统被广泛采用。本章节将介绍几种常见的分布式存储系统，包括Hadoop HDFS、Apache Cassandra、Amazon S3和Google File System (GFS)，并探讨它们的特点和应用场景。

#### 3.1.1 Hadoop HDFS

Hadoop HDFS（Hadoop Distributed File System）是基于Hadoop框架的分布式文件系统，由Apache Software Foundation维护。HDFS设计用于存储和处理大规模数据集，具有高可靠性、高扩展性和高性能的特点。

1. **特点**：
   - **高可靠性**：通过数据复制和容错机制，确保数据在节点故障时不会丢失。
   - **高扩展性**：可以通过增加数据节点来线性扩展存储容量和性能。
   - **高吞吐量**：适合大规模数据的批量处理，支持高并发访问。
   - **数据本地化**：数据存储在数据节点上，减少了数据传输延迟。

2. **应用场景**：
   - **大数据分析**：适用于大规模数据的存储和批处理，如日志分析、数据挖掘和机器学习。
   - **离线计算**：适合离线处理大量数据，如ETL（提取、转换、加载）任务。

3. **架构**：
   - **NameNode**：负责管理文件系统的命名空间和客户端访问。
   - **DataNode**：负责存储实际数据块，并向客户端提供服务。

#### 3.1.2 Apache Cassandra

Apache Cassandra 是一种分布式NoSQL数据库，由Apache Software Foundation维护。它设计用于处理大量数据的高可用性、高性能和可扩展性，具有弹性、灵活和易于部署的特点。

1. **特点**：
   - **高可用性**：通过数据复制和自动故障转移机制，确保系统在节点故障时仍然可用。
   - **可扩展性**：通过线性扩展数据节点，支持大规模数据存储和访问。
   - **数据一致性**：支持最终一致性，通过一致性策略确保数据正确性。
   - **灵活的查询**：支持SQL-like查询语言CQL（Cassandra Query Language）。

2. **应用场景**：
   - **实时数据存储**：适用于实时数据处理和访问，如金融交易数据、物联网数据。
   - **大规模数据存储**：适用于存储和查询大规模结构化和非结构化数据。

3. **架构**：
   - **Seeds**：负责初始化新节点，并在集群中维护种子列表。
   - **Node**：负责存储数据、处理查询和参与一致性协议。
   - **CommitLog**：负责持久化数据，确保数据在节点故障时不会丢失。

#### 3.1.3 Amazon S3

Amazon S3（Simple Storage Service）是亚马逊公司提供的对象存储服务，具有高可靠性、高可用性和持久性。S3设计用于存储和检索大量数据，支持各种类型的数据访问和集成。

1. **特点**：
   - **高可靠性**：通过冗余存储和数据复制，确保数据的持久性和可用性。
   - **高可用性**：通过多可用区部署，确保数据在特定区域故障时仍然可用。
   - **可扩展性**：支持无限扩展，存储容量和带宽按需付费。
   - **数据加密**：提供数据加密功能，确保数据在传输和存储过程中的安全性。

2. **应用场景**：
   - **云存储**：适用于各种类型的云应用，如大数据分析、物联网、媒体流。
   - **数据归档**：适用于长期数据存储和归档，提供低成本的数据持久化解决方案。
   - **内容分发**：通过亚马逊云前端服务（CloudFront），支持全球范围内的内容分发。

3. **架构**：
   - **区域（Region）**：由多个可用区组成，每个可用区由多个数据中心组成。
   - **桶（Bucket）**：用于存储对象的容器，具有唯一名称。
   - **对象（Object）**：数据存储的基本单元，包括数据本身和元数据。

#### 3.1.4 Google File System (GFS)

Google File System (GFS) 是谷歌公司开发的分布式文件系统，主要用于存储和管理大规模数据集。GFS为谷歌的搜索引擎和其他大规模数据处理应用提供了关键支持。

1. **特点**：
   - **高可靠性**：通过数据分片和复制，确保数据在节点故障时不会丢失。
   - **高性能**：通过数据本地化和高效的数据处理，提高系统吞吐量和响应速度。
   - **高扩展性**：支持大规模数据存储和扩展，通过动态增加节点来线性扩展。
   - **简单性**：设计简单，易于管理和维护。

2. **应用场景**：
   - **大规模数据处理**：适用于大规模数据的存储和批处理，如搜索引擎索引生成、日志分析。
   - **云计算**：作为云计算基础设施的一部分，支持谷歌云服务的存储需求。

3. **架构**：
   - **Master**：负责管理文件系统的命名空间、维护文件目录和分配数据块。
   - **ChunkServer**：负责存储数据块，并响应客户端的数据读写请求。

通过上述介绍，我们可以看到，不同的分布式存储系统在特性、应用场景和架构方面各有优势。Hadoop HDFS 适合大数据分析，Apache Cassandra 适合实时数据存储，Amazon S3 适合云存储和内容分发，Google File System 则是谷歌内部大规模数据处理的核心。了解这些系统，有助于根据具体需求选择合适的存储解决方案。

### 第6章：大规模数据处理算法

在分布式存储系统中，数据处理算法是实现高效数据处理的关键。大规模数据处理算法通常涉及数据清洗与预处理、数据压缩与去重、以及数据分析算法。这些算法在分布式环境中具有重要作用，能够显著提高数据处理效率和质量。

#### 6.1.1 数据清洗与预处理

数据清洗与预处理是大规模数据处理的第一步，其目的是消除数据中的噪声、错误和重复信息，提高数据的质量和一致性。

1. **数据清洗**：
   - **缺失值处理**：处理数据中的缺失值，通过插补或删除的方式消除缺失值的影响。
   - **异常值处理**：识别和修正数据中的异常值，如异常高的收入、异常低的温度等。
   - **重复数据检测与去除**：通过比较数据项的属性，检测并去除重复的数据项。

2. **数据预处理**：
   - **数据格式转换**：将不同格式的数据转换为统一的格式，如将CSV转换为JSON。
   - **数据标准化与归一化**：通过标准化和归一化处理，将数据缩放到同一范围内，便于后续分析。
   - **特征提取**：提取数据中的关键特征，用于模型训练和预测。

#### 6.1.2 数据压缩与去重

数据压缩与去重是提高存储效率和传输速度的重要手段。在分布式存储系统中，数据压缩与去重算法能够显著减少存储空间和带宽需求。

1. **数据压缩**：
   - **无损压缩**：通过算法消除数据中的冗余信息，如使用哈希函数、字典编码等。无损压缩能够完全恢复原始数据，但压缩率相对较低。
   - **有损压缩**：在保持数据基本特征的前提下，去除部分不重要或不明显的信息。有损压缩能够实现更高的压缩率，但可能损失部分数据质量。

2. **数据去重**：
   - **基于哈希的去重**：通过哈希函数对数据进行哈希计算，将哈希值作为数据的唯一标识。在存储前，检查新数据是否已存在，以避免重复存储。
   - **基于指纹的去重**：使用指纹算法（如MD5、SHA-256）生成数据的指纹，通过比较指纹来检测重复数据。

#### 6.1.3 数据分析算法

数据分析算法在分布式存储系统中用于提取数据中的有价值信息，支持决策制定和业务优化。以下是一些常见的数据分析算法：

1. **数据分类算法**：
   - **基于规则的分类**：通过定义规则，将数据划分为不同的类别。如根据客户的年龄、收入等属性，将客户分为不同的群体。
   - **基于模型的分类**：利用机器学习算法（如决策树、随机森林、支持向量机等），通过训练模型对数据进行分类。

2. **数据聚类算法**：
   - **基于距离的聚类**：通过计算数据点之间的距离，将数据划分为不同的聚类。如K-means聚类、层次聚类等。
   - **基于密度的聚类**：通过识别数据中的密度高峰，将数据划分为不同的聚类。如DBSCAN算法。

3. **关联规则挖掘算法**：
   - **Apriori算法**：通过频繁项集和关联规则挖掘，发现数据中的频繁模式和关联关系。
   - **FP-Growth算法**：通过构造频繁模式树，实现高效的关联规则挖掘。

4. **时间序列分析算法**：
   - **移动平均法**：通过计算数据点的移动平均值，识别数据中的趋势和周期性。
   - **自回归模型**：利用自回归模型（如ARIMA模型），分析数据中的时间序列特性。

#### 6.1.4 分布式数据处理框架

分布式数据处理框架（如Apache Spark、Flink等）在分布式存储系统中扮演着重要角色，能够高效地处理大规模数据。以下是一些常见的分布式数据处理框架：

   - **特点**：支持批处理，基于MapReduce模型。提供高效的分布式计算能力。

#### 7.1.1 性能评估指标

性能评估指标是衡量分布式存储系统性能的重要工具。以下是一些常见的性能评估指标：

1. **吞吐量**：吞吐量是指系统在单位时间内处理的数据量。吞吐量越高，系统性能越好。吞吐量可以通过以下公式计算：

   $$ 吞吐量 = \frac{总数据量}{处理时间} $$

2. **延迟**：延迟是指数据从存储系统读取或写入所需的时间。延迟越低，系统响应速度越快。延迟可以通过以下公式计算：

   $$ 延迟 = \frac{总时间}{请求次数} $$

3. **并发度**：并发度是指系统同时处理多个请求的能力。高并发度意味着系统能够同时处理更多的请求，提高资源利用率。并发度可以通过以下公式计算：

   $$ 并发度 = \frac{处理中的请求数}{处理完成的请求数} $$

4. **数据可靠性**：数据可靠性是指系统在数据存储和处理过程中保持数据一致性和完整性的能力。高可靠性意味着系统在故障发生时能够迅速恢复，保证数据不丢失。

5. **资源利用率**：资源利用率是指系统在运行过程中使用资源（如CPU、内存、存储）的效率。高资源利用率意味着系统能够充分利用资源，降低运行成本。

6. **可用性**：可用性是指系统在正常运行状态下的时间比例。高可用性意味着系统在故障发生时能够快速恢复，确保业务连续性。

#### 7.1.2 性能优化策略

性能优化策略是指通过一系列技术手段提高分布式存储系统的性能。以下是一些常见的性能优化策略：

1. **数据本地化**：通过将数据存储在数据访问频率较高的节点附近，减少数据传输延迟，提高访问速度。

2. **负载均衡**：通过负载均衡算法，将访问请求均匀分配到不同的节点上，避免单点瓶颈，提高系统并发度和吞吐量。

3. **缓存策略**：通过缓存热点数据，减少对底层存储的访问，提高数据访问速度。常见的缓存策略包括基于LRU（最近最少使用）的缓存替换策略、基于阈值的缓存刷新策略等。

4. **数据压缩**：通过数据压缩技术，减少存储空间和带宽消耗，提高数据传输和存储效率。常见的数据压缩算法包括Huffman编码、LZ77、LZ78等。

5. **数据去重**：通过检测和消除冗余数据，提高数据存储效率。常见的数据去重算法包括基于哈希的去重、基于指纹的去重等。

6. **并行处理**：通过并行处理技术，将数据处理任务分配到多个节点上，提高系统吞吐量和响应速度。常见的技术包括MapReduce、Spark等分布式计算框架。

7. **冗余设计**：通过冗余设计，提高系统的可靠性和性能。常见的设计策略包括数据复制、数据备份、负载均衡等。

#### 代码演示：Hadoop HDFS环境安装与配置

首先，我们需要安装和配置Hadoop HDFS环境。以下是在Ubuntu 18.04系统中安装Hadoop HDFS的步骤：

1. **安装Java**：Hadoop依赖于Java，因此首先安装Java环境。

   ```bash
   sudo apt update
   sudo apt install openjdk-8-jdk
   ```

2. **下载Hadoop**：从[Hadoop官方下载页面](https://hadoop.apache.org/releases.html)下载最新的Hadoop二进制包。

3. **解压Hadoop**：将下载的Hadoop包解压到合适的位置，例如`/usr/local/`。

   ```bash
   sudo tar -xzvf hadoop-3.2.1.tar.gz -C /usr/local/
   ```

4. **配置Hadoop**：进入Hadoop配置目录，并设置环境变量。

   ```bash
   cd /usr/local/hadoop-3.2.1/etc/hadoop
   sudo vi hadoop-env.sh
   ```

   在`hadoop-env.sh`文件中添加以下内容：

   ```bash
   export JAVA_HOME=/usr/lib/jvm/java-8-openjdk-amd64
   ```

5. **配置HDFS**：编辑`hdfs-site.xml`文件，设置HDFS的工作目录和数据存储路径。

   ```xml
   <configuration>
     <property>
       <name>dfs.replication</name>
       <value>3</value>
     </property>
     <property>
       <name>dfs.namenode.name.dir</name>
       <value>file:/usr/local/hadoop-3.2.1/hdfs/namenode</value>
     </property>
     <property>
       <name>dfs.datanode.data.dir</name>
       <value>file:/usr/local/hadoop-3.2.1/hdfs/datanode</value>
     </property>
   </configuration>
   ```

6. **格式化HDFS**：首次启动HDFS前，需要格式化文件系统。

   ```bash
   bin/hdfs namenode -format
   ```

7. **启动HDFS**：启动HDFS守护进程。

   ```bash
   sbin/hdfs daemonstart
   ```

   这将启动NameNode和DataNode，可以通过浏览器访问NameNode Web UI（默认端口50070）查看HDFS状态。

#### 案例分析：大型语言模型（LLM）的分布式数据处理

假设我们有一个大规模的文本数据集，需要对其进行预处理和训练，以构建一个LLM模型。以下是一个简单的案例分析：

1. **数据预处理**：

   预处理步骤包括分词、去除停用词、标记化等。我们使用Spark的`PySpark`库进行分布式预处理。

   ```python
   from pyspark.ml.feature import Tokenizer
   from pyspark.sql.functions import col

   tokenizer = Tokenizer(inputCol="text", outputCol="words")
   df = df.select("text")
   df = tokenizer.transform(df)
   df = df.select([col(c).cast("string") for c in df.columns])
   df = df.filter(df.words != " ")
   ```

2. **构建词汇表**：

   构建词汇表用于将单词转换为索引。

   ```python
   from pyspark.ml.feature import HashingTF, IDF

   hashingTF = HashingTF(inputCol="words", outputCol="rawFeatures", numFeatures=10000)
   featurizedData = hashingTF.transform(df)

   idf = IDF(inputCol="rawFeatures", outputCol="features")
   idfModel = idf.fit(featurizedData)
   rescaledData = idfModel.transform(featurizedData)
   ```

3. **训练LLM模型**：

   使用训练数据集训练一个简单的语言模型，如BERT或GPT。这里我们假设已经有一个训练好的模型。

   ```python
   from pyspark.ml import Pipeline

   pipeline = Pipeline(stages=[hashingTF, idf])
   trainedModel = pipeline.fit(rescaledData)
   ```

4. **模型推理与预测**：

   使用训练好的模型对新的文本数据进行推理和预测。

   ```python
   def predict(text):
       tokenizer = Tokenizer(inputCol="text", outputCol="words")
       featurizedData = tokenizer.transform([text])
       idfModel = idfModel.transform(featurizedData)
       prediction = trainedModel.transform(idfModel)
       return prediction.select("predictedLabel").collect()[0][0]

   # 示例文本
   text = "This is an example sentence for prediction."
   prediction = predict(text)
   print(f"Prediction: {prediction}")
   ```
