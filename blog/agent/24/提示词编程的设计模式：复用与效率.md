复用与效率是编程中的两个核心概念。复用代码可以减少重复工作，提高开发效率；而效率则决定了程序的性能。提示词编程通过提供灵活的编程方式，使代码的复用性和效率得以提升。本部分将详细探讨复用与效率在编程中的重要性。

## 第三部分：设计模式与应用

### 3.1 创建型模式

创建型模式主要关注对象的创建过程。以下是一些常见的创建型模式：

#### 3.1.1 单例模式

单例模式确保一个类仅有一个实例，并提供一个访问它的全局访问点。

**示例**：

```python
class Singleton:
    _instance = None

    def __new__(cls, *args, **kwargs):
        if not cls._instance:
            cls._instance = super().__new__(cls, *args, **kwargs)
        return cls._instance

singleton1 = Singleton()
singleton2 = Singleton()
print(singleton1 is singleton2)  # 输出：True
```

#### 3.1.2 工厂方法模式

工厂方法模式定义了一个创建对象的接口，但将具体的创建操作委托给子类。

**示例**：

```python
class Creator:
    def create_product(self):
        raise NotImplementedError

class ConcreteCreatorA(Creator):
    def create_product(self):
        return ConcreteProductA()

class ConcreteCreatorB(Creator):
    def create_product(self):
        return ConcreteProductB()

class Product:
    pass

class ConcreteProductA(Product):
    pass

class ConcreteProductB(Product):
    pass

creator = ConcreteCreatorA()
product = creator.create_product()
```

#### 3.1.3 抽象工厂模式

抽象工厂模式提供了一个接口，用于创建相关或依赖对象的家族，而不需要明确指定具体的类。

**示例**：

```python
class AbstractFactory:
    def create_product_a(self):
        raise NotImplementedError

    def create_product_b(self):
        raise NotImplementedError

class ConcreteFactoryA(AbstractFactory):
    def create_product_a(self):
        return ConcreteProductA()

    def create_product_b(self):
        return ConcreteProductB()

class ConcreteFactoryB(AbstractFactory):
    def create_product_a(self):
        return ConcreteProductA()

    def create_product_b(self):
        return ConcreteProductB()

class ProductA:
    pass

class ProductB:
    pass

class ConcreteProductA(ProductA):
    pass

class ConcreteProductB(ProductB):
    pass

factory = ConcreteFactoryA()
product_a = factory.create_product_a()
product_b = factory.create_product_b()
```

#### 3.1.4 建造者模式

建造者模式将一个复杂对象的构建与其表示分离，使得同样的构建过程可以创建不同的表示。

**示例**：

```python
class Builder:
    def build_part_a(self):
        raise NotImplementedError

    def build_part_b(self):
        raise NotImplementedError

    def get_product(self):
        raise NotImplementedError

class ConcreteBuilder(Builder):
    def build_part_a(self):
        # 构建部分A

    def build_part_b(self):
        # 构建部分B

    def get_product(self):
        return self.product

class Director:
    def __init__(self, builder):
        self._builder = builder

    def construct_product(self):
        self._builder.build_part_a()
        self._builder.build_part_b()

class Product:
    pass

director = Director(ConcreteBuilder())
director.construct_product()
product = ConcreteBuilder().get_product()
```

#### 3.1.5 原型模式

原型模式通过复制现有的实例来创建新的实例，而不是通过构造函数新建。这可以节省创建对象所需的时间和资源。

**示例**：

```python
class Prototype:
    def clone(self):
        raise NotImplementedError

class ConcretePrototype(Prototype):
    def clone(self):
        return ConcretePrototype()

original = ConcretePrototype()
clone = original.clone()
```

### 3.2 结构型模式

结构型模式主要关注类和对象的组合。以下是一些常见的结构型模式：

#### 3.2.1 适配器模式

适配器模式将一个类的接口转换成客户希望的另一个接口，使得原本接口不兼容的类可以一起工作。

**示例**：

```python
class Adaptee:
    def specific_request(self):
        return "Specific Request"

class Adapter(Adaptee):
    def request(self):
        return self.specific_request()

client = Adapter()
print(client.request())  # 输出：Specific Request
```

#### 3.2.2 桥接模式

桥接模式将抽象部分与实现部分分离，使它们可以独立地变化。它降低了系统的复杂度，提高了组件的复用性。

**示例**：

```python
class Abstraction:
    def operation(self):
        raise NotImplementedError

class RefinedAbstraction(Abstraction):
    def operation(self):
        return "Refined Operation"

class Implementor:
    def operation_implementor(self):
        raise NotImplementedError

class ConcreteImplementorA(Implementor):
    def operation_implementor(self):
        return "Concrete Operation A"

class Bridge(Abstraction):
    def __init__(self, implementor):
        self._implementor = implementor

    def operation(self):
        return self._implementor.operation_implementor()

abstraction = RefinedAbstraction(ConcreteImplementorA())
print(abstraction.operation())  # 输出：Concrete Operation A
```

#### 3.2.3 组合模式

组合模式将对象组合成树形结构以表示部分-整体的层次结构。它使得客户可以统一使用单个对象和组合对象。

**示例**：

```python
class Component:
    def add(self, component):
        raise NotImplementedError

    def remove(self, component):
        raise NotImplementedError

    def operation(self):
        raise NotImplementedError

class Leaf(Component):
    def add(self, component):
        raise "Leaf cannot add components"

    def remove(self, component):
        raise "Leaf cannot remove components"

    def operation(self):
        return "Leaf operation"

class Composite(Component):
    def __init__(self):
        self._components = []

    def add(self, component):
        self._components.append(component)

    def remove(self, component):
        self._components.remove(component)

    def operation(self):
        for component in self._components:
            component.operation()

composite = Composite()
composite.add(Leaf())
composite.add(Leaf())
composite.operation()
```

#### 3.2.4 装饰者模式

装饰者模式动态地给一个对象添加一些额外的职责，通过使用一个封装的对象，增强了该对象的功能。

**示例**：

```python
class Component:
    def operation(self):
        raise NotImplementedError

class ConcreteComponent(Component):
    def operation(self):
        return "ConcreteComponent operation"

class Decorator(Component):
    def __init__(self, component):
        self._component = component

    def operation(self):
        return self._component.operation()

class ConcreteDecoratorA(Decorator):
    def operation(self):
        return "ConcreteDecoratorA before " + self._component.operation()

class ConcreteDecoratorB(Decorator):
    def operation(self):
        return self._component.operation() + " ConcreteDecoratorB after"

component = ConcreteComponent()
decorator_a = ConcreteDecoratorA(component)
decorator_b = ConcreteDecoratorB(decorator_a)
print(decorator_b.operation())
```

#### 3.2.5 代理模式

代理模式为其他对象提供一个代理以控制对这个对象的访问。

**示例**：

```python
class Subject:
    def request(self):
        raise NotImplementedError

class RealSubject(Subject):
    def request(self):
        return "RealSubject request"

class Proxy(Subject):
    def __init__(self, real_subject):
        self._real_subject = real_subject

    def request(self):
        return self._real_subject.request()

real_subject = RealSubject()
proxy = Proxy(real_subject)
print(proxy.request())  # 输出：RealSubject request
```

### 3.3 行为型模式

行为型模式主要关注对象之间的交互和通信。以下是一些常见的行为型模式：

#### 3.3.1 策略模式

策略模式定义了一系列算法，将每个算法封装起来，并使它们可以互换。策略模式让算法的变化独立于使用算法的客户。

**示例**：

```python
class Strategy:
    def execute_strategy(self):
        raise NotImplementedError

class ConcreteStrategyA(Strategy):
    def execute_strategy(self):
        return "Strategy A"

class ConcreteStrategyB(Strategy):
    def execute_strategy(self):
        return "Strategy B"

class Context:
    def __init__(self, strategy):
        self._strategy = strategy

    def set_strategy(self, strategy):
        self._strategy = strategy

    def execute_strategy(self):
        return self._strategy.execute_strategy()

context = Context(ConcreteStrategyA())
print(context.execute_strategy())  # 输出：Strategy A

context.set_strategy(ConcreteStrategyB())
print(context.execute_strategy())  # 输出：Strategy B
```

#### 3.3.2 模板方法模式

模板方法模式定义一个操作中的算法的骨架，而将一些步骤延迟到子类中。模板方法使得子类可以不改变一个算法的结构，即可重定义该算法的某些特定步骤。

**示例**：

```python
class TemplateMethod:
    def template_method(self):
        self.hook_method()
        self.step_a()
        self.step_b()

    def hook_method(self):
        pass

    def step_a(self):
        print("Step A")

    def step_b(self):
        print("Step B")

class ConcreteClassA(TemplateMethod):
    def hook_method(self):
        print("ConcreteClassA hook method")

class ConcreteClassB(TemplateMethod):
    def hook_method(self):
        print("ConcreteClassB hook method")

template_method = TemplateMethod()
template_method.template_method()  # 输出：ConcreteClassA hook method
# Step A
# Step B

concrete_class_a = ConcreteClassA()
concrete_class_a.template_method()  # 输出：ConcreteClassA hook method
# Step A
# Step B

concrete_class_b = ConcreteClassB()
concrete_class_b.template_method()  # 输出：ConcreteClassB hook method
# Step A
# Step B
```

#### 3.3.3 观察者模式

观察者模式定义对象间的一种一对多的依赖关系，当一个对象的状态发生改变时，所有依赖于它的对象都得到通知并自动更新。

**示例**：

```python
class Observer:
    def update(self, subject):
        raise NotImplementedError

class Subject:
    def __init__(self):
        self._observers = []

    def attach(self, observer):
        self._observers.append(observer)

    def detach(self, observer):
        self._observers.remove(observer)

    def notify(self):
        for observer in self._observers:
            observer.update(self)

class ConcreteObserver(Observer):
    def update(self, subject):
        print(f"Observer: {subject} has changed.")

subject = Subject()
observer = ConcreteObserver()
subject.attach(observer)

subject.notify()  # 输出：Observer: <__main__.Subject object at 0x7f6a1d1d75f0> has changed.
```

#### 3.3.4 返回值模式

返回值模式是一种行为型设计模式，用于解决返回多个值的问题，而不是使用复杂的数据结构。

**示例**：

```python
class Result:
    def __init__(self, success, value=None, error_message=None):
        self.success = success
        self.value = value
        self.error_message = error_message

def function_with_result():
    try:
        value = some_expensive_computation()
        return Result(True, value)
    except Exception as e:
        return Result(False, error_message=str(e))

result = function_with_result()
if result.success:
    print(result.value)
else:
    print(f"Error: {result.error_message}")
```

#### 3.3.5 职责链模式

职责链模式使多个对象都有机会处理请求，从而避免了请求发送者和接收者之间的耦合关系。这些对象按照一定的顺序连接起来，形成一条链，请求在这条链上传递，直到有一个对象处理它。

**示例**：

```python
class Handler:
    def __init__(self, successor=None):
        self._successor = successor

    def handle(self, request):
        handled = self._handle(request)
        if not handled:
            if self._successor:
                return self._successor.handle(request)
            else:
                return False

    def _handle(self, request):
        raise NotImplementedError

class ConcreteHandlerA(Handler):
    def _handle(self, request):
        if isinstance(request, ARequest):
            return True
        else:
            return False

class ConcreteHandlerB(Handler):
    def _handle(self, request):
        if isinstance(request, BRequest):
            return True
        else:
            return False

class DefaultHandler(Handler):
    def _handle(self, request):
        return False

class Request:
    pass

class ARequest(Request):
    pass

class BRequest(Request):
    pass

handler_a = ConcreteHandlerA()
handler_b = ConcreteHandlerB()
handler_a._successor = handler_b
handler_a.handle(ARequest())  # 输出：True
handler_a.handle(BRequest())  # 输出：True
handler_a.handle(CRequest())  # 输出：False
```
