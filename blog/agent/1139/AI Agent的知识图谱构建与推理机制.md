## 第一部分：知识图谱基础

### 第1章：知识图谱概述
#### 1.1 知识图谱的定义与背景
知识图谱（Knowledge Graph）是一种用于结构化表示和存储知识的图形化数据模型。它通过实体、属性和关系的组合，将现实世界中的信息进行抽象和组织，形成一种网络结构，以便于计算机处理和推理。

知识图谱的起源可以追溯到语义网（Semantic Web）的概念，由万维网的创始人蒂姆·伯纳斯-李（Tim Berners-Lee）在2001年提出。语义网旨在通过语义标注和机器可读的描述，使得网络上的信息能够被计算机更好地理解和处理。

知识图谱在近年来得到了广泛关注和应用，主要得益于以下几个方面的原因：
1. **大数据的兴起**：随着互联网的快速发展，产生了海量数据，传统的数据存储和检索方法已经无法满足需求。知识图谱通过结构化的方式组织和存储知识，提高了数据检索的效率。
2. **人工智能的进步**：随着深度学习等人工智能技术的发展，计算机对知识的理解和推理能力得到了显著提升。知识图谱为人工智能提供了丰富的知识资源，使得智能系统更加智能。
3. **应用需求的变化**：越来越多的应用场景需要智能系统具备对知识的理解和推理能力，如智能问答、推荐系统、智能搜索引擎等。知识图谱提供了有效的知识表示和推理方法，满足了这些应用的需求。

#### 1.2 知识图谱的重要性与应用领域
知识图谱在多个领域都具有重要的应用价值：
1. **搜索引擎**：知识图谱可以帮助搜索引擎更好地理解用户查询的语义，提供更准确的搜索结果。例如，当用户搜索“奥巴马”时，知识图谱可以提供关于奥巴马的详细信息，包括他的总统任期、家庭背景等。
2. **推荐系统**：知识图谱可以帮助推荐系统发现用户之间的潜在关系，提供更个性化的推荐。例如，在电子商务平台中，知识图谱可以分析用户购买的历史数据，推荐与其有相似兴趣的其他商品。
3. **智能问答**：知识图谱可以为智能问答系统提供丰富的知识资源，使得系统能够回答用户的问题。例如，在智能客服中，知识图谱可以帮助系统理解用户的提问，并从庞大的知识库中找到相关的答案。
4. **知识管理**：知识图谱可以帮助企业和组织更好地管理和利用内部知识，提高工作效率和创新能力。例如，在大型企业中，知识图谱可以帮助员工快速找到所需的知识和信息，促进知识的共享和传播。

#### 1.3 知识图谱与传统数据库的区别
知识图谱与传统数据库在数据模型和查询方式上有显著区别：
1. **数据模型**：
   - **传统数据库**：基于关系型模型，数据以表的形式存储，通过SQL等查询语言进行操作。表与表之间通过外键关联，形成复杂的关系网络。
   - **知识图谱**：基于图形模型，数据以节点（实体）和边（关系）的形式存储。节点表示实体，边表示实体之间的关系，形成一个复杂的网络结构。

2. **查询方式**：
   - **传统数据库**：使用SQL等查询语言进行结构化查询，通过表与表之间的关联来获取所需数据。查询过程较为复杂，需要编写复杂的SQL语句。
   - **知识图谱**：使用图查询语言（如SPARQL）进行查询，可以直接基于节点和边的关系进行操作。查询过程相对简单，能够快速获取所需数据。

#### 1.4 知识图谱的基本元素
知识图谱由以下基本元素组成：
1. **实体（Entity）**：知识图谱中的实体表示现实世界中的对象，如人、地点、事物等。实体具有唯一的标识符和属性。
2. **属性（Attribute）**：属性描述实体的特征或属性，如姓名、年龄、位置等。属性通常与实体关联，并通过关系进行组织。
3. **关系（Relationship）**：关系表示实体之间的关联或联系，如朋友、属于、位于等。关系通常具有方向性和权重。
4. **类型（Type）**：类型是对实体的分类或标签，如人物、地点、组织等。类型用于描述实体的类别和属性。
5. **数据源（Data Source）**：数据源是知识图谱的数据来源，可以是结构化数据、非结构化数据或半结构化数据。数据源提供知识图谱所需的数据和实体关系。

通过这些基本元素，知识图谱能够对现实世界中的信息进行抽象和组织，形成一种结构化、语义化的知识表示，为AI Agent提供丰富的知识资源和推理基础。

### 第2章：知识表示
#### 2.1 实体与属性
在知识图谱中，实体和属性是核心的表示元素。实体代表现实世界中的对象，而属性则描述实体的特征。

1. **实体**：
   实体是知识图谱中的基本元素，表示现实世界中的对象，如人、地点、事物等。实体具有唯一的标识符（ID）和一组属性。实体的标识符通常是一个字符串，用于唯一标识一个实体。实体的属性描述实体的特征或属性，如姓名、年龄、位置等。属性通常与实体关联，并通过关系进行组织。

2. **属性**：
   属性是实体的特征或属性的描述，用于补充实体的信息。属性通常具有类型和值。属性类型表示属性的类型或类别，如字符串、整数、日期等。属性值表示属性的取值，如“张三”的姓名属性值为“张三”，“30”的年龄属性值为“30”。

3. **实体与属性的关系**：
   在知识图谱中，实体与属性之间的关系是通过边（关系）来表示的。边具有方向性和权重，表示实体之间的关系。例如，在社交网络中，一个用户实体可以与另一个用户实体之间建立朋友关系，通过一个表示朋友关系的边连接。这个边的方向是从一个实体指向另一个实体，权重可以表示关系的强度或可信度。

#### 2.2 关系的表示与类型
关系是知识图谱中表示实体之间关联或联系的重要元素。关系具有方向性和类型。

1. **关系的表示**：
   关系通过边（Edge）来表示，边连接两个节点（实体）。边具有起点和终点，表示关系的方向。例如，在知识图谱中，一个实体A与另一个实体B之间存在“朋友”关系，可以表示为边（A, B）。这个边的起点是实体A，终点是实体B。

2. **关系的类型**：
   关系的类型用于描述实体之间的关系类别或标签。关系类型通常是一个字符串，用于表示关系的含义。例如，在社交网络中，关系类型可以是“朋友”、“同事”、“同学”等。关系类型有助于对知识图谱进行分类和组织，使得查询和处理更加高效。

#### 2.3 知识图谱的语义与本体论
知识图谱的语义是指知识图谱所表达的意义和知识结构。本体论（Ontology）是研究知识表示和推理的学科，用于定义知识的概念、关系和属性。在知识图谱中，本体论用于指导知识表示和推理。

1. **语义**：
   语义是知识图谱的核心，决定了知识图谱的表达能力和推理能力。知识图谱的语义包括实体的语义、属性的语义和关系的语义。实体的语义描述实体的属性和特征，如人的姓名、年龄等。属性的语义描述属性的类型和取值范围，如姓名属性是字符串类型，年龄属性是整数类型。关系的语义描述关系的作用和意义，如朋友关系表示两个实体之间的社交关系。

2. **本体论**：
   本体论为知识图谱提供了概念化和分类框架，用于描述知识结构。本体论包括概念（Concept）、属性（Attribute）、关系（Relationship）和实例（Instance）等元素。概念是对实体或属性的分类，属性描述概念的特征或关系，关系描述概念之间的联系，实例是概念的具体实例。

在知识图谱构建过程中，本体论用于定义知识结构和语义关系。通过本体论，知识图谱可以更好地表示知识的语义和结构，提高知识表示的准确性和一致性。

#### 2.4 实体与关系的匹配与相似性
在知识图谱中，实体与关系的匹配和相似性是关键问题，直接影响知识图谱的准确性和可用性。

1. **实体匹配**：
   实体匹配是指将两个或多个实体进行匹配或识别，判断它们是否代表同一个实体。实体匹配的目的是消除数据中的重复和冗余，提高知识图谱的准确性。实体匹配通常基于实体属性的相似性、实体关系的匹配和实体标识符的匹配。例如，如果两个实体具有相同的名称、出生日期和其他属性，那么可以认为它们代表同一个实体。

2. **关系匹配**：
   关系匹配是指将两个或多个关系进行匹配或识别，判断它们是否代表相同的关系。关系匹配的目的是确保知识图谱中关系的一致性和准确性。关系匹配通常基于关系类型的匹配和关系属性的匹配。例如，如果两个关系具有相同的类型（如“朋友”）和属性（如“年龄差异”），那么可以认为它们代表相同的关系。

3. **相似性度量**：
   相似性度量是指计算两个实体或两个关系之间的相似度。相似性度量用于实体匹配和关系匹配，以及推荐系统、聚类分析等应用。常用的相似性度量方法包括基于属性的相似性度量、基于距离的相似性度量、基于模型的相似性度量等。例如，基于属性的相似性度量可以计算两个实体属性的相似度，基于距离的相似性度量可以计算两个实体之间的距离。

通过实体与关系的匹配和相似性度量，知识图谱可以更好地表示和利用实体和关系，提高知识的准确性和可用性。

### 第3章：知识图谱构建方法
知识图谱构建是知识图谱应用中的核心环节，涉及到数据源选择、数据预处理、实体抽取、关系抽取、知识融合等多个步骤。下面将详细探讨这些构建方法。

#### 3.1 数据源选择与数据预处理
1. **数据源选择**：
   数据源是知识图谱构建的基础，选择合适的数据源对于构建高质量的知识图谱至关重要。常见的数据源包括结构化数据（如关系数据库）、半结构化数据（如XML、JSON）、非结构化数据（如文本、图像）等。在选择数据源时，需要考虑数据的质量、覆盖范围、一致性等因素。

2. **数据预处理**：
   数据预处理是知识图谱构建的重要步骤，包括数据清洗、数据格式转换和数据去重等。数据清洗旨在去除数据中的噪声和错误，提高数据的质量。数据格式转换将不同类型的数据转换为统一的格式，便于后续处理。数据去重旨在消除数据中的重复和冗余，提高数据的有效性。

#### 3.2 实体抽取与关系抽取
1. **实体抽取**：
   实体抽取是从原始数据中识别和提取出实体（如人、地点、事物等）的过程。实体抽取方法包括基于规则的方法、基于统计的方法和基于深度学习的方法。基于规则的方法通过预定义的规则来识别实体，具有解释性和可解释性。基于统计的方法通过统计方法识别实体，具有较高的准确性和鲁棒性。基于深度学习的方法通过神经网络模型识别实体，具有较高的准确性和泛化能力。

2. **关系抽取**：
   关系抽取是从原始数据中识别和提取出实体之间的关系（如“属于”、“位于”等）的过程。关系抽取方法包括基于规则的方法、基于统计的方法和基于深度学习的方法。基于规则的方法通过预定义的规则来识别关系，具有解释性和可解释性。基于统计的方法通过统计方法识别关系，具有较高的准确性和鲁棒性。基于深度学习的方法通过神经网络模型识别关系，具有较高的准确性和泛化能力。

#### 3.3 知识融合与融合策略
1. **知识融合**：
   知识融合是将来自不同数据源、不同格式的知识进行整合和统一的过程。知识融合的目标是消除知识之间的不一致性和冲突，提高知识的准确性和一致性。知识融合方法包括基于规则的融合方法、基于统计的融合方法和基于深度学习的融合方法。

2. **融合策略**：
   知识融合策略是指选择合适的融合方法和参数，以最大化融合效果。常见的融合策略包括：
   - **一致性策略**：通过消除数据中的冲突和不一致性，提高知识的准确性。一致性策略包括数据清洗、数据去重和数据规范化等。
   - **加权融合策略**：根据不同数据源的可靠性和重要性，为不同数据源分配不同的权重，进行加权融合。
   - **模型融合策略**：结合不同模型的优点，进行模型融合，提高融合效果。例如，结合规则模型和统计模型的优点，构建混合模型进行融合。

通过数据源选择、数据预处理、实体抽取、关系抽取和知识融合等构建方法，可以构建高质量的知识图谱，为AI Agent提供丰富的知识资源和推理基础。

### 第二部分：知识图谱推理

#### 第4章：推理基础
推理是知识图谱的核心功能之一，它基于知识图谱中的实体、关系和属性，通过逻辑推理和计算方法，发现新的知识或验证已有知识的有效性。在本章中，我们将介绍推理的定义、类型和基本原理。

#### 4.1 推理的定义与类型
1. **推理的定义**：
   推理是从已知的事实或前提中推导出新的结论或知识的过程。在知识图谱中，推理是指利用已有的知识和逻辑规则，发现新的知识或验证已有知识的有效性。

2. **推理的类型**：
   推理可以分为两大类：演绎推理和归纳推理。
   - **演绎推理（Deductive Reasoning）**：演绎推理是从一般到特殊的推理过程，即从一组前提中推导出特定结论。演绎推理遵循逻辑规则，具有确定性。例如，如果所有猫都会爬树，而小黑是一只猫，那么可以推断出小黑会爬树。
   - **归纳推理（Inductive Reasoning）**：归纳推理是从特殊到一般的推理过程，即从一组特定实例中推导出一般规律或结论。归纳推理依赖于经验和概率，具有不确定性。例如，观察多次下雨时天气变凉，可以推断下雨时天气变凉的可能性较大。

#### 4.2 推理算法概述
推理算法是知识图谱推理的核心，根据推理方法的分类，可以分为基于规则的推理算法和基于模型的推理算法。

1. **基于规则的推理算法**：
   基于规则的推理算法是通过预定义的规则，从已知的事实推导出新的结论。这些规则通常表示为“如果...那么...”的形式，称为产生式规则。基于规则的推理算法主要包括以下几种：
   - **正向推理（Forward Chaining）**：正向推理是从已知的事实开始，通过匹配规则的前件，逐步推导出结论。正向推理通常用于推理引擎和专家系统。
   - **反向推理（Backward Chaining）**：反向推理是从结论开始，通过匹配规则的后件，逐步推导出已知的事实。反向推理通常用于验证推理的正确性或寻找证据。

2. **基于模型的推理算法**：
   基于模型的推理算法是通过构建模型，从已知的事实和模型参数中推导出新的结论。这些模型可以是逻辑模型、概率模型或神经网络模型等。基于模型的推理算法主要包括以下几种：
   - **逻辑模型推理**：逻辑模型推理是基于逻辑推理规则的推理算法，如谓词逻辑、模态逻辑等。逻辑模型推理通常用于知识表示和验证。
   - **概率模型推理**：概率模型推理是基于概率分布的推理算法，如贝叶斯网络、马尔可夫模型等。概率模型推理通常用于不确定性和概率推理。
   - **神经网络推理**：神经网络推理是基于神经网络模型的推理算法，如深度神经网络、图神经网络等。神经网络推理通常用于大规模数据和复杂关系的推理。

#### 4.3 基于规则的推理
基于规则的推理是通过预定义的规则，从已知的事实推导出新的结论的过程。下面将详细介绍基于规则的推理方法。

1. **产生式规则**：
   产生式规则（Production Rule）是表示知识的一种形式，通常表示为“如果...那么...”的形式。例如，以下是一个简单的产生式规则：
   ```
   如果（温度高于30℃）并且（湿度低于40%），
   那么（天气炎热）。
   ```

2. **正向推理（Forward Chaining）**：
   正向推理是从已知的事实开始，通过匹配规则的前件，逐步推导出结论的过程。正向推理的基本步骤如下：
   - **初始化**：将已知的事实（前提）放入一个事实库中。
   - **规则匹配**：遍历所有规则，检查规则的前件是否与事实库中的事实匹配。
   - **结论推导**：如果规则的前件与事实匹配，则执行规则的结论部分，将结论添加到事实库中。
   - **循环迭代**：重复规则匹配和结论推导过程，直到无法找到新的结论。

3. **反向推理（Backward Chaining）**：
   反向推理是从结论开始，通过匹配规则的后件，逐步推导出已知的事实的过程。反向推理的基本步骤如下：
   - **初始化**：将目标结论放入一个目标库中。
   - **规则匹配**：遍历所有规则，检查规则的后件是否与目标库中的目标匹配。
   - **前提推导**：如果规则的后件与目标匹配，则执行规则的逆规则，将前提添加到目标库中。
   - **循环迭代**：重复规则匹配和前提推导过程，直到无法找到新的前提。

基于规则的推理方法简单直观，易于理解和实现。然而，它也存在一些局限性，如规则表示能力的限制、推理效率的瓶颈等。在实际应用中，通常会结合多种推理方法，以提高推理效果和效率。

#### 4.4 基于模型的推理

#### 5.1 前向推理算法
前向推理（Forward Chaining）是一种从已知的事实出发，逐步推导出结论的推理方法。它通过匹配规则的前件，将已知的事实转化为新的结论。以下是前向推理的基本步骤和Python代码实现：

1. **基本步骤**：
   - 初始化事实库和规则库。
   - 遍历所有规则，检查规则的前件是否与事实库中的事实匹配。
   - 如果规则的前件与事实匹配，执行规则的结论部分，将结论添加到事实库中。
   - 重复上述步骤，直到无法找到新的结论。

2. **Python代码实现**：
   ```python
   class ForwardChaining:
       def __init__(self, rules):
           self.rules = rules
           self.facts = []

       def add_fact(self, fact):
           self.facts.append(fact)

       def forward_chaining(self):
           while True:
               new_facts = []
               for rule in self.rules:
                   if all(fact in self.facts for fact in rule['antecedents']):
                       new_fact = rule['consequent']
                       new_facts.append(new_fact)
                       self.facts.append(new_fact)
               if not new_facts:
                   break
               self.facts.extend(new_facts)
           return self.facts

   # 示例规则
   rules = [
       {'antecedents': ['温度高于30℃', '湿度低于40%'], 'consequent': '天气炎热'},
       {'antecedents': ['温度低于10℃', '湿度高于90%'], 'consequent': '天气潮湿'},
   ]

   # 初始化推理引擎
   fc = ForwardChaining(rules)

   # 添加事实
   fc.add_fact('温度高于30℃')
   fc.add_fact('湿度低于40%')

   # 执行前向推理
   conclusions = fc.forward_chaining()
   print(conclusions)
   ```

输出结果：
```
['天气炎热']
```

在这个示例中，我们添加了两个事实：“温度高于30℃”和“湿度低于40%”。通过前向推理，我们得出了结论：“天气炎热”。

#### 5.2 后向推理算法
后向推理（Backward Chaining）是一种从结论出发，逐步推导出已知事实的推理方法。它通过匹配规则的结论，将结论分解为已知的事实。以下是后向推理的基本步骤和Python代码实现：

1. **基本步骤**：
   - 初始化目标库和规则库。
   - 遍历所有规则，检查规则的结论是否与目标库中的目标匹配。
   - 如果规则的结论与目标匹配，执行规则的逆规则，将前提添加到目标库中。
   - 重复上述步骤，直到无法找到新的前提。

2. **Python代码实现**：
   ```python
   class BackwardChaining:
       def __init__(self, rules):
           self.rules = rules
           self.targets = []

       def add_target(self, target):
           self.targets.append(target)

       def backward_chaining(self):
           while True:
               new_targets = []
               for rule in self.rules:
                   if rule['consequent'] in self.targets:
                       new_targets.extend(rule['antecedents'])
                       self.targets.extend(rule['antecedents'])
               if not new_targets:
                   break
               self.targets.extend(new_targets)
           return self.targets

   # 示例规则
   rules = [
       {'consequent': '天气炎热', 'antecedents': ['温度高于30℃', '湿度低于40%']},
       {'consequent': '天气潮湿', 'antecedents': ['温度低于10℃', '湿度高于90%']},
   ]

   # 初始化推理引擎
   bc = BackwardChaining(rules)

   # 添加目标
   bc.add_target('天气炎热')

   # 执行后向推理
   premises = bc.backward_chaining()
   print(premises)
   ```

输出结果：
```
['温度高于30℃', '湿度低于40%']
```

在这个示例中，我们添加了一个目标：“天气炎热”。通过后向推理，我们找到了两个前提：“温度高于30℃”和“湿度低于40%”。

#### 5.3 寻找最短路径的推理算法
寻找最短路径的推理算法是一种用于计算实体之间距离或相似度的推理方法。它可以用于路径规划、推荐系统等领域。以下是Dijkstra算法的基本步骤和Python代码实现：

1. **基本步骤**：
   - 初始化图和距离数组。
   - 对于每个节点，设置初始距离为无穷大，除了起始节点，其距离为0。
   - 创建一个优先队列，用于选择距离最小的未访问节点。
   - 遍历优先队列，选择距离最小的节点，并将其标记为已访问。
   - 更新相邻节点的距离，如果发现更短的路径，则更新距离和前驱节点。
   - 重复步骤3和4，直到找到目标节点或所有节点都被访问。

2. **Python代码实现**：
   ```python
   import heapq

   class Graph:
       def __init__(self):
           self.vertices = {}
           self.edges = {}

       def add_vertex(self, vertex):
           if vertex not in self.vertices:
               self.vertices[vertex] = []

       def add_edge(self, vertex1, vertex2, weight):
           self.add_vertex(vertex1)
           self.add_vertex(vertex2)
           self.edges[(vertex1, vertex2)] = weight
           self.edges[(vertex2, vertex1)] = weight

       def dijkstra(self, start):
           distances = {vertex: float('infinity') for vertex in self.vertices}
           previous = {vertex: None for vertex in self.vertices}
           distances[start] = 0
           queue = [(distances[vertex], vertex) for vertex in self.vertices]
           heapq.heapify(queue)

           while queue:
               _, current = heapq.heappop(queue)
               for neighbor, weight in self.vertices[current]:
                   distance = distances[current] + weight
                   if distance < distances[neighbor]:
                       distances[neighbor] = distance
                       previous[neighbor] = current
                       heapq.heappush(queue, (distance, neighbor))

           return distances, previous

   # 示例图
   graph = Graph()
   graph.add_edge('A', 'B', 1)
   graph.add_edge('A', 'C', 4)
   graph.add_edge('B', 'C', 2)
   graph.add_edge('B', 'D', 5)
   graph.add_edge('C', 'D', 1)
   graph.add_edge('D', 'E', 8)
   graph.add_edge('C', 'E', 7)

   # 执行Dijkstra算法
   distances, previous = graph.dijkstra('A')
   print(distances)
   ```

输出结果：
```
{'A': 0, 'B': 1, 'C': 3, 'D': 4, 'E': 12}
```

在这个示例中，我们构建了一个图，并使用Dijkstra算法计算了从节点A到其他节点的最短路径距离。

class InferenceEngine:
    def __init__(self, rules, knowledge_graph):
        self.rules = rules
        self.knowledge_graph = knowledge_graph

    def forward_chaining(self):
        conclusions = []
        for rule in self.rules:
            antecedents = rule['antecedents']
            consequent = rule['consequent']
            if all(self.knowledge_graph.contains_entity(antecedent) for antecedent in antecedents):
                conclusions.append(consequent)
        return conclusions

# 示例规则
rules = [

    {'antecedents': ['发热', '乏力'], 'consequent': '流感'},
]

# 初始化推理引擎
inference_engine = InferenceEngine(rules, knowledge_graph)

# 执行推理
conclusions = inference_engine.forward_chaining()
print(conclusions)

# 导入必要的库
import networkx as nx
from nltk.corpus import stopwords
from sklearn.feature_extraction.text import TfidfVectorizer
from sklearn.naive_bayes import MultinomialNB
from sklearn.pipeline import make_pipeline

# 知识图谱构建
class KnowledgeGraph:
    def __init__(self):
        self.graph = nx.Graph()

    def add_entity(self, entity):
        self.graph.add_node(entity)

    def add_relation(self, entity1, relation, entity2):
        self.graph.add_edge(entity1, entity2, relation=relation)

    def contains_entity(self, entity):
        return entity in self.graph.nodes

    def get_relations(self, entity):
        return [edge[2]['relation'] for edge in self.graph.out_edges(entity, data=True)]

# 实例化知识图谱
kg = KnowledgeGraph()
kg.add_entity('订单')
kg.add_entity('查询')
kg.add_entity('用户')
kg.add_relation('用户', '请求', '查询')
kg.add_relation('查询', '针对', '订单')

# 意图识别模型
class IntentClassifier:
    def __init__(self):
        self.model = make_pipeline(TfidfVectorizer(stop_words=stopwords.words('english')), MultinomialNB())

    def train(self, X, y):
        self.model.fit(X, y)

    def predict(self, X):
        return self.model.predict(X)

    def evaluate(self, X, y):
        predictions = self.predict(X)
        accuracy = (predictions == y).mean()
        return accuracy

# 数据准备
X = ['查询订单', '我要查询订单', '订单查询']
y = ['查询']

# 训练模型
intent_classifier = IntentClassifier()
intent_classifier.train(X, y)

# 评估模型
accuracy = intent_classifier.evaluate(X, y)
print(f'Accuracy: {accuracy:.2f}')

# AI Agent逻辑实现
class AIAssistant:
    def __init__(self, kg, intent_classifier):
        self.kg = kg
        self.intent_classifier = intent_classifier

    def handle_query(self, text):
        intent = self.intent_classifier.predict([text])[0]
        if intent == '查询':
            return '您想查询什么订单？'
        else:
            return '对不起，我不理解您的意思。'

# 实例化AI Agent
ai_assistant = AIAssistant(kg, intent_classifier)

# 测试AI Agent
