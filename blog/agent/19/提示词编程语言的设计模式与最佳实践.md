**1.1 问题背景**

编程语言作为计算机科学的基石，其设计和应用直接影响到软件开发的效率和性能。随着软件复杂性的增加，编程语言的设计模式逐渐成为提高软件开发质量、降低维护成本的关键因素。

**1.1.1 编程语言设计的挑战**

现代编程语言需要满足多方面的需求：

- **易用性**：提高编程效率和代码可读性。
- **性能**：优化执行速度，减少内存消耗。
- **扩展性**：支持模块化和复用。
- **安全性**：防止常见漏洞和攻击。

**1.1.2 提示词编程语言的兴起**

提示词编程语言（Prompt-Based Programming Language）是一种新兴的编程范式，其核心思想是通过预设的提示词（Prompt）来引导程序逻辑的执行。

- **优势**：
  - **简化和标准化**：通过提示词，可以简化编程流程，降低学习成本。
  - **灵活性和扩展性**：提示词允许用户自定义逻辑，提高语言的适应性。
  - **易于调试**：提示词的明确性有助于代码的调试和维护。

**1.1.3 设计模式在编程语言中的应用**

设计模式是一系列解决问题的通用解决方案，在编程语言设计中具有重要应用。以下是一些常见的设计模式及其作用：

- **单例模式**：确保一个类只有一个实例，并提供一个全局访问点。
- **工厂模式**：定义一个创建对象的接口，但将具体的对象创建委托给子类。
- **代理模式**：为其他对象提供代理，以控制对这个对象的访问。
- **装饰者模式**：动态地给一个对象添加一些额外的职责。
- **观察者模式**：当一个对象的状态发生变化时，自动通知其他对象。
- **策略模式**：定义一系列算法，将每一个算法封装起来，并使它们可以相互替换。
- **适配器模式**：使两个无法兼容的接口之间相互合作。
- **模板方法模式**：定义一个操作中的算法的骨架，将一些步骤延迟到子类中。

### 第二部分：设计模式详解

**2.1 单例模式**

**2.1.1 模式原理**

单例模式（Singleton Pattern）是一种创建型设计模式，它确保一个类只有一个实例，并提供一个全局访问点。这种模式主要用于控制实例的数量，减少系统资源的消耗，并提供一个全局访问点以便代码的统一管理。

**2.1.1.1 单例模式的概念**

单例模式的核心在于“一个类只能有一个实例”，并且这个实例可以通过一个全局访问点进行获取。

- **优点**：
  - 简化全局访问，减少资源消耗。
  - 保证实例的唯一性，避免重复创建和销毁带来的性能问题。
  - 提高代码的可维护性和可测试性。

- **缺点**：
  - 可能引入全局状态，影响测试和维护。
  - 破坏封装性，可能导致代码复杂性增加。

**2.1.1.2 单例模式的作用**

单例模式通常用于以下场景：

- **资源管理**：如数据库连接、线程池等，需要确保全局唯一实例。
- **控制访问**：如日志记录器、配置管理器等，需要全局控制访问权限。
- **单例服务**：如某些框架或库提供的核心服务，需要保证唯一实例。

**2.1.2 实现方法**

单例模式的实现方法有多种，以下是一些常见的方法：

- **饿汉式**：在类加载时初始化单例，确保单例的唯一性。

  ```python
  class Singleton:
      instance = None
  
      def __new__(cls):
          if cls.instance is None:
              cls.instance = super(Singleton, cls).__new__(cls)
          return cls.instance
  ```

- **懒汉式**：在需要时创建单例，延迟初始化，减少资源消耗。

  ```python
  class Singleton:
      instance = None
  
      def __new__(cls):
          if cls.instance is None:
              cls.instance = super(Singleton, cls).__new__(cls)
          return cls.instance
  
      def __init__(self):
          if not hasattr(self, 'initialized'):
              self.initialized = True
  ```

- **双重校验锁**：在多线程环境下，确保单例的唯一性。

  ```python
  import threading
  
  class Singleton:
      instance = None
      _lock = threading.Lock()
  
      def __new__(cls):
          if cls.instance is None:
              with cls._lock:
                  if cls.instance is None:
                      cls.instance = super(Singleton, cls).__new__(cls)
          return cls.instance
  ```

**2.1.3 应用实例**

以下是一个简单的应用实例，使用单例模式实现一个日志记录器。

```python
class Logger:
    instance = None
    
    def __new__(cls):
        if cls.instance is None:
            cls.instance = super(Logger, cls).__new__(cls)
        return cls.instance
    
    def log(self, message):
        print(message)

# 单例模式的使用
logger = Logger()
logger.log("This is a log message.")
```

**2.2 工厂模式**

**2.2.1 模式原理**

工厂模式（Factory Pattern）是一种创建型设计模式，用于定义一个创建对象的接口，但将具体的对象创建委托给子类。这种模式有助于降低系统的复杂度，提高代码的可扩展性和复用性。

**2.2.1.1 工厂模式的概念**

工厂模式的核心在于“通过一个工厂类，根据不同的条件创建具体的对象”。

- **优点**：
  - 解耦创建逻辑和具体实现，提高系统的可扩展性。
  - 避免直接使用类名创建对象，简化代码。
  - 提高代码的可维护性和可测试性。

- **缺点**：
  - 可能导致复杂性和性能下降。
  - 难以支持多个工厂类。

**2.2.1.2 工厂模式的作用**

工厂模式通常用于以下场景：

- **对象的创建**：如数据库连接、线程池等，需要根据不同条件创建对象。
- **接口抽象**：如不同类型的商品，需要根据订单信息创建具体的商品对象。
- **框架和库**：如Spring框架中的BeanFactory，用于管理对象的创建。

**2.2.2 实现方法**

工厂模式有多种实现方法，以下是一些常见的方法：

- **简单工厂模式**：通过一个工厂类，根据输入的参数创建具体的对象。

  ```python
  class Factory:
      def create_object(self, type):
          if type == "A":
              return ClassA()
          elif type == "B":
              return ClassB()
  
  # 使用简单工厂模式
  factory = Factory()
  objectA = factory.create_object("A")
  objectB = factory.create_object("B")
  ```

- **工厂方法模式**：每个子类都有自己的工厂方法，根据子类创建具体的对象。

  ```python
  class FactoryA:
      def create_object(self):
          return ClassA()
  
  class FactoryB:
      def create_object(self):
          return ClassB()
  
  # 使用工厂方法模式
  factoryA = FactoryA()
  objectA = factoryA.create_object()
  
  factoryB = FactoryB()
  objectB = factoryB.create_object()
  ```

- **抽象工厂模式**：定义一个抽象工厂类，由多个工厂方法组成，每个工厂方法创建不同类型的对象。

  ```python
  class AbstractFactory:
      def create_productA(self):
          pass
  
      def create_productB(self):
          pass
  
  class ConcreteFactoryA(AbstractFactory):
      def create_productA(self):
          return ProductA()
  
      def create_productB(self):
          return ProductB()
  
  class ConcreteFactoryB(AbstractFactory):
      def create_productA(self):
          return ProductA()
  
      def create_productB(self):
          return ProductB()
  
  # 使用抽象工厂模式
  factoryA = ConcreteFactoryA()
  productA = factoryA.create_productA()
  productB = factoryA.create_productB()
  
  factoryB = ConcreteFactoryB()
  productA = factoryB.create_productA()
  productB = factoryB.create_productB()
  ```

**2.2.3 应用实例**

以下是一个简单的应用实例，使用工厂模式创建不同类型的商品。

```python
class ProductA:
    def display(self):
        print("Product A")

class ProductB:
    def display(self):
        print("Product B")

class Factory:
    def create_product(self, type):
        if type == "A":
            return ProductA()
        elif type == "B":
            return ProductB()

# 使用工厂模式创建商品
factory = Factory()
productA = factory.create_product("A")
productB = factory.create_product("B")

productA.display()
productB.display()
```

**2.3 代理模式**

**2.3.1 模式原理**

代理模式（Proxy Pattern）是一种结构型设计模式，用于为其他对象提供代理，以控制对这个对象的访问。这种模式有助于提高系统的灵活性和扩展性。

**2.3.1.1 代理模式的概念**

代理模式的核心在于“通过代理对象来控制对目标对象的访问”。

- **优点**：
  - 提高系统的灵活性和扩展性，减少直接访问目标对象的复杂性。
  - 保护目标对象，防止恶意访问或滥用。
  - 动态添加额外的职责，如日志记录、安全检查等。

- **缺点**：
  - 可能引入额外的间接性，降低性能。
  - 需要合理设计代理对象，否则可能导致代码复杂度增加。

**2.3.1.2 代理模式的作用**

代理模式通常用于以下场景：

- **安全控制**：如访问控制、权限检查等。
- **远程访问**：如远程方法调用、Web服务代理等。
- **日志记录**：如操作日志记录、性能监控等。
- **负载均衡**：如分布式系统中的负载均衡代理。

**2.3.2 实现方法**

代理模式有两种主要的实现方法：

- **静态代理**：代理类和目标类实现相同的接口，代理类对目标类的所有方法进行包装。

  ```python
  class Proxy:
      def __init__(self, target):
          self._target = target
  
      def method(self):
          print("Before method execution.")
          self._target.method()
          print("After method execution.")
  
  class Target:
      def method(self):
          print("Target method executed.")
  
  # 使用静态代理
  target = Target()
  proxy = Proxy(target)
  proxy.method()
  ```

- **动态代理**：通过反射机制动态创建代理对象，代理类实现对目标对象的代理。

  ```python
  import prox
  from types import MethodType
  
  class DynamicProxy:
      def __init__(self, target):
          self._target = target
  
      def __getattribute__(self, name):
          if name.startswith("__"):
              return super().__getattribute__(name)
          else:
              def wrapped_method(*args, **kwargs):
                  print("Before method execution.")
                  result = self._target.__getattribute__(name)(*args, **kwargs)
                  print("After method execution.")
                  return result
              return MethodType(wrapped_method, self)
  
  class Target:
      def method(self):
          print("Target method executed.")
  
  # 使用动态代理
  target = Target()
  proxy = DynamicProxy(target)
  proxy.method()
  ```

**2.3.3 应用实例**

以下是一个简单的应用实例，使用代理模式实现日志记录功能。

```python
class Logger:
    def log(self, message):
        print(f"Logging: {message}")

class Target:
    def method(self):
        print("Target method executed.")

class Proxy:
    def __init__(self, target, logger):
        self._target = target
        self._logger = logger
  
    def method(self):
        self._logger.log("Before method execution.")
        self._target.method()
        self._logger.log("After method execution.")

# 使用代理模式实现日志记录
logger = Logger()
target = Target()
proxy = Proxy(target, logger)
proxy.method()
```

**2.4 装饰者模式**

**2.4.1 模式原理**

装饰者模式（Decorator Pattern）是一种结构型设计模式，用于动态地给一个对象添加一些额外的职责。这种模式有助于扩展对象的功能，而不需要修改原始对象。

**2.4.1.1 装饰者模式的概念**

装饰者模式的核心在于“通过装饰者对象来给原始对象添加额外的功能”。

- **优点**：
  - 提高代码的复用性和可维护性，避免重复代码。
  - 动态添加和删除功能，提高系统的灵活性。
  - 保持原始对象的接口不变，易于扩展。

- **缺点**：
  - 可能导致代码复杂度增加。
  - 需要合理设计装饰者之间的关系，避免功能冲突。

**2.4.1.2 装饰者模式的作用**

装饰者模式通常用于以下场景：

- **功能扩展**：如日志记录、权限验证等，动态地添加功能。
- **资源管理**：如连接池、缓存等，动态地管理资源。
- **性能优化**：如缓存装饰者、异步处理等，提高性能。

**2.4.2 实现方法**

装饰者模式主要有以下两种实现方法：

- **装饰者链**：多个装饰者对象按顺序组合，每个装饰者对象负责调用下一个装饰者对象的方法。

  ```python
  class Decorator:
      def __init__(self, component):
          self._component = component
  
      def operation(self):
          self._component.operation()
  
  class ConcreteDecoratorA(Decorator):
      def operation(self):
          print("Additional functionality A")
          self._component.operation()
  
  class ConcreteDecoratorB(Decorator):
      def operation(self):
          print("Additional functionality B")
          self._component.operation()
  
  class Component:
      def operation(self):
          print("Basic functionality")
  
  # 使用装饰者链
  component = Component()
  decoratorA = ConcreteDecoratorA(component)
  decoratorB = ConcreteDecoratorB(decoratorA)
  decoratorB.operation()
  ```

- **装饰者组合**：使用组合模式，将装饰者对象组合成复合对象，实现动态添加功能。

  ```python
  class Decorator(ComposeComponent):
      def __init__(self, component):
          super().__init__(component)
  
      def operation(self):
          self._component.operation()
          self._add_extra_functionality()
  
      def _add_extra_functionality(self):
          print("Additional functionality")
  
  class Component:
      def operation(self):
          print("Basic functionality")
  
  # 使用装饰者组合
  component = Component()
  decorator = Decorator(component)
  decorator.operation()
  ```

**2.4.3 应用实例**

以下是一个简单的应用实例，使用装饰者模式实现日志记录功能。

```python
class Logger:
    def log(self, message):
        print(f"Logging: {message}")

class Component:
    def operation(self):
        print("Basic functionality")

class Decorator(Component):
    def __init__(self, component, logger):
        super().__init__(component)
        self._logger = logger
  
    def operation(self):
        self._logger.log("Before operation")
        super().operation()
        self._logger.log("After operation")

# 使用装饰者模式实现日志记录
logger = Logger()
component = Component()
decorator = Decorator(component, logger)
decorator.operation()
```

**2.5 观察者模式**

**2.5.1 模式原理**

观察者模式（Observer Pattern）是一种行为型设计模式，用于定义对象间的一对多依赖关系。当一个对象的状态发生变化时，自动通知其他对象，从而实现模块间的解耦。

**2.5.1.1 观察者模式的概念**

观察者模式的核心在于“一对多的依赖关系”，其中一个对象（被观察者）的状态变化会通知所有的观察者对象。

- **优点**：
  - 提高系统的可扩展性和灵活性，便于模块间的解耦。
  - 易于实现模块间的通信，降低系统的复杂性。
  - 支持广播通信，提高系统的响应速度。

- **缺点**：
  - 可能引入过多的观察者对象，影响性能。
  - 需要合理设计观察者之间的依赖关系，避免循环引用。

**2.5.1.2 观察者模式的作用**

观察者模式通常用于以下场景：

- **事件处理**：如用户操作、系统事件等，实现实时响应。
- **状态管理**：如购物车、库存管理等，实现状态变化通知。
- **异步通信**：如消息队列、Web服务调用等，实现异步处理。

**2.5.2 实现方法**

观察者模式主要有以下两种实现方法：

- **基于事件**：使用事件驱动模型，实现观察者之间的通信。

  ```python
  class EventManager:
      def __init__(self):
          self._observers = []
  
      def register(self, observer):
          self._observers.append(observer)
  
      def notify(self, event):
          for observer in self._observers:
              observer.update(event)
  
  class Observer:
      def update(self, event):
          print(f"Observer {id(self)} received event: {event}")
  
  # 使用基于事件的方法
  event_manager = EventManager()
  observer1 = Observer()
  observer2 = Observer()
  event_manager.register(observer1)
  event_manager.register(observer2)
  event_manager.notify("Event 1")
  ```

- **基于回调**：使用回调函数，实现观察者之间的通信。

  ```python
  class Subject:
      def __init__(self):
          self._observers = []
  
      def register(self, observer, callback):
          self._observers.append((observer, callback))
  
      def notify(self, event):
          for observer, callback in self._observers:
              callback(event)
  
  class Observer:
      def __call__(self, event):
          print(f"Observer {id(self)} received event: {event}")
  
  # 使用基于回调的方法
  subject = Subject()
  observer1 = Observer()
  observer2 = Observer()
  subject.register(observer1, observer1)
  subject.register(observer2, observer2)
  subject.notify("Event 1")
  ```

**2.5.3 应用实例**

以下是一个简单的应用实例，使用观察者模式实现系统事件监听。

```python
class SystemEvent:
    def __init__(self, event_type, event_data):
        self._event_type = event_type
        self._event_data = event_data

    def get_event_type(self):
        return self._event_type

    def get_event_data(self):
        return self._event_data

class EventManager:
    def __init__(self):
        self._observers = []

    def register(self, observer):
        self._observers.append(observer)

    def notify(self, event):
        for observer in self._observers:
            observer.update(event)

class Observer:
    def update(self, event):
        print(f"Observer {id(self)} received event of type {event.get_event_type()} with data {event.get_event_data()}")

# 使用观察者模式实现系统事件监听
event_manager = EventManager()
observer1 = Observer()
observer2 = Observer()
event_manager.register(observer1)
event_manager.register(observer2)
event = SystemEvent("Login", "User logged in")
event_manager.notify(event)
```

**2.6 策略模式**

**2.6.1 模式原理**

策略模式（Strategy Pattern）是一种行为型设计模式，用于定义一系列算法，将每一个算法封装起来，并使它们可以相互替换。这种模式有助于提高代码的复用性和可维护性。

**2.6.1.1 策略模式的概念**

策略模式的核心在于“将算法封装，使算法的变化不会影响到使用算法的客户端”。

- **优点**：
  - 提高代码的复用性和可维护性，便于算法的扩展和替换。
  - 解耦算法和客户端，提高系统的灵活性和可扩展性。
  - 易于实现算法的动态切换。

- **缺点**：
  - 可能引入过多的策略类，导致代码复杂度增加。
  - 需要合理设计策略之间的依赖关系，避免冲突。

**2.6.1.2 策略模式的作用**

策略模式通常用于以下场景：

- **算法策略**：如排序算法、查找算法等，便于算法的扩展和替换。
- **行为策略**：如支付策略、优惠策略等，便于策略的动态切换。
- **业务规则**：如业务流程中的决策点，便于业务规则的动态调整。

**2.6.2 实现方法**

策略模式主要有以下两种实现方法：

- **基于接口**：定义一个策略接口，每个策略类实现接口的方法。

  ```python
  class StrategyInterface:
      def execute(self, data):
          pass
  
  class ConcreteStrategyA(StrategyInterface):
      def execute(self, data):
          print(f"Executing strategy A with data {data}")
  
  class ConcreteStrategyB(StrategyInterface):
      def execute(self, data):
          print(f"Executing strategy B with data {data}")
  
  class Context:
      def __init__(self, strategy):
          self._strategy = strategy
  
      def set_strategy(self, strategy):
          self._strategy = strategy
  
      def execute_strategy(self, data):
          self._strategy.execute(data)
  
  # 使用基于接口的方法
  context = Context(ConcreteStrategyA())
  context.execute_strategy("Data 1")
  context.set_strategy(ConcreteStrategyB())
  context.execute_strategy("Data 2")
  ```

- **基于组合**：使用组合模式，将策略类组合到客户端中。

  ```python
  class Context:
      def __init__(self, strategy=None):
          self._strategy = strategy
  
      def set_strategy(self, strategy):
          self._strategy = strategy
  
      def execute_strategy(self, data):
          if self._strategy:
              self._strategy.execute(data)
  
  class ConcreteStrategyA:
      def execute(self, data):
          print(f"Executing strategy A with data {data}")
  
  class ConcreteStrategyB:
      def execute(self, data):
          print(f"Executing strategy B with data {data}")
  
  # 使用基于组合的方法
  context = Context()
  context._strategy = ConcreteStrategyA()
  context.execute_strategy("Data 1")
  context._strategy = ConcreteStrategyB()
  context.execute_strategy("Data 2")
  ```

**2.6.3 应用实例**

以下是一个简单的应用实例，使用策略模式实现排序算法。

```python
class StrategyInterface:
    def sort(self, data):
        pass

class ConcreteStrategyA(StrategyInterface):
    def sort(self, data):
        data.sort()

class ConcreteStrategyB(StrategyInterface):
    def sort(self, data):
        data.sort(reverse=True)

class Context:
    def __init__(self, strategy):
        self._strategy = strategy

    def set_strategy(self, strategy):
        self._strategy = strategy

    def execute_strategy(self, data):
        self._strategy.sort(data)

# 使用策略模式实现排序算法
context = Context(ConcreteStrategyA())
data = [3, 1, 4, 1, 5, 9, 2, 6, 5, 3, 5]
context.execute_strategy(data)
print("Sorted data:", data)

context.set_strategy(ConcreteStrategyB())
context.execute_strategy(data)
print("Reverse sorted data:", data)
```

**2.7 适配器模式**

**2.7.1 模式原理**

适配器模式（Adapter Pattern）是一种结构型设计模式，用于将一个类的接口转换成客户希望的另一个接口。这种模式使得原本由于接口不兼容而无法在一起工作的类可以协同工作。

**2.7.1.1 适配器模式的概念**

适配器模式的核心在于“通过适配器，将不兼容的接口转换为兼容的接口”。

- **优点**：
  - 提高类的复用性和灵活性，解决接口不兼容的问题。
  - 保护原有类的内部结构，无需修改原有类的代码。
  - 增强系统的扩展性和灵活性。

- **缺点**：
  - 可能引入额外的间接性，降低性能。
  - 需要合理设计适配器，否则可能导致代码复杂度增加。

**2.7.1.2 适配器模式的作用**

适配器模式通常用于以下场景：

- **类适配器**：用于将一个类的接口转换为另一个接口，通常用于旧类的封装。
- **对象适配器**：用于将一个对象转换为另一个接口，通常用于组件间的接口适配。

**2.7.2 实现方法**

适配器模式主要有以下两种实现方法：

- **类适配器**：通过继承原有类，并实现新的接口。

  ```python
  class Adapter(AbstracTarget):
      def __init__(self, adaptee):
          self._adaptee = adaptee
  
      def operation1(self):
          self._adaptee.operation1()
  
      def operation2(self):
          self._adaptee.operation2()
  
  class Adaptee:
      def operation1(self):
          print("Operation 1")
  
      def operation2(self):
          print("Operation 2")
  
  class Target:
      def operation1(self):
          print("Operation 1")
  
      def operation2(self):
          print("Operation 2")
  
  # 使用类适配器
  adaptee = Adaptee()
  adapter = Adapter(adaptee)
  target = Target()
  
  adapter.operation1()
  adapter.operation2()
  ```

- **对象适配器**：通过组合原有对象，并实现新的接口。

  ```python
  class Adapter(Target):
      def __init__(self, adaptee):
          self._adaptee = adaptee
  
      def operation1(self):
          self._adaptee.operation1()
  
      def operation2(self):
          self._adaptee.operation2()
  
  class Adaptee:
      def operation1(self):
          print("Operation 1")
  
      def operation2(self):
          print("Operation 2")
  
  class Target:
      def operation1(self):
          print("Operation 1")
  
      def operation2(self):
          print("Operation 2")
  
  # 使用对象适配器
  adaptee = Adaptee()
  adapter = Adapter(adaptee)
  target = Target()
  
  adapter.operation1()
  adapter.operation2()
  ```

**2.7.3 应用实例**

以下是一个简单的应用实例，使用适配器模式将一个旧类转换为新的接口。

```python

    def operation1(self):
```

**2.8 模板方法模式**

**2.8.1 模式原理**

模板方法模式（Template Method Pattern）是一种行为型设计模式，定义一个操作中的算法的骨架，将一些步骤延迟到子类中。这种模式有助于提高代码的复用性和可维护性。

**2.8.1.1 模板方法模式的概念**

模板方法模式的核心在于“定义一个算法的骨架，将部分步骤延迟到子类中”。

- **优点**：
  - 提高代码的复用性和可维护性，将通用的步骤提取到父类中。
  - 提供一个扩展点，便于子类进行定制化实现。
  - 避免子类重复编写通用的步骤，降低代码复杂度。

- **缺点**：
  - 可能导致子类继承关系复杂，影响代码的可读性。
  - 需要合理设计模板方法，避免过度抽象。

**2.8.1.2 模板方法模式的作用**

模板方法模式通常用于以下场景：

- **通用流程**：如业务流程、系统框架等，将通用的步骤提取到父类中。
- **多态实现**：如界面渲染、事件处理等，提供扩展点给子类实现。
- **策略组合**：如组合多个策略，定义一个统一的执行流程。

**2.8.2 实现方法**

模板方法模式主要有以下两种实现方法：

- **基于继承**：使用继承关系，将通用的步骤定义在父类中，将特殊的步骤定义在子类中。

  ```python
  class TemplateMethod:
      def template_method(self):
          self.step1()
          self.step2()
          self.step3()
  
      def step1(self):
          print("Step 1")
  
      def step2(self):
          print("Step 2")
  
      def step3(self):
          print("Step 3")
  
  class ConcreteTemplateA(TemplateMethod):
      def step2(self):
          print("Customized Step 2 for ConcreteTemplateA")
  
  class ConcreteTemplateB(TemplateMethod):
      def step3(self):
          print("Customized Step 3 for ConcreteTemplateB")
  
  # 使用基于继承的方法
  template_method = TemplateMethod()
  template_method.template_method()
  
  concrete_template_a = ConcreteTemplateA()
  concrete_template_a.template_method()
  
  concrete_template_b = ConcreteTemplateB()
  concrete_template_b.template_method()
  ```

- **基于组合**：使用组合关系，将通用的步骤定义在父类中，将特殊的步骤定义在子类中。

  ```python
  class TemplateMethod:
      def __init__(self, concrete_class):
          self._concrete_class = concrete_class
  
      def template_method(self):
          self._concrete_class.step1()
          self._concrete_class.step2()
          self._concrete_class.step3()
  
  class ConcreteClassA:
      def step1(self):
          print("Step 1 for ConcreteClassA")
  
      def step2(self):
          print("Step 2 for ConcreteClassA")
  
      def step3(self):
          print("Step 3 for ConcreteClassA")
  
  class ConcreteClassB:
      def step1(self):
          print("Step 1 for ConcreteClassB")
  
      def step2(self):
          print("Step 2 for ConcreteClassB")
  
      def step3(self):
          print("Step 3 for ConcreteClassB")
  
  # 使用基于组合的方法
  template_method = TemplateMethod(ConcreteClassA())
  template_method.template_method()
  
  template_method = TemplateMethod(ConcreteClassB())
  template_method.template_method()
  ```
